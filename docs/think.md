# 2. 설치 및 가상화 기초

### 설치 및 가상화 기초

- ISO 이미지 개념과 사용법
- VirtualBox, VMware ESXi 개요 및 설치 실습
- 가상머신 네트워크 설정 (NAT, Bridged, Host-only)
- 원격 접속 도구: PuTTY 사용법 (SSH 기본)

---

### 1. ISO 이미지와 가상 머신 (상세)

리눅스를 설치하고 실습하기 위해 우리는 가상의 컴퓨터, 즉 가상 머신(Virtual Machine, VM)을 사용할 것입니다. 가상 머신을 만들기 위해서는 운영체제의 설치 파일인 ISO 이미지가 필요합니다.

**ISO 이미지란?**

- CD나 DVD 같은 광학 디스크의 모든 내용을 하나의 파일로 압축한 것입니다. 운영체제 설치 CD를 파일 형태로 만들었다고 생각하면 쉽습니다.
- Ubuntu, Rocky Linux 등 대부분의 리눅스 배포판은 공식 웹사이트에서 ISO 파일을 무료로 제공합니다.

**가상화 소프트웨어**

- VirtualBox: Oracle에서 제공하는 무료 가상화 소프트웨어로, 개인용 PC에서 다양한 OS를 테스트하기에 가장 적합하고 널리 쓰입니다.
- VMware Workstation / ESXi: VMware사의 제품으로, VirtualBox보다 더 강력한 기능과 성능을 제공합니다. 특히 ESXi는 서버에 직접 설치하여 여러 가상 머신을 운영하는 데 특화된 '하이퍼바이저'입니다.

---

### 2. 가상 머신 네트워크 설정 (상세)

가상 머신이 외부와 어떻게 통신할지 결정하는 중요한 설정입니다. 주로 사용하는 세 가지 방식이 있습니다.

- **NAT (Network Address Translation)**
- 가상 머신이 인터넷(외부)으로 나가는 것은 가능하지만, 외부에서 가상 머신으로 직접 들어오는 것은 막혀있는 가장 기본적인 방식입니다. (가장 안전하고 간편)
- **Bridged (브릿지)**
- 가상 머신이 실제 PC처럼 공유기로부터 IP 주소를 할당받아, 네트워크상에서 하나의 독립된 컴퓨터처럼 동작합니다. 외부에서 가상 머신으로 직접 접속해야 할 때 사용합니다.
- **Host-only (호스트 전용)**
- 외부 인터넷과는 단절되고, 오직 내 PC(호스트)와 가상 머신 사이에서만 통신이 가능한 폐쇄적인 방식입니다. 보안 테스트 등 고립된 환경이 필요할 때 사용합니다.

## 리눅스 설치와 가상화의 기초

리눅스(Linux)를 사용하는 방법은 크게 두 가지입니다. 물리적인 컴퓨터에 직접 설치하거나, 가상화 기술을 이용해 기존 운영 체제(예: Windows) 위에서 별개의 프로그램처럼 실행하는 방법입니다.

### 1. 리눅스 직접 설치 방법

- 리눅스 배포판(예: Ubuntu) ISO 이미지 파일을 다운로드합니다.
- Rufus 같은 도구를 사용하여 부팅 가능한 USB 드라이브를 제작합니다.
- 컴퓨터 BIOS/UEFI 설정에서 부팅 순서를 USB로 변경합니다.
- 화면 안내에 따라 설치를 진행합니다.

### 2. 가상화(Virtualization) 기초

가상화는 물리적인 컴퓨터 하나를 여러 개의 가상 컴퓨터(Virtual Machine, VM)로 나누어 쓸 수 있게 해주는 기술입니다. 이를 통해 하나의 PC에서 Windows와 Linux 등 여러 운영 체제를 동시에 실행할 수 있습니다.

- 장점: 자원 효율성 증대, 비용 절감, 개발 및 테스트에 용이한 격리 환경 제공.
- 하이퍼바이저(Hypervisor): 가상화를 구현하는 소프트웨어입니다. VirtualBox, VMware 등이 대표적이며, 기존 OS에 프로그램을 설치하듯 간단히 사용할 수 있습니다.

### 3. 대표적인 가상화 소프트웨어

- VirtualBox: Oracle에서 제공하는 무료 오픈소스 소프트웨어로, 초보자가 사용하기 편리합니다.
- VMware Workstation Player: 개인 사용자를 위한 무료 버전으로, 강력한 성능을 제공합니다.
- KVM (Kernel-based Virtual Machine): 리눅스 커널에 내장된 고성능 가상화 기술입니다.

## 심화 학습: 리눅스 배포판과 설치

### 1. 주요 리눅스 배포판 비교

리눅스는 커널을 기반으로 다양한 소프트웨어를 묶어 '배포판' 형태로 제공됩니다. 배포판은 크게 데비안(Debian) 계열과 레드햇(Red Hat) 계열로 나눌 수 있습니다.

- 데비안(Debian) 계열
    
    특징: 안정성과 방대한 소프트웨어 패키지(APT)가 장점입니다.
    
    - Ubuntu: 가장 인기 있는 배포판. 사용자 친화적인 환경으로 초보자에게 적극 추천됩니다.
    - Linux Mint: Windows와 유사한 인터페이스를 제공하여 Windows 사용자가 쉽게 적응할 수 있습니다.
- 레드햇(Red Hat) 계열
    
    특징: 기업 환경에서의 안정성과 유료 기술 지원에 중점을 둡니다. (패키지: YUM, DNF, RPM)
    
    - RHEL (Red Hat Enterprise Linux): 유료 기업용 배포판으로, 현업에서 가장 널리 사용됩니다.
    - Fedora: 최신 기술을 가장 먼저 도입하는 배포판으로, 개발자들에게 인기가 많습니다.
    - Rocky Linux / AlmaLinux: RHEL과 100% 호환되는 무료 서버용 배포판입니다.

### 2. 리눅스 디스크 파티셔닝(Partitioning) 개념

하나의 물리적 디스크를 여러 개의 논리적인 구역(파티션)으로 나누는 작업입니다. 파티셔닝을 통해 시스템의 안정성과 데이터 관리 효율성을 높일 수 있습니다.

- 주요 이유: OS 영역과 데이터 영역을 분리하여 안정성을 높이고, 용도별로 공간을 효율적으로 관리하기 위함입니다.
- 파티션의 종류 (클릭하여 펼치기)
    - 주(Primary) 파티션: 부팅이 가능한 파티션. 디스크당 최대 4개까지 만들 수 있습니다.
    - 확장(Extended) 파티션: 4개 이상의 파티션이 필요할 때 생성하며, 내부에 논리 파티션을 만듭니다. 디스크당 1개만 가능합니다.
    - 논리(Logical) 파티션: 확장 파티션 안에 생성하는 파티션입니다.

리눅스에서 디스크를 사용하려면 파티셔닝 → 파일 시스템 생성(포맷) → 마운트(디렉터리에 연결)의 3단계를 거칩니다.

### 3. 가상화(Virtualization)와 컨테이너(Container) 기술 비교

두 기술 모두 애플리케이션을 격리된 환경에서 실행하지만, 가상화하는 대상과 방식에 근본적인 차이가 있습니다. 가상화는 하드웨어를, 컨테이너는 운영체제(OS)를 가상화합니다.

- 가상화 (Virtual Machine) - 독립적인 컴퓨터 만들기
    - 핵심: 하드웨어 수준 가상화. 하이퍼바이저(Hypervisor)를 통해 물리적 서버 위에 여러 개의 가상 머신(VM)을 생성합니다.
    - 구성: 각 VM은 독립적인 운영체제(Guest OS)를 가집니다.
    - 장점: 완전한 격리로 보안성이 높고, 서로 다른 OS를 운영할 수 있습니다.
    - 단점: OS를 포함하여 용량이 크고(GB 단위), 부팅 속도가 느립니다.
- 컨테이너 (Container) - OS 안의 격리된 방 만들기
    - 핵심: 운영체제 수준 가상화. 호스트 OS의 커널을 모든 컨테이너가 공유합니다.
    - 구성: 애플리케이션과 그 실행에 필요한 파일들만 패키지로 포함합니다.
    - 장점: OS가 없어 매우 가볍고(MB 단위), 수 초 내에 시작되어 빠릅니다. 높은 이식성을 가집니다.
    - 단점: 커널을 공유하므로 가상화에 비해 격리 수준이 낮습니다.

### 심화: LVM(Logical Volume Manager)의 이해

LVM은 여러 개의 하드 디스크를 합쳐서 하나의 큰 저장 공간처럼 사용하거나, 디스크 공간을 동적으로 늘리고 줄일 수 있게 만드는 매우 유연한 디스크 관리 방식입니다.

### LVM의 핵심 구성 요소 (PV, VG, LV)

- PV (Physical Volume / 물리 볼륨): 실제 하드 디스크 또는 파티션 그 자체입니다. LVM으로 사용하기 위한 준비 단계입니다.
- VG (Volume Group / 볼륨 그룹): 하나 이상의 물리 볼륨(PV)들이 모여 만들어진 하나의 큰 저장 공간(저장소)입니다.
- LV (Logical Volume / 논리 볼륨): 볼륨 그룹(VG)이라는 큰 저장소에서 사용자가 필요한 만큼 할당받아 사용하는 논리적인 파티션입니다. 우리가 최종적으로 사용하는 공간입니다.

> 간단한 비유: PV는 '찰흙 덩어리', VG는 '모든 찰흙을 뭉친 큰 덩어리', LV는 '큰 덩어리에서 떼어내 만든 그릇'
> 

이러한 구조 덕분에 LVM은 데이터 손실 없이 동적으로 파티션(LV)의 크기를 조절할 수 있는 강력한 장점을 가집니다.
