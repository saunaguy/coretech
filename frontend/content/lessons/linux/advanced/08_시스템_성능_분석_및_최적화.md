### 시스템 자원 모니터링
> 🩺 시스템이 느려지거나 문제가 발생했을 때, 가장 먼저 해야 할 일은 시스템의 핵심 자원(CPU, 메모리, 디스크 I/O) 상태를 확인하는 것입니다.

**1. `vmstat` : 가상 메모리 및 프로세스, CPU 통계 확인**
* 일정 시간 간격으로 시스템의 메모리, 프로세스, CPU 활동에 대한 요약 정보를 보여줍니다. 시스템의 전반적인 부하 상태를 파악하기 좋습니다.
```bash
# 2초 간격으로 5번 상태를 출력
$ vmstat 2 5
```
<details>
<summary>출력 결과 주요 항목 분석</summary>
• r: 실행 대기 중인 프로세스 수(높으면 CPU 바쁨)
• free/buff/cache: 메모리 가용/버퍼/캐시
• si/so: 스왑 인/아웃(지속적 증가 시 메모리 압박)
• us/sy/id/wa: 사용자/커널/유휴/IO대기 시간 비율
</details>

**2. `iostat` : 디스크 입출력(I/O) 통계 확인**
* 디스크의 읽기/쓰기 활동과 CPU 상태를 상세하게 보여줍니다. 디스크 성능 문제를 진단할 때 필수적입니다. (`sysstat` 패키지 설치 필요)
```bash
# 2초 간격으로 디스크 상태를 상세하게(-x) 보여주기
$ iostat -x 2
```
<details>
<summary>출력 결과 주요 항목 분석</summary>
• r/s, w/s: 초당 읽기/쓰기 요청 수
• rkB/s, wkB/s: 초당 처리량(kB)
• await: 요청 평균 대기 시간(ms)
• svctm / %util: 서비스 시간/디스크 사용률(높으면 병목 가능)
</details>

**3. `df` & `du` : 디스크 사용량 확인**
* `df` (Disk Free): 전체 디스크의 남은 용량을 확인합니다.
* `du` (Disk Usage): 특정 디렉토리나 파일이 차지하는 용량을 확인합니다.
```bash
# 사람이 읽기 쉬운 단위(G, M, K)로 전체 디스크 현황 보기
$ df -h

# 현재 디렉토리의 각 하위 디렉토리별 용량 보기
$ du -h --max-depth=1 .
```

---

### 빠른 튜닝 체크리스트
* CPU: 과도한 단일 프로세스는 `taskset`으로 코어 고정, `nice`/`renice` 우선순위 조정
* 메모리: 불필요한 서비스 중지, 스왑 압박 시 `vm.swappiness` 재조정
* 디스크: IO 대기 높으면 스케줄러 점검, 병렬 디스크/RAID/LVM stripe 고려
* 네트워크: 대역폭/RTT에 따른 `sysctl`(rmem/wmem) 튜닝, NIC 오프로드 옵션 확인

### 로그 분석: 문제 해결의 실마리 찾기
> 📝 시스템에 문제가 발생했을 때, 로그 파일은 무엇이, 언제, 왜 잘못되었는지 알려주는 유일한 단서입니다. 효과적인 로그 분석은 숙련된 시스템 관리자의 핵심 역량입니다.

**1. `journalctl` : systemd 환경의 표준 로그 관리자**
* 최신 리눅스 시스템의 표준 로그 관리 도구입니다. 커널, 서비스, 애플리케이션 등 시스템의 모든 로그를 중앙에서 관리하며, 강력한 필터링 기능을 제공합니다.
<details>
<summary>주요 사용 예시</summary>
</details>

**2. `/var/log` : 전통적인 로그 파일 디렉토리**
* 다양한 서비스와 시스템 이벤트가 텍스트 파일 형태로 기록되는 전통적인 로그 저장소입니다. `tail`, `grep`, `less` 같은 텍스트 처리 도구와 함께 사용하면 강력한 분석이 가능합니다.
<details>
<summary>주요 로그 파일</summary>
</details>

```bash
# 인증 로그 파일에서 "Failed password" (실패한 암호)가 포함된 줄 검색
$ sudo grep "Failed password" /var/log/auth.log
```
