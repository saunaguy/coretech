# 2-4-11: 파일 시스템 점검/마운트 (`fsck`, `mount`, `fstab`, `automount`)

리눅스에서 디스크나 파티션을 사용하려면 파일 시스템을 생성하고, 이를 특정 디렉터리에 연결하는 **마운트(Mount)** 과정이 반드시 필요합니다. 또한 파일 시스템에 문제가 생겼을 때 이를 점검하고 복구하는 방법과, 부팅 시 자동으로 마운트되도록 설정하는 방법을 알아봅니다.

## 1. `mount`: 파일 시스템 연결

- **기능**: `mount` 명령어는 특정 저장 장치(파티션, LV, 네트워크 드라이브 등)의 파일 시스템을 리눅스 디렉터리 트리의 특정 위치(**마운트 포인트**)에 연결하는 역할을 합니다.

- **사용법**:
  `mount -t [타입] -o [옵션] [장치] [마운트포인트]`

  - **[장치]**: `/dev/sdb1`, `/dev/my_vg/my_lv` 등 연결할 장치명.
  - **[마운트포인트]**: 장치를 연결할 비어있는 디렉터리 (예: `/mnt`, `/data`).

- **예시**:
  ```bash
  # /dev/sdb1 장치를 /data 디렉터리에 마운트
  sudo mount /dev/sdb1 /data

  # 현재 마운트된 모든 파일 시스템 확인
  mount
  # 또는 df -hT

  # 마운트 해제
  sudo umount /data
  # 또는 sudo umount /dev/sdb1
  ```

- **주요 옵션 (`-o`)**:
    - `ro` / `rw`: 읽기 전용(read-only) 또는 읽기/쓰기(read-write)로 마운트.
    - `noatime`: 파일 접근 시간(access time)을 기록하지 않아 I/O 성능을 향상시킵니다. (서버에서 널리 사용)
    - `defaults`: `rw, suid, dev, exec, auto, nouser, async` 옵션을 모두 포함하는 기본값.

## 2. `fstab`: 부팅 시 자동 마운트 설정

`mount` 명령어로 마운트한 파일 시스템은 재부팅하면 사라집니다. 시스템이 부팅될 때마다 특정 파일 시스템이 자동으로 마운트되도록 설정하려면 `/etc/fstab` (file systems table) 파일을 수정해야 합니다.

- **`/etc/fstab` 파일 구조**:
  한 줄이 하나의 마운트 설정을 의미하며, 6개의 필드로 구성됩니다.
  `[장치] [마운트포인트] [파일시스템타입] [옵션] [덤프] [패스]`

  - **[장치]**: 장치명(예: `/dev/sdb1`)을 직접 쓰는 것보다, 장치 이름이 바뀌어도 문제없는 **UUID**를 사용하는 것이 강력히 권장됩니다. (`blkid` 명령어로 확인 가능)
  - **[마운트포인트]**: 마운트할 디렉터리.
  - **[파일시스템타입]**: `xfs`, `ext4`, `nfs` 등.
  - **[옵션]**: `mount` 명령어의 `-o` 옵션과 동일 (예: `defaults`, `noatime`).
  - **[덤프]**: `dump` 명령어로 백업할지 여부. 보통 `0`으로 설정합니다.
  - **[패스]**: 부팅 시 `fsck`로 파일 시스템을 점검하는 순서. 루트 파일 시스템은 `1`, 나머지는 `2`, 점검하지 않으려면 `0`으로 설정합니다.

- **예시**:
  ```
  # blkid /dev/sdb1 로 UUID 확인 후 추가
  UUID=1234-ABCD-5678  /data  xfs  defaults,noatime  0  2
  ```

- **`fstab` 테스트 및 적용**:
  `fstab` 파일을 수정한 후, 재부팅 없이 바로 설정이 올바른지 테스트하고 적용할 수 있습니다.
  ```bash
  # fstab에 정의된 모든 파일 시스템을 마운트 (이미 마운트된 것은 무시)
  sudo mount -a
  ```
  만약 이 명령에서 오류가 발생하면 `fstab` 설정에 문제가 있는 것이므로, 재부팅 전에 반드시 수정해야 합니다.

## 3. `fsck`: 파일 시스템 점검 및 복구

- **기능**: `fsck` (file system check)는 비정상적인 종료나 디스크 오류 등으로 인해 손상될 수 있는 파일 시스템의 일관성을 검사하고 복구하는 도구입니다. 실제로는 파일 시스템 타입에 맞는 특정 `fsck` 도구(예: `fsck.xfs`, `fsck.ext4`)를 호출해주는 래퍼(wrapper) 명령어입니다.

- **주의사항**: **반드시 마운트되지 않은(unmounted) 파일 시스템에 대해서만 실행해야 합니다.** 마운트된 파일 시스템에 `fsck`를 실행하면 데이터가 심각하게 손상될 수 있습니다.

- **사용법**:
  ```bash
  # 먼저 파일 시스템을 마운트 해제
  sudo umount /dev/sdb1

  # 파일 시스템 점검 및 복구
  sudo fsck /dev/sdb1
  ```
  점검 과정에서 발견된 문제를 어떻게 처리할지 사용자에게 물어볼 수 있습니다. `-y` 옵션을 주면 모든 질문에 자동으로 "yes"로 답하며 복구를 진행합니다.

## 4. `automount` (Autofs)

- **기능**: `autofs` 서비스는 `fstab`과 달리, 특정 디렉터리에 접근하는 시점에 해당 파일 시스템(주로 NFS와 같은 네트워크 파일 시스템)을 자동으로 마운트하고, 일정 시간 사용하지 않으면 자동으로 마운트 해제하는 기능입니다.
- **장점**: 시스템 부팅 시 모든 네트워크 파일 시스템을 마운트하려고 시도하지 않으므로 부팅 속도가 빨라지고, 네트워크 문제 발생 시 부팅이 멈추는 현상을 방지할 수 있습니다. 필요할 때만 마운트하므로 자원 관리에도 효율적입니다.
- **설정**: `/etc/auto.master` 파일과 보조 설정 파일들을 통해 어떤 디렉터리에 접근할 때 어떤 장치를 마운트할지 정의합니다.
