# 2-4-9: 패키지 저장소/리포지토리 설정 (EPEL, PPA, repo 파일)

`dnf`, `yum`, `apt`와 같은 패키지 관리자는 **리포지토리(Repository)**라는 중앙 저장소에 접속하여 패키지 목록을 받고, 필요한 패키지를 다운로드합니다. 기본적으로 각 리눅스 배포판은 공식적으로 지원하는 패키지들만 모아놓은 공식 리포지토리를 사용합니다.

하지만 때로는 공식 리포지토리에 없는 최신 버전의 소프트웨어나 서드파티 프로그램을 설치해야 할 필요가 있습니다. 이때 추가적인 리포지토리를 시스템에 등록하여 패키지 관리자가 더 많은 패키지를 찾을 수 있도록 할 수 있습니다.

## 1. Red Hat 계열 (CentOS, RHEL, Fedora)의 리포지토리 설정

Red Hat 계열 시스템의 리포지토리 설정은 `/etc/yum.repos.d/` 디렉터리 안에 있는 `.repo` 파일들을 통해 관리됩니다.

### `.repo` 파일 구조

- 예시: `/etc/yum.repos.d/CentOS-Base.repo`
  ```ini
  [baseos]
  name=CentOS Stream $releasever - BaseOS
  mirrorlist=http://mirrorlist.centos.org/?release=$releasever&arch=$basearch&repo=BaseOS&infra=$infra
  #baseurl=http://mirror.centos.org/$contentdir/$releasever/BaseOS/$basearch/os/
  gpgcheck=1
  enabled=1
  gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-centosofficial
  ```
  - `[baseos]`: 리포지토리의 고유 ID.
  - `name`: 리포지토리의 설명.
  - `mirrorlist` 또는 `baseurl`: 패키지 파일들이 있는 실제 서버 주소.
  - `enabled=1`: 이 리포지토리를 사용할지 여부 (0은 비활성화).
  - `gpgcheck=1`: 다운로드한 패키지의 GPG 서명을 검증하여 패키지의 신뢰성과 무결성을 확인할지 여부. (보안을 위해 항상 1로 설정하는 것이 좋습니다.)
  - `gpgkey`: GPG 서명 검증에 사용할 공개키의 위치.

### EPEL: 가장 유명한 서드파티 리포지토리

- **EPEL (Extra Packages for Enterprise Linux)**은 Fedora 프로젝트에서 관리하는 리포지토리로, RHEL이나 CentOS의 공식 리포지토리에 포함되지 않는 수많은 고품질 추가 패키지들을 제공합니다. 사실상 표준처럼 사용되는 필수적인 추가 리포지토리입니다.

- **EPEL 설치 방법**:
  ```bash
  # dnf(yum)을 사용하여 epel-release 패키지를 설치하면 자동으로 repo 파일이 추가됨
  sudo dnf install epel-release
  ```
  설치 후 `/etc/yum.repos.d/epel.repo` 파일이 생성된 것을 확인할 수 있습니다.

## 2. Debian 계열 (Ubuntu)의 리포지토리 설정

Debian 계열 시스템의 리포지토리 설정은 주로 `/etc/apt/sources.list` 파일과 `/etc/apt/sources.list.d/` 디렉터리의 `.list` 파일들을 통해 관리됩니다.

### `/etc/apt/sources.list` 파일 구조

- 예시: Ubuntu의 `sources.list`
  ```
  deb http://archive.ubuntu.com/ubuntu/ jammy main restricted universe multiverse
  deb-src http://archive.ubuntu.com/ubuntu/ jammy main restricted universe multiverse
  ```
  - `deb` / `deb-src`: 바이너리 패키지 / 소스 패키지 리포지토리.
  - `http://archive.ubuntu.com/ubuntu/`: 리포지토리 서버 주소.
  - `jammy`: 배포판의 코드명 (예: 22.04 LTS).
  - `main`, `restricted`, `universe`, `multiverse`: 패키지의 라이선스 및 지원 수준에 따른 분류.

### PPA: 개인 패키지 아카이브

- **PPA (Personal Package Archive)**는 Ubuntu 사용자들이 Launchpad라는 플랫폼을 통해 자신만의 `apt` 리포지토리를 만들어 소프트웨어를 쉽게 배포할 수 있도록 하는 서비스입니다. 개발자가 직접 제공하는 최신 버전의 소프트웨어를 설치할 때 주로 사용됩니다.

- **PPA 추가 및 사용 방법**:
  `add-apt-repository` 명령어를 사용하여 PPA를 시스템에 추가할 수 있습니다.

  ```bash
  # 특정 PPA를 시스템에 추가 (예: 최신 버전의 'neovim'을 위한 PPA)
  sudo add-apt-repository ppa:neovim-ppa/stable

  # PPA를 추가했으므로, 패키지 목록을 다시 업데이트해야 함
  sudo apt update

  # 이제 해당 PPA가 제공하는 패키지를 설치할 수 있음
  sudo apt install neovim
  ```
  PPA를 추가하면 `/etc/apt/sources.list.d/` 디렉터리에 해당 PPA의 `.list` 파일이 자동으로 생성됩니다.

- **주의사항**: PPA는 공식적으로 검증된 리포지토리가 아니므로, 신뢰할 수 있는 개발자나 커뮤니티가 제공하는 PPA만 추가해야 합니다. 잘못된 PPA는 시스템을 불안정하게 만들거나 보안 문제를 일으킬 수 있습니다.

## 리포지토리 관리 명령어

- **활성화된 리포지토리 목록 보기**:
  - Red Hat 계열: `dnf repolist`
  - Debian 계열: `apt-cache policy` (또는 `sources.list` 파일 확인)

- **리포지토리 비활성화/활성화**:
  - Red Hat 계열: `dnf config-manager --set-disabled <repo_id>` 또는 `.repo` 파일의 `enabled` 값을 수정.
  - Debian 계열: `add-apt-repository --remove <ppa_name>` 또는 `.list` 파일을 삭제/주석 처리.

리포지토리 관리는 시스템이 접근할 수 있는 소프트웨어의 범위를 결정하는 중요한 작업입니다. 공식 리포지토리를 기반으로 하되, 필요에 따라 EPEL이나 신뢰할 수 있는 PPA를 추가하여 소프트웨어 관리의 유연성을 높일 수 있습니다.
