# 2-4-14: 네트워크 진단 보강 (`nmap`, `dig`, `curl`, `nc`)

기본적인 네트워크 도구(`ping`, `traceroute`)를 넘어, 더 깊이 있는 진단과 상호작용을 가능하게 하는 고급 도구들을 알아봅니다. 이 도구들은 포트 스캔, DNS 상세 조회, HTTP 요청, TCP/UDP 레벨의 통신에 사용됩니다.

## 1. `nmap`: 네트워크 탐색과 보안 감사의 스위스 칼

- **기능**: `nmap` (Network Mapper)은 네트워크에 연결된 호스트를 발견하고, 해당 호스트에서 어떤 서비스(포트)가 열려 있는지, 어떤 운영체제를 사용하는지 등 방대한 정보를 스캔할 수 있는 강력한 네트워크 탐색 도구입니다. 원래는 보안 감사용으로 만들어졌지만, 네트워크 문제를 진단하는 데도 매우 유용합니다.

- **주요 사용 사례**:
    - 특정 서버에 어떤 포트들이 열려 있는지 확인 (방화벽 규칙 검증).
    - 내 네트워크에 어떤 장치들이 연결되어 있는지 확인.
    - 서비스가 특정 포트에서 정상적으로 응답하는지 확인.

- **주요 스캔 유형**:
    - `-sT` (TCP Connect Scan): 가장 기본적인 TCP 스캔. 완전한 3-way handshake를 시도하여 포트가 열려있는지 확인합니다.
    - `-sS` (SYN Stealth Scan): "Half-open" 스캔. SYN 패킷만 보내고 응답(SYN/ACK)을 받으면 포트가 열린 것으로 간주하고 바로 연결을 끊어 로그가 덜 남습니다. (루트 권한 필요)
    - `-p-`: 1번부터 65535번까지 모든 포트를 스캔합니다.
    - `-O`: 원격 호스트의 운영체제를 추측합니다.
    - `-A`: `-O`와 서비스 버전 감지 등 여러 기능을 한 번에 실행하는 공격적인 스캔.

- **예시**:
  ```bash
  # 192.168.1.1 호스트의 자주 사용되는 1000개 포트를 스캔
  nmap 192.168.1.1

  # 특정 호스트의 22번(ssh), 80번(http), 443번(https) 포트가 열려있는지 확인
  nmap -p 22,80,443 example.com

  # SYN 스캔으로 빠르게 포트 상태 확인
  sudo nmap -sS example.com
  ```

## 2. `dig` & `nslookup`: DNS 상세 조회

- **기능**: `dig` (Domain Information Groper)와 `nslookup`은 도메인 이름에 대한 DNS 정보를 조회하는 도구입니다. `ping`이나 웹 브라우저에서 특정 도메인에 접속이 안 될 때, DNS 서버가 해당 도메인을 올바른 IP 주소로 변환(resolve)해주고 있는지 확인할 수 있습니다. `dig`가 `nslookup`보다 더 상세하고 전문적인 정보를 제공하여 현재는 `dig`가 더 선호됩니다.

- **사용법**:
  ```bash
  # google.com의 A 레코드(IP 주소) 조회
  dig google.com

  # MX 레코드(메일 서버) 조회
  dig google.com MX

  # 특정 네임서버(예: 8.8.8.8)에 직접 질의
  dig @8.8.8.8 google.com

  # nslookup 사용 (간단한 조회)
  nslookup google.com
  ```

## 3. `curl`: URL 전송의 만능 도구

- **기능**: `curl` (Client for URLs)은 HTTP, HTTPS, FTP 등 다양한 프로토콜을 사용하여 데이터를 전송(주고받는)할 수 있는 매우 강력하고 유연한 커맨드라인 도구입니다. 웹 서버가 정상적으로 응답하는지, API가 올바른 데이터를 반환하는지 등을 테스트하는 데 필수적입니다.

- **주요 옵션**:
    - `-I` (HEAD): HTTP 헤더 정보만 가져옵니다. (콘텐츠는 받지 않음)
    - `-L` (Location): 서버가 리다이렉션(3xx 응답)을 보내면, 해당 URL로 따라갑니다.
    - `-v` (verbose): 요청과 응답의 전체 과정을 자세하게 보여줍니다. (SSL 핸드셰이크, 헤더 등)
    - `-X`: 요청 메서드를 지정합니다. (예: `GET`, `POST`, `PUT`, `DELETE`)
    - `-d`: POST 요청 시 전송할 데이터를 지정합니다.
    - `-H`: 요청 헤더를 직접 지정합니다.

- **예시**:
  ```bash
  # example.com의 HTML 콘텐츠 가져오기
  curl http://example.com

  # example.com의 HTTP 헤더만 확인
  curl -I http://example.com

  # API에 POST 요청 보내기
  curl -X POST -H "Content-Type: application/json" -d '{"name":"test"}' http://api.example.com/users

  # SSL 인증서 문제를 무시하고 요청 (-k 또는 --insecure)
  curl -k https://self-signed.example.com
  ```

## 4. `nc` (`netcat`): 네트워크의 맥가이버 칼

- **기능**: `netcat`으로도 불리는 `nc`는 TCP나 UDP 프로토콜을 사용하여 네트워크 연결을 읽고 쓰는 모든 작업을 할 수 있는 단순하지만 강력한 유틸리티입니다. 특정 포트가 열려 있는지 간단하게 확인하거나, 간단한 클라이언트/서버를 만들어 테스트하는 등 다양한 용도로 활용됩니다.

- **사용법**:
  ```bash
  # 특정 호스트의 특정 포트가 열려 있는지 확인 (배너 정보 확인)
  # -v: 자세한 정보, -z: 데이터 전송 없이 포트 스캔만 수행
  nc -vz example.com 80
  # Connection to example.com 80 port [tcp/http] succeeded!

  # 간단한 채팅 서버 만들기
  # 서버 측: 12345번 포트에서 연결을 기다림
  nc -l 12345

  # 클라이언트 측: 서버에 연결
  nc localhost 12345
  ```

이러한 고급 도구들은 네트워크의 동작을 더 깊은 수준에서 이해하고, 복잡한 문제를 체계적으로 진단하는 데 큰 도움을 줍니다.
