# 2-4-4: 파일 비교/검증 (`diff`, `cmp`, `md5sum`)

파일의 내용이 같은지, 혹은 어떻게 다른지 비교하거나 파일이 전송 과정에서 변조되지 않았는지 무결성을 검증하는 것은 시스템 관리와 개발에서 매우 중요한 작업입니다. 리눅스는 이를 위한 여러 유용한 도구를 제공합니다.

## 1. `diff`: 두 파일의 차이점을 라인 단위로 분석

- **기능**: `diff` (difference)는 두 개의 텍스트 파일을 **라인(line) 단위**로 비교하여 어떻게 다른지를 상세하게 보여주는 명령어입니다. 어떤 라인이 추가되었는지, 삭제되었는지, 또는 변경되었는지를 알려주어 코드 리뷰나 설정 파일 변경 추적 등에 널리 사용됩니다.

- **주요 옵션**:
    - `-u` (unified): 가장 널리 사용되는 형태로, 변경된 부분의 위아래 문맥(context)을 함께 보여주어 가독성이 높습니다. Git 등 버전 관리 시스템에서 사용하는 diff 형식과 유사합니다.
    - `-i` (ignore-case): 대소문자 차이를 무시합니다.
    - `-w` (ignore-all-space): 모든 공백(whitespace) 차이를 무시합니다.
    - `-r` (recursive): 디렉터리를 비교할 때, 하위의 모든 파일들을 재귀적으로 비교합니다.

- **Unified Diff 형식 읽기**:
  ```diff
  --- file1.txt   2025-09-25 10:00:00.000000000 +0900
  +++ file2.txt   2025-09-25 10:01:00.000000000 +0900
  @@ -1,4 +1,4 @@
   apple
  -banana
  +banaNA
   cherry
   date
  ```
  - `---`: 첫 번째 파일(원본)
  - `+++`: 두 번째 파일(새 버전)
  - `@@ ... @@`: 변경된 부분의 위치 정보 (예: `-1,4`는 원본 파일의 1번째 줄부터 4줄, `+1,4`는 새 파일의 1번째 줄부터 4줄을 의미)
  - `-`: 첫 번째 파일에만 있는 라인 (삭제된 라인)
  - `+`: 두 번째 파일에만 있는 라인 (추가된 라인)
  - 공백으로 시작하는 라인: 두 파일에 공통으로 존재하는 라인 (문맥)

- **예시**:
  ```bash
  # 두 설정 파일의 차이점을 unified 형식으로 보기
  diff -u httpd.conf.old httpd.conf.new

  # 두 디렉터리의 모든 파일 비교하기
  diff -r project-v1/ project-v2/
  ```

## 2. `cmp`: 두 파일의 차이점을 바이트 단위로 확인

- **기능**: `cmp` (compare)는 두 파일을 **바이트(byte) 단위**로 비교하여, 다른 부분이 처음으로 나타나는 위치와 라인 번호를 알려줍니다. 텍스트 파일뿐만 아니라 이미지, 실행 파일 등 바이너리 파일 비교에 유용합니다. `diff`처럼 모든 차이점을 보여주는 것이 아니라, 다른지 같은지만 빠르게 확인하고 싶을 때 사용합니다.

- **예시**:
  ```bash
  $ cmp file1.bin file2.bin
  file1.bin file2.bin differ: byte 102, line 5
  ```
  (두 파일은 102번째 바이트, 5번째 라인에서 처음으로 차이가 발생함)

  만약 두 파일이 완전히 같다면, `cmp`는 아무것도 출력하지 않습니다.

## 3. 해시를 이용한 파일 무결성 검증

파일을 다운로드하거나 복사한 후, 원본과 동일한지, 중간에 데이터가 손상되거나 변조되지 않았는지 확인하는 것을 **무결성 검증**이라고 합니다. 이때 **해시(Hash)** 함수가 사용됩니다. 해시 함수는 파일의 내용을 입력으로 받아, 고정된 길이의 고유한 문자열(해시 값 또는 체크섬)을 출력합니다. 원본 파일의 해시 값과 내가 가진 파일의 해시 값을 비교하여 일치하면 파일이 변조되지 않았음을 확신할 수 있습니다.

### `md5sum` & `sha256sum`

- **`md5sum`**: MD5 해시 알고리즘을 사용하여 128비트(32자리 16진수) 해시 값을 생성합니다. 널리 사용되지만, 현재는 보안 목적으로는 취약점이 발견되어 더 이상 권장되지 않습니다.
- **`sha256sum`**: 더 안전하고 강력한 SHA-256 알고리즘을 사용하여 256비트(64자리 16진수) 해시 값을 생성합니다. 현재 파일 무결성 검증에 널리 권장되는 방식입니다.

- **사용법**:
  ```bash
  # 파일의 SHA-256 해시 값 계산
  $ sha256sum my-image.iso
  e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855  my-image.iso

  # 여러 파일의 해시 값 계산
  $ sha256sum file1.txt file2.txt
  ...
  ```

- **검증 방법**:
  소프트웨어 배포 사이트 등에서는 보통 다운로드 파일과 함께 `SHA256SUMS`와 같은 체크섬 파일을 제공합니다. 이 파일을 이용해 다운로드한 파일들을 한 번에 검증할 수 있습니다.

  1.  다운로드한 파일과 체크섬 파일(`SHA256SUMS`)을 같은 디렉터리에 둡니다.
  2.  `sha256sum` 명령어에 `-c` (check) 옵션을 사용하여 검증합니다.

  ```bash
  $ cat SHA256SUMS
  e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855  my-image.iso
  d1b2c3...  another-file.zip

  $ sha256sum -c SHA256SUMS
  my-image.iso: OK
  another-file.zip: FAILED
  sha256sum: WARNING: 1 computed checksum did NOT match
  ```
  `OK`는 파일이 일치함을, `FAILED`는 파일이 손상되었거나 변조되었음을 의미합니다.
