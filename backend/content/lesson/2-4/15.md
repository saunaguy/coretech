# 2-4-15: 무결성/해시 (`sha256sum`) 및 감사 (`auditd`) 기초

시스템 보안의 중요한 두 축은 **무결성(Integrity)**과 **감사(Auditing)**입니다. 무결성은 데이터가 허가 없이 변경되지 않았음을 보장하는 것이고, 감사는 시스템에서 발생하는 모든 보안 관련 이벤트를 기록하고 추적하는 것입니다.

## 1. 파일 무결성 검증: 해시(Hash)

(이 내용은 `2-4-4`에서 다룬 `md5sum`, `sha256sum`과 중복되지만, 보안 관점에서 다시 한번 강조합니다.)

해시 함수는 파일의 내용을 바탕으로 고유한 디지털 지문(체크섬)을 생성합니다. 이 해시 값을 비교함으로써 파일이 원본과 동일한지, 즉 변조되지 않았는지 확인할 수 있습니다.

- **`sha256sum`**: 현재 파일 무결성 검증에 널리 사용되는 표준적인 해시 알고리즘입니다. SHA-2(Secure Hash Algorithm 2) 계열에 속하며 256비트 길이의 해시 값을 생성합니다.
- **`shasum`**: Perl 기반의 해시 계산 도구로, `-a` 옵션을 통해 SHA-1, SHA-256, SHA-512 등 다양한 알고리즘을 선택할 수 있습니다.

### 사용 시나리오

1.  **소프트웨어 다운로드 검증**: 신뢰할 수 있는 출처에서 소프트웨어를 다운로드할 때, 제공된 SHA-256 체크섬과 다운로드한 파일의 체크섬을 비교하여 파일이 전송 중 변조되지 않았는지 확인합니다.

    ```bash
    # 다운로드한 파일의 SHA-256 해시 계산
    sha256sum downloaded_file.iso

    # 웹사이트에 게시된 해시 값과 눈으로 직접 비교
    ```

2.  **중요 설정 파일의 변경 감지**: 시스템의 중요 설정 파일들(예: `/etc/passwd`, `/etc/sudoers`)의 해시 값을 미리 계산하여 저장해 둡니다. 그리고 주기적으로 현재 파일의 해시 값과 저장된 값을 비교하여 허가되지 않은 변경이 있었는지 감지할 수 있습니다. (AIDE, Tripwire와 같은 호스트 기반 침입 탐지 시스템(HIDS)이 이 원리를 사용합니다.)

    ```bash
    # 초기 해시 값 저장
    sha256sum /etc/ssh/sshd_config > sshd_config.sha256

    # 나중에 검증
    sha256sum -c sshd_config.sha256
    # /etc/ssh/sshd_config: OK (변경 없음)
    # /etc/ssh/sshd_config: FAILED (변경됨)
    ```

## 2. 시스템 감사: `auditd`

- **기능**: `auditd` (Audit Daemon)는 리눅스 커널의 감사 기능(Audit Framework)과 연동하여, 시스템에서 발생하는 보안 관련 이벤트를 정책에 따라 기록하는 핵심적인 감사 시스템입니다. "누가, 언제, 어디서, 무엇을 했는가"에 대한 상세한 로그를 남겨, 사후 추적과 책임 소재 규명, 규정 준수(Compliance) 등에 사용됩니다.

- **주요 추적 이벤트**:
    - 특정 파일이나 디렉터리에 대한 접근(읽기, 쓰기, 실행).
    - 시스템 콜(System Call) 호출.
    - 사용자 로그인, 로그아웃, 계정 변경.
    - SELinux 관련 이벤트.

### `auditd` 관련 도구

- **`auditd`**: 감사 로그를 생성하는 백그라운드 데몬.
- **`auditctl`**: 감사 규칙을 설정하고 제어하는 명령어. (어떤 이벤트를 기록할지 정의)
- **`ausearch`**: 생성된 감사 로그 파일(`/var/log/audit/audit.log`)을 검색하고 조회하는 명령어.
- **`aureport`**: 감사 로그를 요약하여 통계 리포트를 생성하는 명령어.

### 감사 규칙 설정 (`auditctl`)

감사 규칙은 `/etc/audit/rules.d/` 디렉터리에 `.rules` 파일로 정의하며, 시스템 부팅 시 `auditd`가 이 규칙들을 읽어 적용합니다.

- **주요 규칙 유형**:
    - **파일/디렉터리 감시 (`-w`)**: 특정 파일에 대한 접근을 감시합니다.
    - **시스템 콜 감시 (`-a`)**: 특정 시스템 콜의 사용을 감시합니다.

- **규칙 예시**:
  ```bash
  # /etc/passwd 파일에 대한 모든 쓰기(w)와 속성 변경(a)을 감시
  # -p wa: 권한(permission)을 지정
  # -k passwd_changes: 이 이벤트를 식별하기 위한 키(key) 지정
  auditctl -w /etc/passwd -p wa -k passwd_changes

  # 32비트 시스템에서 chown 시스템 콜이 사용될 때마다 기록
  auditctl -a always,exit -F arch=b32 -S chown -k user_group_changes
  ```

### 로그 검색 (`ausearch`)

`audit.log`는 매우 상세하고 복잡하므로, `ausearch`를 사용하여 의미 있는 정보를 필터링하는 것이 중요합니다.

```bash
# 위에서 설정한 "passwd_changes" 키로 이벤트 검색
ausearch -k passwd_changes

# 특정 사용자(UID 1001)에 대한 이벤트 검색
ausearch -ui 1001

# 특정 시간 이후의 이벤트 검색
ausearch -ts recent
```

무결성 검증과 감사는 시스템 보안을 강화하고, 문제가 발생했을 때 원인을 추적할 수 있는 중요한 안전장치입니다. 특히 `auditd`는 복잡하지만, 보안이 중요한 서버 환경에서는 반드시 설정하고 관리해야 할 핵심 기능입니다.
