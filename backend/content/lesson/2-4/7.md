# 2-4-7: 네트워크 기초 도구 (`ping`, `traceroute`, `netstat`, `ss`)

네트워크 문제를 진단하고 해결하는 것은 시스템 관리의 가장 기본적인 역량 중 하나입니다. 리눅스는 네트워크 상태를 확인하고 문제를 추적하는 데 유용한 여러 강력한 커맨드라인 도구를 제공합니다.

## 1. `ping`: 연결의 시작

- **기능**: `ping` (Packet INternet Groper)은 대상 호스트(서버)가 네트워크상에서 응답하는지 확인하는 가장 기본적인 도구입니다. **ICMP(Internet Control Message Protocol)** 라는 프로토콜의 `echo request` 패킷을 보내고, 대상 호스트가 `echo reply` 패킷으로 응답하는지를 확인하여 네트워크 연결 상태와 응답 시간을 측정합니다.

- **주요 사용 사례**:
    - 특정 서버(예: google.com)가 살아있는지 확인.
    - 나와 특정 서버 간의 네트워크 지연 시간(latency) 측정.
    - DNS가 정상적으로 동작하는지 확인 (도메인 이름으로 ping이 성공하면).

- **사용법**:
  ```bash
  # google.com으로 ping 보내기 (Ctrl+C를 누를 때까지 계속 보냄)
  ping google.com

  # 5번만 ping 보내고 종료 (-c 옵션)
  ping -c 5 8.8.8.8
  ```
  - `time=... ms`: 응답 시간. 낮을수록 좋습니다.
  - `packet loss`: 패킷 손실률. 0%가 아니면 네트워크에 문제가 있을 수 있습니다.

## 2. `traceroute`: 목적지까지의 경로 추적

- **기능**: `traceroute`는 내 컴퓨터에서 목적지 호스트까지 패킷이 어떤 경로(어떤 라우터들을 거쳐 가는지)를 통해 전달되는지 보여주는 도구입니다. 네트워크 중간의 어느 지점에서 문제가 발생했는지(지연이 심하거나, 패킷이 더 이상 전달되지 않거나) 파악하는 데 매우 유용합니다.

- **동작 원리**: 패킷의 **TTL(Time To Live)** 값을 1부터 점차 늘려가며 보냅니다. TTL은 패킷이 라우터를 하나 거칠 때마다 1씩 감소하며, 0이 되면 해당 라우터는 패킷을 버리고 "Time Exceeded" ICMP 메시지를 출발지로 보냅니다. `traceroute`는 이 응답을 받아 각 단계의 라우터 주소를 알아냅니다.

- **사용법**:
  ```bash
  # google.com까지의 경로 추적
  traceroute google.com
  ```
  - 각 줄은 경로상의 라우터(홉, hop)를 의미합니다.
  - `* * *`가 표시되는 경우, 해당 라우터가 응답하지 않거나 방화벽에 의해 차단되었음을 의미합니다.

## 3. `netstat`: 구관이 명관인 네트워크 상태 정보

- **기능**: `netstat` (network statistics)는 시스템의 네트워크 연결, 라우팅 테이블, 인터페이스 통계 등 전반적인 네트워크 상태 정보를 보여주는 전통적인 명령어입니다.

- **주요 옵션**:
    - `-n` (numeric): 호스트 이름이나 포트 이름을 숫자로 표시합니다. (더 빠름)
    - `-t` (tcp): TCP 프로토콜 연결만 보여줍니다.
    - `-u` (udp): UDP 프로토콜 연결만 보여줍니다.
    - `-l` (listen): 현재 "LISTEN" 상태, 즉 연결을 기다리고 있는 포트만 보여줍니다.
    - `-p` (program): 해당 포트를 사용하고 있는 프로세스의 이름과 PID를 보여줍니다. (루트 권한 필요)

- **자주 쓰는 조합**:
  ```bash
  # 현재 LISTEN 중인 모든 TCP/UDP 포트와 관련 프로세스 확인
  sudo netstat -ntlp
  sudo netstat -nulp
  ```

## 4. `ss`: `netstat`의 현대적인 대체재

- **기능**: `ss` (socket statistics)는 `netstat`을 대체하기 위해 만들어진 최신 도구입니다. 커널의 TCP 스택 정보를 직접 가져오므로, 특히 연결이 매우 많은 시스템에서 `netstat`보다 훨씬 빠르게 동작합니다.

- **`netstat`과의 옵션 호환성**: `netstat`의 주요 옵션(`-n`, `-t`, `-u`, `-l`, `-p`)을 거의 동일하게 사용할 수 있어 쉽게 전환할 수 있습니다.

- **자주 쓰는 조합**:
  ```bash
  # netstat -ntlp와 동일한 기능
  sudo ss -ntlp

  # netstat -nulp와 동일한 기능
  sudo ss -nulp
  ```

- **`ss`의 추가 기능**: 특정 조건으로 연결을 필터링하는 기능이 강력합니다.
  ```bash
  # 80번 포트(http)를 사용하는 모든 연결 보기
  ss -nt '( dport = :80 or sport = :80 )'

  # 특정 IP 주소(1.2.3.4)와 관련된 모든 연결 보기
  ss -nt dst 1.2.3.4
  ```

**결론**: 간단한 연결 확인은 `ping`, 경로 추적은 `traceroute`, 시스템의 포트 및 연결 상태 확인은 `ss` (또는 익숙하다면 `netstat`)를 사용하는 것이 일반적인 네트워크 진단 워크플로우입니다. 특히 어떤 프로세스가 어떤 포트를 사용하고 있는지 확인할 때 `ss -ntlp`나 `netstat -ntlp`는 반드시 기억해야 할 중요한 명령어 조합입니다.
