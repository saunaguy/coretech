# 2-4-6: 스토리지 관리 (`fdisk`, LVM, RAID, Multipath)

서버에서 스토리지를 관리하는 것은 단순히 디스크를 장착하고 포맷하는 것 이상의 복잡한 작업들을 포함합니다. 용량의 유연한 확장, 데이터 안정성 확보, 성능 향상 등을 위해 LVM, RAID와 같은 고급 스토리지 기술이 사용됩니다.

## 1. 파티셔닝: `fdisk`

- **기능**: `fdisk`는 하드 디스크에 **파티션(Partition)**을 생성, 수정, 삭제하는 전통적인 도구입니다. 파티션은 하나의 물리적 디스크를 여러 개의 논리적인 구역으로 나누는 것을 의미하며, 각 파티션은 독립적인 파일 시스템을 가질 수 있습니다.
- **GPT vs MBR**: 현대의 2TB 이상 대용량 디스크는 대부분 **GPT(GUID Partition Table)** 방식을 사용합니다. 오래된 시스템이나 2TB 미만 디스크에서는 **MBR(Master Boot Record)** 방식이 사용될 수 있습니다. `fdisk`는 두 방식 모두를 지원하며, 대화형 인터페이스를 통해 파티션 작업을 수행합니다.

- **사용법 (대화형)**:
  ```bash
  # /dev/sdb 디스크에 대한 파티션 작업 시작
  sudo fdisk /dev/sdb
  ```
  - `m`: 도움말 보기
  - `p`: 현재 파티션 테이블 출력
  - `n`: 새 파티션 생성
  - `d`: 파티션 삭제
  - `t`: 파티션 타입 변경 (예: Linux, LVM, RAID)
  - `w`: 변경 사항을 디스크에 저장하고 종료
  - `q`: 변경 사항을 저장하지 않고 종료

## 2. LVM (Logical Volume Manager): 유연한 볼륨 관리

- **개념**: LVM은 여러 개의 물리적 디스크나 파티션을 하나의 큰 논리적 저장 공간으로 통합하고, 필요에 따라 논리적 볼륨의 크기를 동적으로 늘리거나 줄일 수 있게 해주는 매우 유연한 스토리지 관리 기술입니다.

- **LVM의 3단계 구조**:
    1.  **PV (Physical Volume)**: 물리적 디스크 또는 파티션에 LVM 메타데이터를 추가하여 LVM에서 사용할 수 있는 상태로 만듭니다. (`pvcreate` 명령 사용)
    2.  **VG (Volume Group)**: 하나 이상의 PV들을 모아 하나의 큰 저장 공간 그룹을 만듭니다. (`vgcreate` 명령 사용)
    3.  **LV (Logical Volume)**: VG라는 큰 저장 공간에서 필요한 만큼의 용량을 할당받아 생성하는 논리적인 볼륨입니다. 이 LV를 포맷하여 실제 사용하게 됩니다. (`lvcreate` 명령 사용)

- **장점**:
    - **온라인 확장**: 서비스 중단 없이 파일 시스템의 용량을 늘릴 수 있습니다.
    - **유연성**: 여러 디스크를 하나처럼 사용하거나, 하나의 디스크를 여러 용도로 나눠 쓰기 편리합니다.
    - **스냅샷(Snapshot)**: 특정 시점의 LV 상태를 그대로 복사하여 백업이나 테스트에 활용할 수 있습니다.

- **주요 명령어**:
  ```bash
  # PV 생성
  pvcreate /dev/sdb1 /dev/sdc1

  # VG 생성 (my_vg라는 이름으로)
  vgcreate my_vg /dev/sdb1 /dev/sdc1

  # LV 생성 (my_vg에서 10GB를 할당받아 my_lv라는 이름으로)
  lvcreate -L 10G -n my_lv my_vg

  # LV 용량 확장 (5GB 추가)
  lvextend -L +5G /dev/my_vg/my_lv
  # 이후 파일 시스템도 확장해야 함 (예: resize2fs /dev/my_vg/my_lv)
  ```

## 3. RAID (Redundant Array of Independent Disks): 안정성과 성능

- **개념**: RAID는 여러 개의 물리적 디스크를 하나의 논리적 단위로 묶어 **데이터 안정성(Redundancy)**이나 **성능(Performance)**을 향상시키는 기술입니다.

- **주요 RAID 레벨**:
    - **RAID 0 (Striping)**: 데이터를 여러 디스크에 분산 저장하여 읽기/쓰기 속도를 높입니다. 하지만 하나의 디스크만 고장 나도 모든 데이터가 손실되므로 안정성은 오히려 떨어집니다.
    - **RAID 1 (Mirroring)**: 두 개 이상의 디스크에 동일한 데이터를 복제하여 저장합니다. 하나의 디스크가 고장 나도 다른 디스크에 데이터가 그대로 남아 있어 안정성이 매우 높습니다. 하지만 사용 가능한 용량은 전체 디스크 용량의 절반이 됩니다.
    - **RAID 5 (Parity)**: 최소 3개 이상의 디스크를 사용하여 데이터와 함께 **패리티(Parity)** 정보를 분산 저장합니다. 하나의 디스크가 고장 나도 남은 데이터와 패리티 정보를 이용해 데이터를 복구할 수 있습니다. 속도, 용량, 안정성을 절충한 방식으로 널리 사용됩니다.
    - **RAID 6**: RAID 5와 유사하지만, 2개의 패리티 정보를 사용하여 2개의 디스크가 동시에 고장 나도 복구할 수 있습니다. 더 높은 안정성을 제공합니다.

- 리눅스에서는 `mdadm`이라는 도구를 사용하여 소프트웨어 RAID를 구성할 수 있습니다.

## 4. Multipath: 고가용성을 위한 다중 경로

- **개념**: 서버가 스토리지(주로 SAN 스토리지)에 연결될 때, 단일 경로(케이블, 스위치, 컨트롤러 등)에 장애가 발생하면 스토리지 접근이 불가능해지는 문제를 해결하기 위한 기술입니다. 서버와 스토리지 사이에 여러 개의 경로를 구성하고, 이를 하나의 논리적인 장치처럼 보이게 만들어 특정 경로에 장애가 발생해도 다른 경로를 통해 중단 없이 서비스할 수 있도록 합니다.

- **주요 기능**:
    - **고가용성(High Availability)**: 경로 장애 시 자동으로 다른 경로로 전환(Failover)합니다.
    - **성능 향상(Load Balancing)**: 여러 경로에 I/O를 분산하여 성능을 높일 수 있습니다.

- 리눅스에서는 `multipath-tools` 패키지를 설치하고 `multipathd` 데몬을 설정하여 Multipath를 구성합니다.

이러한 고급 스토리지 기술들은 기업 환경의 서버에서 데이터를 안전하고 효율적으로 관리하기 위한 필수적인 요소들입니다.
