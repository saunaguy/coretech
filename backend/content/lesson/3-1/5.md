# 3-1-5: 스토리지 운영: `fstab`(`noatime`/`discard`), LVM 스냅샷, `fsck`

스토리지는 서버 성능과 안정성에 직접적인 영향을 미치는 핵심 요소입니다. 파일 시스템을 어떻게 마운트하고, 데이터를 어떻게 안전하게 백업하며, 문제가 생겼을 때 어떻게 복구할 것인지에 대한 운영 전략을 알아봅니다.

## 1. `/etc/fstab` 최적화: `noatime`과 `discard`

`/etc/fstab` 파일은 부팅 시 파일 시스템을 어떻게 마운트할지 결정하는 중요한 설정 파일입니다. 여기에 몇 가지 옵션을 추가하는 것만으로도 성능을 개선하고 스토리지의 수명을 늘릴 수 있습니다.

### `noatime`: 불필요한 I/O 줄이기

- **기능**: 리눅스는 기본적으로 파일이 읽힐 때마다 해당 파일의 메타데이터에 **접근 시간(access time, atime)**을 기록합니다. 하지만 대부분의 서버 환경에서 이 정보는 거의 사용되지 않으며, 모든 읽기 작업에 쓰기 작업이 동반되므로 상당한 I/O 부하를 유발합니다.
- **`noatime` 옵션**: `atime` 업데이트를 완전히 비활성화하여 불필요한 쓰기 작업을 없애고 I/O 성능을 향상시킵니다. 데이터베이스나 웹 서버와 같이 읽기 작업이 빈번한 서비스에 매우 효과적입니다.

- **설정 예시 (`/etc/fstab`)**:
  ```
  # [장치]              [마운트포인트] [타입] [옵션]                  [덤프] [패스]
  UUID=1234-ABCD...   /data          xfs    defaults,noatime        0      2
  ```

### `discard`: SSD를 위한 TRIM 활성화

- **기능**: SSD(Solid State Drive)는 특성상 파일 시스템에서 데이터가 삭제되었다는 것을 바로 알지 못합니다. `discard` 옵션은 파일 시스템에서 파일이 삭제될 때, SSD 컨트롤러에게 해당 블록이 비었음을 알려주는 **TRIM** 명령을 전달하는 역할을 합니다.
- **효과**: SSD는 미리 비어있는 블록을 알고 있음으로써, 나중에 쓰기 작업을 할 때 "삭제 표시 -> 쓰기" 대신 "쓰기"만 수행하여 쓰기 성능 저하를 방지하고 SSD의 수명을 늘릴 수 있습니다.
- **주의사항**: 오래된 SSD나 일부 SAN 스토리지 환경에서는 TRIM 지원이 불안정할 수 있으므로, 하드웨어 호환성을 확인하고 사용하는 것이 좋습니다. 최근에는 `fstrim` 명령을 `cron`이나 `systemd timer`로 주기적으로 실행하는 방식이 더 선호되기도 합니다.

- **설정 예시 (`/etc/fstab`)**:
  ```
  # SSD 장치에 discard 옵션 추가
  UUID=5678-EFGH...   /var/lib/mysql   ext4   defaults,noatime,discard  0  2
  ```

## 2. LVM 스냅샷: 온라인 백업의 핵심

- **기능**: LVM 스냅샷(Snapshot)은 특정 시점의 논리 볼륨(LV) 상태를 그대로 "사진 찍듯이" 복사해두는 기능입니다. 스냅샷은 원본 볼륨과 동일한 데이터를 가리키지만, 원본 볼륨에 변경이 발생하면 변경되기 전의 원본 데이터 블록을 스냅샷 공간에 따로 저장합니다(Copy-on-Write).

- **장점**:
    - **온라인 백업**: 서비스 중단 없이, 특정 시점의 일관된 데이터 상태를 백업할 수 있습니다. (예: DB 데이터를 백업하기 직전에 스냅샷 생성)
    - **안전한 테스트**: 중요한 변경 작업(패치, 업그레이드 등)을 하기 전에 스냅샷을 만들어두면, 문제가 발생했을 때 스냅샷 시점으로 빠르고 쉽게 롤백(revert)할 수 있습니다.

- **사용법**:
  ```bash
  # 1. my_vg/data_lv에 대한 스냅샷(data_snap) 생성 (1G의 스냅샷 공간 할당)
  # 스냅샷 공간은 변경되는 데이터만 저장하므로 원본보다 훨씬 작아도 됨
  sudo lvcreate -L 1G -s -n data_snap /dev/my_vg/data_lv

  # 2. 스냅샷 볼륨을 마운트하여 백업 작업 수행
  sudo mount /dev/my_vg/data_snap /mnt/backup
  # ... /mnt/backup 디렉터리의 내용을 백업 ...
  sudo umount /mnt/backup

  # 3. 백업 완료 후 스냅샷 삭제
  sudo lvremove /dev/my_vg/data_snap
  ```

## 3. `fsck`: 파일 시스템 복구

(이 내용은 `2-4-11`에서 다루었지만, 운영 관점에서 다시 정리합니다.)

- **시나리오**: 시스템이 비정상적으로 종료된 후 부팅 시, 특정 파일 시스템 마운트에 실패하며 부팅이 멈추는 경우가 있습니다. 이는 파일 시스템에 오류가 발생했음을 의미하며, `fsck`를 이용한 복구가 필요합니다.

- **복구 절차 (긴급 복구 모드)**:
    1.  부팅 실패 시, 시스템은 보통 긴급 복구 셸(emergency shell)로 진입합니다. 루트 파일 시스템이 읽기 전용(read-only)으로 마운트되어 있을 수 있습니다.
    2.  `journalctl -xb` 명령으로 부팅 로그를 확인하여 어떤 장치의 파일 시스템에 문제가 발생했는지 확인합니다. (예: `/dev/sda3`)
    3.  **해당 파일 시스템이 마운트 해제된 상태인지 반드시 확인합니다.** (`mount | grep /dev/sda3`)
    4.  `fsck`를 실행하여 파일 시스템을 점검하고 복구합니다.
        ```bash
        fsck /dev/sda3
        ```
        - 복구 과정에서 여러 질문이 나올 수 있으며, 잘 모를 경우 기본값(yes)으로 답하는 것이 일반적입니다. `-y` 옵션을 주면 자동으로 복구를 진행합니다 (`fsck -y /dev/sda3`).
    5.  복구가 완료되면 `reboot` 명령으로 시스템을 재시작합니다.

안정적인 스토리지 운영은 성능 최적화(`noatime`), 데이터 보호(LVM 스냅샷), 그리고 장애 복구(`fsck`)라는 세 가지 축을 중심으로 이루어집니다. 이러한 도구와 개념을 잘 이해하고 활용하는 것은 서버 관리자의 핵심 역량입니다.
