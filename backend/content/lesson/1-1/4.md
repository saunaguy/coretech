# 1-1-4: 시스템 콜과 핸즈온

응용 프로그램은 어떻게 운영체제의 기능을 사용해서 파일을 읽거나 네트워크 통신을 할 수 있을까요? 그 비밀은 바로 '시스템 콜'에 있습니다.

## 1. 📞 시스템 콜 (System Call)

- **정의**: 응용 프로그램(프로세스)이 운영체제 커널이 제공하는 기능을 사용하기 위한 **공식적인 인터페이스(문)**입니다. 프로그램은 파일 생성, 네트워크 연결, 메모리 할당과 같은 특권이 필요한 작업을 직접 수행할 수 없으며, 반드시 운영체제에 요청해야 합니다. 이때 사용되는 것이 시스템 콜입니다.

- **왜 필요한가?**: 시스템의 안정성과 보안을 위해서입니다. 만약 모든 프로그램이 하드웨어에 직접 접근할 수 있다면, 하나의 잘못된 프로그램이 전체 시스템을 망가뜨리거나 다른 프로그램의 데이터를 훔쳐볼 수 있습니다. 이를 막기 위해 운영체제는 하드웨어와 중요한 시스템 자원을 독점적으로 관리하고, 오직 시스템 콜이라는 정해진 통로를 통해서만 접근을 허용합니다.

## 2. 🔒 사용자 모드 vs. 커널 모드

시스템 콜의 필요성을 이해하려면 CPU의 두 가지 작동 모드를 알아야 합니다.

- **사용자 모드 (User Mode)**
    - 일반적인 응용 프로그램이 실행되는 모드입니다.
    - 하드웨어 자원에 직접 접근하는 것이 금지되어 있습니다.
    - 할당된 메모리 영역에만 접근할 수 있어 다른 프로세스에 영향을 주지 않습니다.
    - 우리가 사용하는 대부분의 프로그램(웹 브라우저, 텍스트 에디터 등)은 사용자 모드에서 실행됩니다.

- **커널 모드 (Kernel Mode)**
    - 운영체제 커널이 실행되는 모드입니다.
    - CPU, 메모리, 디스크 등 모든 시스템 자원에 접근할 수 있는 **절대적인 권한**을 가집니다.
    - 시스템 콜이 호출되면, CPU는 사용자 모드에서 커널 모드로 전환하여 요청된 작업을 처리합니다.

### 시스템 콜의 동작 과정 (단순화)

1.  **요청**: 사용자 모드의 응용 프로그램이 파일 읽기(`read`)와 같은 작업을 요청합니다. (정확히는 C 라이브러리 함수를 호출)
2.  **트랩 (Trap)**: C 라이브러리는 내부적으로 CPU에게 시스템 콜을 요청하는 특별한 명령어(e.g., `syscall`)를 실행합니다. 이 순간 CPU는 '트랩'이라는 인터럽트를 발생시키고, 실행 모드를 **사용자 모드에서 커널 모드로 전환**합니다.
3.  **커널 작업 수행**: 커널은 요청받은 시스템 콜 번호에 해당하는 커널 함수(e.g., `sys_read`)를 찾아 실행합니다. 예를 들어, 디스크 컨트롤러에 명령을 보내 파일을 읽어옵니다.
4.  **반환**: 커널은 작업 결과를 응용 프로그램에 반환하고, CPU는 다시 **커널 모드에서 사용자 모드로 전환**합니다.
5.  **복귀**: 응용 프로그램은 커널로부터 받은 결과를 바탕으로 다음 작업을 계속 수행합니다.

## 3. 🔬 핸즈온: `strace`로 시스템 콜 관찰하기

`strace`는 특정 프로그램이 실행되는 동안 어떤 시스템 콜을 사용하는지 실시간으로 추적해서 보여주는 강력한 디버깅 도구입니다. 이를 통해 프로그램의 내부 동작을 엿볼 수 있습니다.

**사용법**: `strace [실행할 명령어]`

### 예제 1: `ls` 명령어 분석

`ls` 명령어가 현재 디렉터리의 파일 목록을 어떻게 화면에 출력하는지 시스템 콜을 통해 살펴봅시다.

```bash
# strace ls
```

출력되는 수많은 시스템 콜 중에서 핵심적인 몇 가지를 살펴보면 다음과 같은 흐름을 볼 수 있습니다. (출력은 시스템마다 다를 수 있습니다)

- `execve("/bin/ls", ...)`: `ls` 프로그램을 실행합니다.
- `openat(AT_FDCWD, ".", ...)`: 현재 디렉터리(`.`)를 엽니다.
- `getdents64(...)`: 열린 디렉터리에서 파일/디렉터리 목록 정보를 읽어옵니다.
- `write(1, "file1.txt\nfile2.log\n...", ...)`: 파일 목록을 표준 출력(화면, 파일 디스크립터 1번)에 씁니다.
- `close(...)`: 열었던 디렉터리를 닫습니다.

**분석**: `ls`는 단순히 파일 목록을 보여주는 간단한 명령어처럼 보이지만, 내부적으로는 디렉터리를 열고(`openat`), 내용을 읽고(`getdents64`), 화면에 쓰는(`write`) 시스템 콜을 통해 운영체제와 긴밀하게 통신하고 있음을 알 수 있습니다.

### 예제 2: `cat /dev/null` 분석

`/dev/null`은 모든 입력을 무시하고 아무것도 출력하지 않는 특수한 파일입니다. 이 파일을 `cat`으로 읽으려고 하면 어떤 일이 일어날까요?

```bash
# strace cat /dev/null
```

- `openat(AT_FDCWD, "/dev/null", ...)`: `/dev/null` 파일을 읽기 모드로 엽니다.
- `read(3, "", 65536)`: 파일 디스크립터 3번(`/dev/null`)에서 데이터를 읽으려고 시도합니다. 하지만 `/dev/null`은 항상 비어있으므로, 아무것도 읽지 못하고 즉시 0을 반환합니다 (파일의 끝을 의미).
- `write(1, "", 0)`: 읽은 내용이 없으므로 표준 출력(화면)에 아무것도 쓰지 않습니다.
- `close(3)`: 파일을 닫습니다.

**분석**: `cat` 프로그램은 파일을 열고(`openat`), 내용이 없을 때까지 계속 읽고(`read`), 읽은 내용을 화면에 쓰는(`write`) 동작을 반복합니다. `strace`를 통해 이 기본 동작 원리를 명확하게 확인할 수 있습니다.

이처럼 `strace`는 시스템 콜을 직접 눈으로 확인하게 해 줌으로써, 리눅스 시스템의 깊은 동작 원리를 이해하는 데 매우 유용한 도구입니다.
