# 1-1-10: 1-1장 핸즈온, 체크, 요약

지금까지 운영체제와 하드웨어의 기본적인 상호작용에 대해 배웠습니다. 이번 장에서는 배운 내용을 요약하고, 간단한 명령어를 통해 실제 시스템을 확인하며, 핵심 개념을 잘 이해했는지 스스로 점검해 봅니다.

## 1. 📝 1-1장 핵심 요약

- **하드웨어와 운영체제**: 운영체제는 CPU, 메모리, 스토리지와 같은 복잡한 하드웨어 자원을 관리하고, 사용자에게 편리한 인터페이스를 제공하는 시스템 소프트웨어입니다.

- **프로세스**: 디스크에 저장된 정적인 프로그램이 메모리에 올라와 실행되는 동적인 상태를 말하며, 자신만의 독립된 메모리 공간을 가집니다.

- **메모리와 스왑**: 운영체제는 가상 메모리 기법을 통해 각 프로세스에게 실제보다 큰 메모리 공간을 제공합니다. 물리적 메모리(RAM)가 부족하면, 디스크의 일부(스왑 공간)를 임시 메모리로 사용하여 시스템의 안정성을 유지합니다.

- **파일 시스템과 아이노드**: 파일 시스템은 디스크에 파일을 체계적으로 저장하고 관리하는 논리적 구조입니다. 아이노드(Inode)는 파일의 실제 데이터를 제외한 모든 메타데이터(권한, 크기, 시간 등)를 저장하는 핵심 데이터 구조입니다.

- **모드와 시스템 콜**: 시스템 보호를 위해 CPU는 **사용자 모드**와 **커널 모드**로 나뉘어 동작합니다. 사용자 프로그램이 파일 입출력과 같은 특권 작업을 수행하려면, 커널에 서비스를 요청하는 유일한 통로인 **시스템 콜**을 사용해야 합니다.

## 2. 🔬 주요 명령어 핸즈온

터미널을 열고 다음 명령어들을 직접 입력해보며 자신의 리눅스 시스템 정보를 확인해 보세요.

- **CPU 정보 확인**: `lscpu`
    - 시스템에 장착된 CPU의 아키텍처, 코어 수, 클럭 속도 등 상세한 정보를 보여줍니다.
    ```bash
    $ lscpu
    Architecture:        x86_64
    CPU op-mode(s):      32-bit, 64-bit
    Byte Order:          Little Endian
    CPU(s):              8
    On-line CPU(s) list: 0-7
    ...
    ```

- **메모리 상태 확인**: `free -h`
    - 전체 메모리, 사용 중인 메모리, 여유 메모리, 그리고 스왑(Swap) 공간의 크기와 사용량을 사람이 읽기 쉬운 단위(GB, MB)로 보여줍니다.
    ```bash
    $ free -h
                  total        used        free      shared  buff/cache   available
    Mem:           15Gi       4.5Gi       4.8Gi       1.2Gi       6.1Gi       9.5Gi
    Swap:         2.0Gi          0B       2.0Gi
    ```

- **디스크(파일 시스템) 사용량 확인**: `df -h`
    - 현재 시스템에 마운트된 파일 시스템들의 전체 크기, 사용량, 남은 용량을 보여줍니다. `df`는 "Disk Free"의 약자입니다.
    ```bash
    $ df -h
    Filesystem      Size  Used Avail Use% Mounted on
    /dev/sda1        50G   20G   30G  40% /
    tmpfs           7.8G     0  7.8G   0% /dev/shm
    ...
    ```

- **커널 버전 및 시스템 정보 확인**: `uname -a`
    - 현재 실행 중인 리눅스 커널의 이름, 버전, 시스템 아키텍처 등 전반적인 시스템 정보를 보여줍니다.
    ```bash
    $ uname -a
    Linux my-desktop 5.15.0-48-generic #54-Ubuntu SMP ... x86_64 x86_64 x86_64 GNU/Linux
    ```

- **시스템 콜 추적 (복습)**: `strace`
    - `strace whoami` 명령을 실행하여, 현재 사용자의 이름을 출력하는 간단한 명령어가 어떤 시스템 콜을 통해 동작하는지 관찰해 보세요. `write()` 시스템 콜로 사용자 이름을 화면에 출력하는 것을 확인할 수 있습니다.

## 3. 🤔 개념 체크 (Check Your Understanding)

아래 질문에 스스로 답해보며 배운 내용을 점검해 보세요.

- **Q1: 프로그램과 프로세스의 주된 차이점은 무엇인가요?**
    - **A**: 프로그램은 디스크에 저장된 코드 묶음(정적인 상태)이고, 프로세스는 그 프로그램이 메모리에서 실행되고 있는 상태(동적인 상태)입니다. 하나의 프로그램으로 여러 개의 프로세스를 만들 수 있습니다.

- **Q2: 스와핑(swapping)이 자주 발생하면 왜 시스템 성능에 좋지 않은가요?**
    - **A**: 스와핑은 메모리(RAM)와 디스크 간의 데이터 교환을 의미합니다. 디스크는 메모리보다 수천 배 이상 느리기 때문에, 스와핑이 빈번해지면 CPU가 데이터 입출력을 기다리느라 대부분의 시간을 낭비하게 되어 시스템 전체의 반응 속도가 급격히 저하됩니다.

- **Q3: 일반 응용 프로그램이 하드웨어 장치에 직접 접근할 수 있나요? 그 이유는 무엇인가요?**
    - **A**: 접근할 수 없습니다. 시스템의 안정성과 보안을 위해, 하드웨어와 같은 주요 자원은 커널 모드에서 실행되는 운영체제만이 독점적으로 관리합니다. 응용 프로그램은 반드시 시스템 콜을 통해 운영체제에 요청하여 간접적으로 장치를 사용해야 합니다.

- **Q4: VFS(가상 파일 시스템)의 역할은 무엇인가요?**
    - **A**: VFS는 다양한 종류의 파일 시스템(ext4, XFS, NTFS 등)에 대해 일관된 인터페이스를 제공하는 추상화 계층입니다. 덕분에 사용자와 응용 프로그램은 파일 시스템의 구체적인 종류와 상관없이 `open()`, `read()`, `write()`와 같은 표준 함수로 파일을 다룰 수 있습니다.
