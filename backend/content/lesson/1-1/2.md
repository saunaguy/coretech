# 1-1-2: 프로세스, 메모리, 스왑

운영체제의 가장 중요한 역할 중 하나는 하드웨어 자원을 관리하고, 여러 프로그램들이 원활하게 실행되도록 환경을 제공하는 것입니다. 이를 이해하기 위해 프로세스, 메모리, 스왑의 개념을 알아야 합니다.

## 1. 💻 프로세스 (Process)

- **정의**: 단순히 말해, **실행 중인 프로그램**을 의미합니다. 하드 디스크에 저장된 프로그램 코드(예: `/bin/bash`)가 메모리에 올라와 CPU에 의해 실행될 때, 우리는 그것을 '프로세스'라고 부릅니다.

- **프로그램 vs. 프로세스**
    - **프로그램(Program)**: 특정 작업을 수행하기 위한 코드의 묶음. 디스크에 저장된 정적인 상태입니다. (예: 요리책의 레시피)
    - **프로세스(Process)**: 프로그램이 메모리에서 실행되고 있는 동적인 상태. 생명 주기를 가지며, 자신만의 메모리 공간, 파일 핸들, 시스템 자원 등을 할당받습니다. (예: 레시피를 따라 요리하는 행위 자체)

- **프로세스의 특징**
    - **독립성**: 각 프로세스는 자신만의 독립적인 메모리 공간을 가집니다. 한 프로세스가 다른 프로세스의 메모리 영역을 직접 침범할 수 없습니다. (운영체제가 보호)
    - **자원 할당**: 운영체제로부터 CPU 시간, 메모리, 파일 등 필요한 자원을 할당받습니다.
    - **계층 구조**: 프로세스는 다른 프로세스를 생성할 수 있으며, 이때 부모-자식 관계가 형성됩니다. (예: 셸에서 명령어를 실행하는 경우)

## 2. 🧠 메모리 관리 (Memory Management)

- **정의**: 운영체제가 한정된 물리적 메모리(RAM)를 여러 프로세스에게 효율적으로 할당하고, 사용이 끝나면 회수하는 모든 작업을 의미합니다.

- **메모리 관리가 필요한 이유**
    - **다중 프로그래밍**: 여러 프로세스를 동시에 메모리에 올려놓고 CPU 활용률을 극대화하기 위함입니다.
    - **메모리 보호**: 한 프로세스가 다른 프로세스의 데이터를 훼손하는 것을 방지하여 시스템의 안정성을 유지합니다.
    - **효율적인 자원 사용**: 한정된 메모리를 최대한 효율적으로 나누어 사용해야 합니다.

- **가상 메모리 (Virtual Memory)**
    - **개념**: 운영체제는 각 프로세스에게 실제 물리 메모리 크기와 상관없이, 매우 큰 가상의 메모리 공간을 할당해 줍니다. 프로세스는 자신이 시스템의 모든 메모리를 독차지하는 것처럼 동작합니다.
    - **장점**:
        1.  **단순함**: 개발자는 실제 메모리 주소를 신경 쓸 필요 없이 가상 주소 공간에서 프로그래밍하면 됩니다.
        2.  **보호**: 가상 메모리 덕분에 다른 프로세스의 메모리 공간에 접근하는 것이 원천적으로 차단됩니다.
        3.  **효율성**: 프로그램의 일부만 메모리에 올려도 실행이 가능하며, 여러 프로세스 간에 공통된 라이브러리(공유 라이브러리)를 메모리에서 공유할 수 있습니다.

    - **동작 원리**: 운영체제는 **MMU(Memory Management Unit)**라는 하드웨어의 도움을 받아, 프로세스가 사용하는 가상 주소를 실제 물리 메모리 주소로 변환해 줍니다.

## 3. 🔄 스왑 (Swap)

- **정의**: 물리적 메모리(RAM)가 부족할 때, 디스크(HDD/SSD)의 일부 공간을 메모리처럼 사용하는 기술입니다. 이 디스크 공간을 **스왑 공간(Swap Space)**이라고 합니다.

- **스왑의 역할 (가상 메모리의 확장)**
    - **메모리 확장**: 실제 물리 메모리보다 더 큰 프로그램을 실행할 수 있게 해줍니다.
    - **비상 대응**: 메모리 사용량이 갑자기 급증하여 RAM이 가득 찼을 때, 시스템이 완전히 멈추는 것을 방지하는 완충 역할을 합니다.

- **동작 방식**
    - **스와핑 (Swapping)**: 메모리와 스왑 공간 사이에서 데이터 블록(페이지)을 주고받는 행위입니다.
    - **스왑 아웃 (Swap-out)**: 당장 사용되지 않는 데이터나 프로세스를 메모리에서 스왑 공간으로 내보내는 것.
    - **스왑 인 (Swap-in)**: 스왑 공간으로 옮겨졌던 데이터가 다시 필요해져서 메모리로 불러오는 것.

- **주의할 점**
    - **성능 저하**: 디스크는 RAM에 비해 속도가 매우 느리기 때문에, 스와핑이 빈번하게 발생하면 시스템 전체의 성능이 급격히 저하됩니다. 이를 **스레싱(Thrashing)**이라고 합니다.
    - **모니터링**: 따라서 시스템 관리자는 스왑 사용량을 지속적으로 모니터링하고, 스와핑이 과도하게 발생하지 않도록 메모리 증설 등의 조치를 취해야 합니다.

이처럼 프로세스, 메모리, 스왑은 리눅스 시스템의 성능과 안정성에 직접적인 영향을 미치는 핵심 개념들입니다.
