# 1-1-9: 사용자 모드, 커널 모드, 그리고 시스템 콜

운영체제가 시스템을 안정적으로 보호하기 위해 사용하는 가장 근본적인 메커니즘은 바로 CPU의 **이중 모드(Dual-Mode)**와 **시스템 콜(System Call)**입니다. 이 개념은 운영체제 보안의 출발점입니다.

## 1. 🛡️ 왜 보호가 필요한가? (복습)

만약 모든 프로그램이 하드웨어에 직접 접근할 수 있는 모든 권한을 가진다면 어떤 일이 벌어질까요?

- 한 프로그램의 버그가 다른 프로그램의 메모리를 침범하여 **전체 시스템을 멈추게 할 수 있습니다.**
- 악의적인 프로그램이 다른 사용자의 파일을 몰래 읽거나 삭제할 수 있습니다.
- 여러 프로그램이 동시에 하드웨어를 제어하려고 하면서 충돌이 발생합니다.

이러한 대혼란을 막기 위해, 운영체제는 CPU의 도움을 받아 실행 모드를 **사용자 모드**와 **커널 모드**로 분리합니다.

## 2. 🔒 이중 모드 (Dual-Mode Operation)

현대의 CPU는 현재 실행 중인 코드가 어떤 권한을 갖는지 나타내는 **모드 비트(Mode Bit)**라는 하드웨어 상태 플래그를 가지고 있습니다.

- **모드 비트 `1` = 사용자 모드 (User Mode)**
    - **권한**: 제한된 권한.
    - **실행 주체**: 일반적인 응용 프로그램 (웹 브라우저, 게임, 문서 편집기 등).
    - **특징**: 프로그램은 자신에게 할당된 메모리 영역에만 접근할 수 있으며, 하드웨어 제어와 같은 특권 명령(privileged instruction)을 실행할 수 없습니다. 만약 실행을 시도하면 CPU는 예외(exception)를 발생시키고 운영체제가 해당 프로그램을 강제 종료합니다.

- **모드 비트 `0` = 커널 모드 (Kernel Mode)**
    - **다른 이름**: 관리자 모드(Supervisor Mode), 시스템 모드(System Mode), 특권 모드(Privileged Mode).
    - **권한**: 시스템의 모든 것을 할 수 있는 절대적인 권한.
    - **실행 주체**: 운영체제 커널.
    - **특징**: 모든 메모리 영역에 접근할 수 있고, 모든 CPU 명령어(특권 명령 포함)를 실행하여 하드웨어를 직접 제어할 수 있습니다.

컴퓨터가 부팅되면 커널이 가장 먼저 실행되므로 **커널 모드**로 시작합니다. 커널은 시스템 초기화를 마친 뒤, 응용 프로그램을 실행할 때 CPU를 **사용자 모드**로 전환하여 프로그램에 제어권을 넘깁니다.

## 3. 🚪 유일한 관문, 시스템 콜 (System Call)

그렇다면 사용자 모드에서 실행되는 응용 프로그램이 파일 읽기, 네트워크 통신과 같이 특권이 필요한 작업은 어떻게 수행할까요? 바로 **시스템 콜**이라는 유일한 "관문"을 통해서만 가능합니다.

**시스템 콜**은 사용자 프로세스가 커널에게 특권 작업을 **정중하게 요청**하는 절차입니다.

### 시스템 콜의 상세 동작 과정

1.  **준비 (사용자 모드)**: 응용 프로그램이 시스템 콜(예: `write`)을 호출합니다. 정확히는 C 라이브러리의 `write` 함수를 호출하면, 이 함수가 시스템 콜을 위한 준비를 합니다. 필요한 인자(argument)들을 정해진 CPU 레지스터에 저장합니다.

2.  **트랩 (Trap) 발생 (사용자 모드 → 커널 모드)**: 라이브러리 함수는 `SYSCALL` (또는 `INT 0x80` 등)이라는 특별한 명령어를 실행합니다. 이 명령은 CPU에게 소프트웨어 인터럽트(트랩)를 발생시킵니다.

3.  **모드 전환**: `SYSCALL` 명령이 실행되는 순간, CPU 하드웨어는 **자동으로 모드 비트를 `1`에서 `0`으로 바꿉니다.** (커널 모드로 전환)

4.  **핸들러 호출**: CPU는 커널 메모리 내에 미리 약속된 주소(시스템 콜 핸들러)로 실행 흐름을 점프시킵니다. 사용자 프로그램이 커널의 아무 곳이나 마음대로 들어갈 수 없도록, 이 진입점은 유일하게 고정되어 있습니다.

5.  **요청 수행 (커널 모드)**: 시스템 콜 핸들러는 레지스터에 저장된 인자들을 확인하여 요청이 유효한지 검사합니다. 그 후, 요청에 맞는 커널 내부 함수(예: 파일 쓰기 처리 함수)를 실행하여 실제 작업을 수행합니다.

6.  **결과 반환 (커널 모드)**: 작업이 끝나면, 커널은 결과값(성공 여부, 에러 코드 등)을 특정 레지스터에 저장합니다.

7.  **복귀 (커널 모드 → 사용자 모드)**: 커널은 `RTI` (Return from Interrupt)와 같은 특권 명령을 실행하여 시스템 콜을 종료합니다. 이 명령이 실행되면 CPU 하드웨어는 **자동으로 모드 비트를 `0`에서 `1`로 다시 바꿉니다.** (사용자 모드로 전환)

8.  **작업 재개**: 실행 흐름은 원래 시스템 콜을 호출했던 응용 프로그램의 다음 명령어로 돌아가고, 프로그램은 레지스터에 저장된 결과값을 확인하여 다음 작업을 이어갑니다.

이처럼 시스템 콜은 하드웨어(모드 비트, 트랩 명령어)와 소프트웨어(시스템 콜 핸들러)의 긴밀한 협력을 통해, **시스템의 안정성을 해치지 않으면서도 응용 프로그램이 운영체제의 서비스를 이용할 수 있도록 하는 핵심적인 메커니즘**입니다.
