# 1-1-3: 스토리지와 파일 시스템

컴퓨터에 데이터를 영구적으로 저장하기 위해서는 스토리지 하드웨어와 이를 관리하는 논리적인 구조인 파일 시스템이 필요합니다. 이 둘의 관계를 이해하는 것은 리눅스 시스템 관리의 기본입니다.

## 1. 💽 스토리지 (Storage)

스토리지는 전원이 꺼져도 데이터가 사라지지 않는 비휘발성 저장 장치입니다. 대표적으로 HDD(하드 디스크 드라이브)와 SSD(솔리드 스테이트 드라이브)가 있습니다.

- **HDD**: 자기 플래터를 회전시켜 데이터를 읽고 쓰는 기계식 장치. 용량 대비 저렴하지만 속도가 느립니다.
- **SSD**: 반도체 메모리를 이용해 데이터를 읽고 쓰는 전자식 장치. 속도가 매우 빠르고 소음이 없지만, 가격이 비쌉니다.

운영체제는 이러한 물리적인 스토리지 장치를 직접 다루지 않습니다. 대신, 파일 시스템이라는 논리적인 구조를 통해 데이터를 관리합니다.

## 2. 📂 파일 시스템 (File System)

- **정의**: 스토리지 장치에 있는 파일들을 **체계적으로 저장하고, 쉽게 찾아 사용할 수 있도록 관리하는 논리적인 체계**입니다. 파일 시스템이 없다면, 스토리지는 단순히 데이터를 연속적으로 기록하는 거대한 공간에 불과할 것입니다.

- **파일 시스템의 역할**
    - **이름 지정(Naming)**: 각 파일에 고유한 이름을 부여합니다.
    - **계층 구조(Hierarchy)**: 디렉터리(폴더)를 사용하여 파일들을 주제별, 용도별로 정리할 수 있게 합니다.
    - **메타데이터(Metadata) 관리**: 파일의 실제 데이터 외에, 파일에 대한 부가 정보(속성)를 관리합니다. 예를 들어, 파일 크기, 생성일, 수정일, 소유자, 접근 권한 등이 있습니다.
    - **데이터 접근**: 사용자가 파일 이름을 통해 원하는 데이터에 쉽게 접근하고 읽고 쓸 수 있도록 합니다.

## 3. 파일 시스템의 핵심 개념

### 파일 (File)과 디렉터리 (Directory)

- **파일**: 연관된 정보의 집합. 리눅스에서는 일반 파일, 디렉터리, 심볼릭 링크, 장치 파일 등 모든 것을 파일로 취급합니다.
- **디렉터리**: 파일들을 담는 컨테이너. 다른 디렉터리를 포함하여 계층적인 구조를 만듭니다. 최상위 디렉터리는 루트(`/`) 디렉터리입니다.

### 아이노드 (Inode)

- **정의**: "Index Node"의 줄임말로, 파일 시스템에서 각 파일이나 디렉터리에 대한 **모든 메타데이터를 저장하는 데이터 구조**입니다. 파일의 실제 데이터(내용)를 제외한 모든 정보가 아이노드에 담겨 있습니다.
- **포함되는 정보**: 파일 종류, 접근 권한(permission), 소유자(owner), 그룹(group), 파일 크기, 시간 정보(생성, 수정, 접근), 그리고 **데이터 블록의 위치를 가리키는 포인터**.
- **동작 방식**:
    1.  사용자가 파일 이름(예: `/home/user/report.txt`)으로 접근을 시도합니다.
    2.  파일 시스템은 디렉터리 구조를 탐색하여 `report.txt`에 해당하는 아이노드 번호(inode number)를 찾습니다.
    3.  해당 아이노드를 통해 파일의 메타데이터(권한 등)를 확인하고, 데이터 블록 포인터를 따라 실제 데이터가 저장된 위치에 접근합니다.

> **핵심**: 파일 이름은 사람이 식별하기 위한 것이고, 시스템은 내부적으로 아이노드 번호를 통해 파일을 관리합니다.

## 4. 리눅스의 주요 파일 시스템

리눅스는 다양한 종류의 파일 시스템을 지원합니다. 대표적인 것들은 다음과 같습니다.

- **ext4 (Fourth Extended Filesystem)**: 오랫동안 리눅스의 기본 파일 시스템으로 사용되어 왔으며, 안정성과 범용성이 뛰어납니다.
- **XFS (X-tend File System)**: 대용량 파일 및 대규모 파일 시스템 환경에서 높은 성능을 발휘합니다. 병렬 입출력 처리에 강점이 있어 고성능 서버에 많이 사용됩니다.
- **Btrfs (B-tree File System)**: 스냅샷, 내장 볼륨 관리, 자가 치유 등 현대적인 기능들을 많이 포함하고 있는 차세대 파일 시스템입니다.

## 5. 가상 파일 시스템 (VFS: Virtual File System)

- **정의**: 리눅스 커널 내의 추상화 계층으로, **사용자나 응용 프로그램이 파일 시스템의 종류에 관계없이 동일한 방식으로 파일에 접근할 수 있도록 하는 인터페이스**입니다.
- **역할**:
    - **통일된 인터페이스**: `open()`, `read()`, `write()`와 같은 표준 시스템 콜을 통해 ext4, XFS, 심지어 네트워크 파일 시스템(NFS)까지 동일한 방식으로 다룰 수 있게 합니다.
    - **다양성 지원**: VFS 덕분에 리눅스는 수많은 종류의 파일 시스템을 동시에 마운트하여 사용할 수 있습니다.

결론적으로, 사용자는 VFS가 제공하는 일관된 인터페이스를 통해 파일을 다루고, VFS는 각 파일 시스템의 특성에 맞는 드라이버를 호출하여 실제 스토리지 장치에 데이터를 읽고 쓰는 복잡한 과정을 처리해 줍니다.
