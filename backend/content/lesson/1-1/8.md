# 1-1-8: 커널의 핵심 기능 (심화)

리눅스 커널은 운영체제의 심장부로서, 시스템의 모든 자원을 관리하고 제어합니다. 커널은 여러 개의 하위 시스템(Subsystem)으로 구성되어 있으며, 각 하위 시스템은 특정 역할을 전문적으로 수행합니다. 여기서는 커널의 5가지 핵심 기능을 더 깊이 있게 살펴보겠습니다.

## 1. ⚙️ 프로세스 관리 (Process Management)

프로세스 관리는 CPU 시간을 여러 프로세스에 분배하고, 프로세스들이 서로 원활하게 통신하도록 돕는 기능입니다.

- **스케줄러 (Scheduler)**
    - **역할**: 멀티태스킹의 핵심. 수많은 프로세스 중에서 어떤 프로세스에게 CPU를 할당할지, 그리고 얼마나 오래 사용하게 할지를 결정하는 알고리즘입니다.
    - **리눅스의 CFS (Completely Fair Scheduler)**: 리눅스는 "완전 공정 스케줄러"라는 이름의 스케줄러를 사용합니다. 이름처럼, 모든 프로세스가 CPU 시간을 **공평하게** 나누어 갖도록 하는 것을 목표로 합니다. 각 프로세스의 CPU 사용 시간을 추적하여, 가장 적게 사용한 프로세스에게 우선적으로 CPU를 할당하는 방식으로 동작합니다.

- **프로세스 간 통신 (IPC: Inter-Process Communication)**
    - **역할**: 독립적인 메모리 공간을 가진 프로세스들이 서로 데이터를 주고받고, 작업을 동기화할 수 있도록 하는 통신 메커니즘을 제공합니다.
    - **종류**:
        - **파이프 (Pipe)**: 두 프로세스 간의 단방향 통신 채널. `command1 | command2` 와 같은 형태로 사용됩니다.
        - **소켓 (Socket)**: 동일한 시스템 내의 프로세스 간, 또는 네트워크로 연결된 다른 시스템의 프로세스 간 통신에 사용됩니다.
        - **공유 메모리 (Shared Memory)**: 여러 프로세스가 특정 메모리 공간을 공유하여, 매우 빠른 속도로 데이터를 주고받을 수 있게 합니다.

## 2. 🧠 메모리 관리 (Memory Management)

한정된 물리적 메모리(RAM)를 효율적으로 관리하고, 각 프로세스에게 안정적인 메모리 환경을 제공합니다.

- **가상 메모리 관리 (Virtual Memory Management)**
    - **역할**: 각 프로세스에게 독립적이고 거대한 가상 주소 공간을 제공하고, 이를 실제 물리 메모리 주소로 변환(mapping)하는 작업을 담당합니다.
    - **페이지 폴트 (Page Fault) 처리**: 프로세스가 접근하려는 데이터가 물리 메모리에 없는 경우(페이지 폴트 발생), 디스크(스왑 공간)에서 해당 데이터를 메모리로 가져오는 과정을 처리합니다. 이 모든 과정은 프로세스에게 투명하게 이루어집니다.

- **슬랩 할당자 (Slab Allocator)**
    - **역할**: 커널 내부에서는 아이노드, 프로세스 제어 블록(PCB) 등 동일한 크기의 작은 객체들이 매우 빈번하게 생성되고 소멸됩니다. 슬랩 할당자는 이러한 객체들을 위한 **특화된 메모리 관리 기법**입니다.
    - **방식**: 미리 비슷한 크기의 객체들을 담을 수 있는 메모리 풀('슬랩')을 만들어 두고, 요청이 오면 여기서 객체를 꺼내주고 반납하면 다시 풀에 넣습니다. 이를 통해 메모리 단편화를 줄이고 할당/해제 속도를 크게 향상시킵니다.

## 3. 📂 파일 시스템 (File System)

디스크에 저장된 데이터를 체계적으로 관리하고, 사용자에게 일관된 파일 접근 인터페이스를 제공합니다.

- **가상 파일 시스템 (VFS: Virtual File System)**
    - **역할**: 리눅스가 ext4, XFS, NFS 등 수많은 종류의 파일 시스템을 지원할 수 있게 하는 **추상화 계층**입니다. VFS는 응용 프로그램에게 통일된 파일 관련 시스템 콜(e.g., `open`, `read`, `write`) 인터페이스를 제공하고, 각 파일 시스템의 실제 동작은 해당 파일 시스템 드라이버에 위임합니다.

- **페이지 캐시 (Page Cache)**
    - **역할**: 디스크 I/O는 CPU나 메모리에 비해 매우 느립니다. 페이지 캐시는 디스크에서 읽어온 데이터나 디스크에 쓸 데이터를 **메모리(RAM)에 임시로 저장**하여 입출력 속도를 향상시키는 기법입니다.
    - **동작**: 한 번 읽은 파일 내용은 페이지 캐시에 저장되어, 다음 접근 시에는 디스크까지 가지 않고 메모리에서 바로 읽어올 수 있습니다. 쓰기 작업 역시 일단 페이지 캐시에 쓴 뒤, 나중에 커널이 디스크에 반영합니다(Write-back Caching).

## 4. 🌐 네트워킹 (Networking)

네트워크를 통해 다른 컴퓨터와 데이터를 주고받을 수 있도록 하는 모든 기능을 담당합니다.

- **프로토콜 스택 (Protocol Stack)**
    - **역할**: TCP, UDP, IP 등 복잡한 네트워크 프로토콜의 규칙을 구현한 코드의 집합입니다. 데이터에 헤더를 붙여 캡슐화하고, 수신된 데이터에서 헤더를 제거하며 상위 계층으로 전달하는 역할을 합니다.

- **소켓 인터페이스 (Socket Interface)**
    - **역할**: 응용 프로그램이 네트워크 기능을 사용할 수 있도록 VFS와 유사한 **추상화된 API**를 제공합니다. 개발자는 `socket()`, `bind()`, `connect()` 와 같은 시스템 콜을 통해 복잡한 네트워크 프로토콜 스택을 직접 다루지 않고도 네트워크 프로그래밍을 할 수 있습니다.

## 5. 🔌 장치 드라이버 (Device Drivers)

- **역할**: 커널의 나머지 부분과 하드웨어 장치 사이의 **번역가** 역할을 합니다. 커널이 특정 하드웨어의 복잡한 작동 방식을 몰라도, 표준화된 인터페이스를 통해 장치를 제어할 수 있게 해줍니다.
- **분류**:
    - **문자 장치 (Character Devices)**: 데이터를 문자 스트림처럼 순차적으로 처리하는 장치 (e.g., 키보드, 마우스, 터미널).
    - **블록 장치 (Block Devices)**: 정해진 크기(블록) 단위로 데이터를 랜덤하게 접근할 수 있는 장치 (e.g., 하드 디스크, SSD).
    - **네트워크 장치 (Network Devices)**: 네트워크 패킷을 주고받는 장치 (e.g., 이더넷 카드).

이처럼 커널은 각기 다른 역할을 수행하는 정교한 하위 시스템들의 유기적인 결합체이며, 이들이 함께 작동하여 강력하고 안정적인 리눅스 시스템을 만듭니다.
