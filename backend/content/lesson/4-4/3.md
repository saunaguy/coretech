# 4-4-3: 캐싱/압축, WAF 개요/배치 패턴

역방향 프록시(L7 로드밸런서)는 단순히 요청을 분산하는 것을 넘어, 다양한 부가 기능을 통해 웹 서비스의 성능과 보안을 크게 향상시킬 수 있습니다. 그중 가장 대표적인 것이 **캐싱(Caching)**, **압축(Compression)**, 그리고 **WAF(웹 방화벽)**입니다.

## 1. 캐싱 (Caching)

- **개념**: 한 번 요청되었던 정적 콘텐츠(이미지, CSS, JavaScript 파일 등)나, 자주 변경되지 않는 동적 콘텐츠의 응답 결과를 역방향 프록시 서버의 메모리나 디스크에 저장해 두는 기술입니다.
- **동작**: 동일한 콘텐츠에 대한 다음 요청이 들어오면, 실제 백엔드 서버까지 가지 않고 프록시 서버가 직접 캐시된 데이터를 응답합니다.
- **효과**:
    - **응답 속도 향상**: 클라이언트는 더 가까운 프록시 서버로부터 즉시 응답을 받으므로 로딩 속도가 매우 빨라집니다.
    - **백엔드 부하 감소**: 백엔드 서버는 반복적인 요청을 처리할 필요가 없어져, 더 중요한 동적 콘텐츠 생성에 자원을 집중할 수 있습니다.

- **`Nginx` 캐싱 설정 예시**:
  ```nginx
  # 캐시 저장 경로와 옵션 설정
  proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=my_cache:10m max_size=10g inactive=60m;

  server {
      # ...
      location / {
          proxy_cache my_cache; # 'my_cache' 캐시 사용
          proxy_pass http://backend_servers;
          # ...
      }
  }
  ```

## 2. 압축 (Compression)

- **개념**: 백엔드 서버로부터 받은 HTTP 응답 본문(주로 텍스트 기반인 HTML, CSS, JS 파일)을 클라이언트에게 보내기 전에, `Gzip`이나 `Brotli`와 같은 알고리즘으로 압축하여 전송하는 기술입니다.
- **동작**: 클라이언트(웹 브라우저)는 요청 헤더에 `Accept-Encoding: gzip, deflate, br`와 같이 자신이 지원하는 압축 알고리즘을 명시합니다. 역방향 프록시는 이 헤더를 보고, 응답을 압축한 뒤 `Content-Encoding: gzip`과 같은 헤더를 추가하여 클라이언트에게 보냅니다. 브라우저는 이 헤더를 보고 압축을 해제하여 사용자에게 보여줍니다.
- **효과**:
    - **전송 데이터 크기 감소**: 응답의 크기가 수십 % 이상 줄어들어, 사용자의 네트워크 대역폭을 절약하고 페이지 로딩 속도를 향상시킵니다. 특히 모바일 환경에서 효과가 큽니다.

- **`Nginx` 압축 설정 예시**:
  ```nginx
  server {
      # ...
      gzip on; # Gzip 압축 활성화
      gzip_types text/plain text/css application/json application/javascript;
      # ...
  }
  ```

## 3. WAF (Web Application Firewall, 웹 방화벽)

- **개념**: 일반적인 네트워크 방화벽(L3/L4)이 IP 주소와 포트 번호를 기반으로 트래픽을 제어하는 것과 달리, WAF는 **HTTP 요청의 내용(URL, 헤더, 본문 등)을 분석**하여 웹 애플리케이션에 대한 악의적인 공격을 탐지하고 차단하는 보안 솔루션입니다.
- **주요 차단 공격**:
    - **SQL Injection**: 입력값에 악의적인 SQL 구문을 삽입하여 데이터베이스를 공격하는 행위.
    - **XSS (Cross-Site Scripting)**: 게시판 등에 악성 스크립트를 삽입하여 다른 사용자의 브라우저에서 실행되게 하는 공격.
    - 악의적인 봇(Bot)의 비정상적인 접근.
    - 알려진 웹 취약점을 이용한 공격.

### WAF 배치 패턴

- **역방향 프록시 형태의 WAF**: 가장 일반적인 형태로, WAF가 역방향 프록시처럼 동작하며 모든 HTTP 요청을 가장 앞에서 먼저 받습니다. WAF는 요청을 검사하여 안전하다고 판단될 경우에만 실제 웹 서버(또는 로드밸런서)로 트래픽을 전달합니다.
  `Client → WAF → Web Server`

- **로드밸런서와 연동**: 대규모 환경에서는 로드밸런서 바로 뒤, 혹은 로드밸런서의 일부 기능으로 WAF를 배치합니다.
  `Client → Load Balancer → WAF → Web Servers`

- **클라우드 기반 WAF**: AWS WAF, Cloudflare WAF와 같이 클라우드 서비스 제공업체가 제공하는 WAF 서비스를 사용합니다. 사용자는 인프라를 직접 관리할 필요 없이, 관리 콘솔에서 간단하게 규칙을 설정하여 사용할 수 있습니다.

- **`Nginx` 기반 WAF**: `Nginx`에 `ModSecurity`와 같은 오픈소스 WAF 모듈을 통합하여, `Nginx` 자체가 WAF 역할을 수행하도록 구성할 수 있습니다.

캐싱과 압축은 서비스의 **성능**을 최적화하는 기술이고, WAF는 서비스의 **보안**을 강화하는 기술입니다. 현대적인 웹 아키텍처에서는 이 기능들을 역방향 프록시 또는 로드밸런서 단에서 통합하여 처리함으로써, 백엔드 서버가 비즈니스 로직 처리에만 집중할 수 있도록 역할을 분리하는 것이 일반적인 모범 사례(Best Practice)입니다.
