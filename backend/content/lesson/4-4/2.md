# 4-4-2: HAProxy/Nginx 역/정방향 프록시 구성

프록시(Proxy) 서버는 클라이언트와 서버 사이에서 중개자 역할을 하는 서버를 의미합니다. 프록시는 그 위치와 목적에 따라 **정방향 프록시(Forward Proxy)**와 **역방향 프록시(Reverse Proxy)**로 나뉩니다. `HAProxy`와 `Nginx`는 역방향 프록시, 특히 L7 로드밸런서로 널리 사용되는 대표적인 오픈소스 소프트웨어입니다.

## 1. 정방향 프록시 (Forward Proxy)

- **위치**: **클라이언트 측**에 위치하여, 클라이언트의 모든 요청을 대신 받아 목적지 서버로 전달합니다.
- **특징**: 서버는 실제 클라이언트가 누구인지 알지 못하고, 프록시 서버와 통신합니다. 클라이언트의 신원을 숨기는 효과가 있습니다.
- **주요 사용 목적**:
    - **캐싱(Caching)**: 자주 요청되는 콘텐츠를 프록시 서버에 캐시해 두었다가, 다음 요청 시 실제 서버까지 가지 않고 즉시 응답하여 속도를 향상시킵니다.
    - **보안 및 접근 제어**: 회사 내부망에서 직원들이 특정 웹사이트(예: 유해 사이트)에 접근하는 것을 차단하거나, 특정 사용자만 인터넷에 접근하도록 제어할 수 있습니다.
    - **익명성**: 클라이언트의 실제 IP 주소를 감추고 프록시 서버의 IP 주소로 요청하게 됩니다.

## 2. 역방향 프록시 (Reverse Proxy)

- **위치**: **서버 측**에 위치하여, 외부 클라이언트의 모든 요청을 대신 받아 내부의 실제 서버(백엔드 서버) 중 하나에게 전달합니다.
- **특징**: 클라이언트는 자신이 실제 서버와 통신하는지, 역방향 프록시와 통신하는지 알지 못합니다. 실제 서버의 존재를 숨기는 효과가 있습니다.
- **주요 사용 목적 (L7 로드밸런서의 기능과 동일)**:
    - **로드 밸런싱(Load Balancing)**: 들어오는 요청을 여러 대의 백엔드 서버로 분산하여 부하를 줄입니다.
    - **보안**: 실제 백엔드 서버의 IP 주소와 아키텍처를 외부에 숨겨 보안을 강화합니다.
    - **SSL Offloading**: 클라이언트와의 HTTPS 암호화/복호화 처리를 역방향 프록시가 전담하여, 백엔드 서버의 부담을 덜어줍니다.
    - **캐싱(Caching)**: 정적 콘텐츠(이미지, CSS, JS 파일 등)를 역방향 프록시가 캐시하여, 백엔드 서버로의 요청을 줄이고 응답 속도를 높입니다.
    - **URL 기반 라우팅**: 요청된 URL 경로에 따라 다른 백엔드 서버로 요청을 전달합니다.

## 3. `HAProxy`를 이용한 역방향 프록시 구성

`HAProxy`는 고성능 L4/L7 로드밸런싱에 특화된 소프트웨어입니다.

- **`/etc/haproxy/haproxy.cfg` 설정 예시**:
  ```
  frontend http_front
      bind *:80
      default_backend http_back

  backend http_back
      balance roundrobin
      server web1 192.168.1.101:80 check
      server web2 192.168.1.102:80 check
  ```
  - **`frontend http_front`**: 클라이언트로부터 요청을 받는 부분입니다. `bind *:80`은 80번 포트로 들어오는 모든 요청을 받는다는 의미입니다.
  - **`default_backend http_back`**: 받은 요청을 `http_back`이라는 백엔드로 전달합니다.
  - **`backend http_back`**: 실제 백엔드 서버들의 그룹입니다.
  - **`balance roundrobin`**: 부하 분산 알고리즘을 라운드 로빈으로 설정합니다.
  - **`server web1 ...`**: 백엔드 서버를 정의합니다. `check` 옵션은 해당 서버에 대해 헬스 체크를 수행하라는 의미입니다.

## 4. `Nginx`를 이용한 역방향 프록시 구성

`Nginx`는 원래 고성능 웹 서버로 개발되었지만, 강력한 역방향 프록시 및 로드밸런싱 기능도 내장하고 있어 널리 사용됩니다.

- **`/etc/nginx/conf.d/load_balancer.conf` 설정 예시**:
  ```nginx
  upstream backend_servers {
      server 192.168.1.101:80;
      server 192.168.1.102:80;
  }

  server {
      listen 80;

      location / {
          proxy_pass http://backend_servers;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      }
  }
  ```
  - **`upstream backend_servers`**: 백엔드 서버들의 그룹을 정의합니다.
  - **`server { ... }`**: 가상 호스트를 정의합니다. `listen 80`은 80번 포트로 요청을 받는다는 의미입니다.
  - **`location / { ... }`**: 루트(`/`) 경로로 들어오는 모든 요청에 대해 다음을 수행합니다.
  - **`proxy_pass http://backend_servers;`**: 요청을 `backend_servers` 그룹으로 전달합니다. 이것이 역방향 프록시의 핵심 지시어입니다.
  - **`proxy_set_header ...`**: 백엔드 서버가 클라이언트의 실제 IP 주소나 원래 요청된 호스트 이름을 알 수 있도록, 관련 정보를 HTTP 헤더에 추가하여 전달합니다. 이는 로그 분석이나 애플리케이션 로직에 매우 중요합니다.

`HAProxy`는 로드밸런싱 기능 자체에 더 집중하고 최적화되어 있으며, `Nginx`는 웹 서버 기능과 함께 강력한 역방향 프록시 기능을 제공하여 캐싱, URL 재작성(rewrite) 등 더 다양한 웹 관련 기능을 한 번에 처리할 수 있다는 장점이 있습니다. 어떤 것을 선택할지는 아키텍처와 요구사항에 따라 달라집니다.
