# 1-2-2: 리눅스 설치 방법

리눅스 배포판을 사용하기로 결정했다면, 다음은 어떤 방식으로 설치할지 선택해야 합니다. 사용자의 목적과 환경에 따라 여러 가지 설치 방법이 있습니다.

### 설치 사전 준비

어떤 방법을 선택하든, 가장 먼저 할 일은 원하는 리눅스 배포판의 공식 웹사이트에 방문하여 **ISO 이미지 파일**을 다운로드하는 것입니다. ISO 파일은 운영체제 설치에 필요한 모든 것을 담고 있는 하나의 큰 파일입니다. 그 후, 이 ISO 파일을 **부팅 가능한 USB 드라이브**로 만들어야 합니다. (가상 머신 설치 시에는 ISO 파일만 있으면 됩니다.)

- **부팅 USB 제작 도구**: Rufus, balenaEtcher, Ventoy 등

---

## 1. 💻 전체 설치 (네이티브 / 베어메탈 설치)

- **설명**: 컴퓨터의 주 저장 장치(하드 드라이브, SSD)에 리눅스를 직접 설치하는 가장 전통적인 방법입니다. 컴퓨터를 리눅스 전용으로 사용하거나, 기존 윈도우 옆에 별도의 공간(파티션)을 만들어 함께 사용하는 **듀얼 부팅(Dual-boot)** 구성이 가능합니다.
- **장점**: 하드웨어를 직접 제어하므로 **최상의 성능**을 낼 수 있습니다. 리눅스의 모든 기능을 100% 활용할 수 있습니다.
- **단점**: 설치 과정(특히 파티션 설정)이 초보자에게는 다소 복잡할 수 있습니다. 실수할 경우 기존의 데이터(예: 윈도우)가 손상될 위험이 있습니다.
- **적합한 경우**: 주력 운영체제로 리눅스를 사용하려는 경우, 고성능이 필요한 서버를 구축하는 경우.

## 2. 📦 가상 머신 (Virtual Machine) 설치

- **설명**: 현재 사용 중인 운영체제(Host OS, 예: 윈도우, macOS) 위에 가상화 소프트웨어를 설치하고, 그 소프트웨어 안에서 또 다른 운영체제(Guest OS, 예: 리눅스)를 실행하는 방식입니다.
- **대표적인 가상화 소프트웨어**: VirtualBox (무료), VMware Workstation/Player, Hyper-V (윈도우 내장 기능)
- **장점**:
    - **안전함**: 가상 머신 내에서 어떤 실수를 하더라도 원래 사용하던 Host OS에는 전혀 영향을 주지 않습니다.
    - **편리함**: 여러 종류의 리눅스 배포판을 동시에 설치하고 쉽게 삭제할 수 있습니다. 특정 상태를 저장하는 **스냅샷(Snapshot)** 기능은 매우 유용합니다.
- **단점**: 하드웨어를 가상으로 흉내 내는 방식이라, 전체 설치에 비해 성능이 다소 저하됩니다.
- **적합한 경우**: **리눅스를 처음 배우는 학습용**, 개발 및 테스트 환경, 다양한 배포판을 체험해보고 싶은 경우. **(이 강의에서는 가상 머신을 이용한 설치를 권장합니다.)**

## 3. 🪟 WSL (Windows Subsystem for Linux)

- **설명**: Microsoft가 윈도우 10/11에서 리눅스 환경을 직접 사용할 수 있도록 개발한 기능입니다. 별도의 가상 머신 프로그램 없이, 윈도우 내에서 리눅스 명령어와 도구들을 바로 실행할 수 있습니다.
- **WSL1 vs WSL2**: 초기 WSL1은 리눅스 시스템 콜을 윈도우 시스템 콜로 번역하는 방식이었지만, **WSL2**는 경량화된 가상 머신 기술을 사용하여 실제 리눅스 커널을 실행합니다. 이로 인해 파일 시스템 성능과 호환성이 크게 향상되었습니다.
- **장점**: 윈도우와 리눅스 간의 통합이 매우 뛰어납니다 (파일 시스템 상호 접근 가능). 설치가 빠르고 간편하며, 개발에 필요한 리눅스 도구를 즉시 사용할 수 있습니다.
- **단점**: GUI 환경보다는 CLI(명령줄 인터페이스) 중심의 환경입니다. (최근 GUI 앱 지원이 추가되었지만 완벽하지 않을 수 있음) 하드웨어에 직접 접근하는 작업에는 적합하지 않습니다.
- **적합한 경우**: 주력 OS는 윈도우를 사용하면서, 웹 개발 등 리눅스의 강력한 개발 도구와 셸 환경이 필요한 개발자.

## 4. 💿 라이브 USB (Live USB)

- **설명**: 제작해 둔 부팅 USB 드라이브로 컴퓨터를 부팅하여, 하드 디스크에 **설치하지 않고** 리눅스를 직접 체험해보는 방식입니다.
- **장점**: 내 컴퓨터에 어떤 영향도 주지 않고 특정 배포판이 내 하드웨어와 잘 맞는지 테스트해볼 수 있습니다. 기존 시스템에 문제가 생겼을 때 데이터를 백업하거나 복구하는 용도로도 유용합니다.
- **단점**: USB 드라이브에서 직접 실행되므로 속도가 느립니다. 기본적으로 변경 사항이 저장되지 않아 재부팅하면 모든 작업 내용이 사라집니다. (단, 'Persistence' 옵션을 주면 변경 사항을 저장할 수도 있습니다.)
- **적합한 경우**: 설치 전 배포판을 미리 체험해보고 싶은 경우, 시스템 응급 복구.

## 📊 설치 방법 비교 요약

| 구분 | 성능 | 격리성 (안전성) | 위험도 | 사용 편의성 | 추천 대상 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **전체 설치** | 최상 | 낮음 | 높음 | 보통 | 주력 OS 사용자, 서버 관리자 |
| **가상 머신** | 보통 | 높음 | 매우 낮음 | 쉬움 | **학습자**, 개발자, 테스터 |
| **WSL** | 좋음 | 보통 | 낮음 | 매우 쉬움 | 윈도우 기반 개발자 |
| **라이브 USB** | 낮음 | 매우 높음 | 없음 | 쉬움 | 설치 전 체험, 시스템 복구 |
