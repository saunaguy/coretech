# 4-1-3: 라우팅 테이블/메트릭, 기본 게이트웨이

컴퓨터가 다른 네트워크에 있는 목적지와 통신하기 위해서는, 패킷을 어디로 보내야 할지를 결정해야 합니다. 이 결정 과정의 핵심이 바로 **라우팅(Routing)**이며, 그 결정의 근거가 되는 것이 **라우팅 테이블(Routing Table)**입니다.

## 1. 라우팅 테이블의 이해

- **개념**: 라우팅 테이블은 커널이 관리하는 일종의 지도 또는 이정표입니다. 목적지 IP 주소로 가기 위해, 패킷을 어떤 네트워크 인터페이스를 통해 어떤 다음 라우터(게이트웨이)로 보내야 하는지에 대한 규칙들의 목록입니다.
- **확인 명령어**:
  ```bash
  ip route show
  # 또는
  netstat -rn
  ```

- **라우팅 테이블 예시 분석**:
  ```
  $ ip route show
  default via 192.168.1.1 dev eth0 proto dhcp metric 100 
  172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 
  192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.100 metric 100
  ```
  - **`default via 192.168.1.1 dev eth0 ...`**: **기본 게이트웨이(Default Gateway)** 규칙. 라우팅 테이블의 다른 어떤 규칙과도 일치하지 않는 모든 트래픽(주로 인터넷으로 나가는 트래픽)은 `eth0` 인터페이스를 통해 `192.168.1.1` 라우터로 보내라는 의미입니다. 가장 중요한 규칙입니다.
  - **`192.168.1.0/24 dev eth0 ...`**: `192.168.1.0` ~ `192.168.1.255` 범위의 IP 주소로 가는 트래픽은 게이트웨이를 거치지 않고, `eth0` 인터페이스를 통해 직접 통신하라는 의미입니다. (로컬 네트워크 통신)
  - **`172.17.0.0/16 dev docker0 ...`**: `172.17.0.0/16` 대역(Docker 네트워크)으로 가는 트래픽은 `docker0` 인터페이스를 통해 직접 통신하라는 의미입니다.

## 2. 라우팅 결정 과정 (Longest Prefix Match)

커널은 패킷의 목적지 IP 주소를 라우팅 테이블의 모든 규칙과 비교하여, **가장 구체적인(가장 긴 프리픽스/서브넷 마스크를 가진) 규칙**을 선택합니다. 이를 **Longest Prefix Match** 원칙이라고 합니다.

- **예시**: 목적지 IP가 `192.168.1.50`인 패킷
    1.  `192.168.1.0/24` 규칙과 일치합니다. (프리픽스 길이 24)
    2.  `default` 규칙(`0.0.0.0/0`)과도 일치합니다. (프리픽스 길이 0)
    3.  `24`가 `0`보다 크므로, 커널은 `192.168.1.0/24` 규칙을 선택하여 `eth0` 인터페이스로 패킷을 직접 보냅니다.

- **예시**: 목적지 IP가 `8.8.8.8`(Google DNS)인 패킷
    1.  `192.168.1.0/24` 규칙과 일치하지 않습니다.
    2.  `172.17.0.0/16` 규칙과 일치하지 않습니다.
    3.  `default` 규칙과 일치합니다.
    4.  커널은 `default` 규칙을 선택하여 `eth0` 인터페이스를 통해 `192.168.1.1` 게이트웨이로 패킷을 보냅니다.

## 3. 메트릭 (Metric)

- **개념**: 만약 목적지까지 갈 수 있는 경로가 여러 개 있다면(예: 유선랜과 무선랜이 동시에 연결된 경우), 어떤 경로를 우선적으로 사용할지 결정하는 값입니다. **메트릭 값이 낮을수록 우선순위가 높습니다.**

- **시나리오**: 서버에 두 개의 네트워크 카드(`eth0`, `eth1`)가 있고, 각각 다른 라우터를 통해 인터넷에 연결될 수 있습니다. `eth0`가 더 빠른 주 회선이고, `eth1`은 백업 회선입니다.

- **설정 방법**:
  ```bash
  # 주 회선(eth0)의 기본 게이트웨이는 낮은 메트릭 값(예: 100)으로 설정
  sudo ip route add default via 192.168.1.1 dev eth0 metric 100

  # 백업 회선(eth1)의 기본 게이트웨이는 높은 메트릭 값(예: 200)으로 설정
  sudo ip route add default via 10.0.0.1 dev eth1 metric 200
  ```
  - 평상시에는 메트릭이 낮은 `eth0` 경로를 사용하다가, `eth0`에 문제가 생겨 해당 경로가 비활성화되면 커널은 자동으로 메트릭이 더 높은 `eth1` 경로를 사용하게 됩니다.

## 4. 라우팅 문제 트러블슈팅

- **"Network is unreachable" 에러**: 이 에러는 커널이 라우팅 테이블에서 목적지로 가는 경로를 전혀 찾지 못했음을 의미합니다.
    - **원인 1: 기본 게이트웨이 부재**: `ip route show` 명령으로 `default` 경로가 있는지 확인합니다. 없다면 `sudo ip route add default via [게이트웨이_IP]`로 추가해 줍니다.
    - **원인 2: 잘못된 IP 또는 서브넷 마스크**: 서버에 할당된 IP 주소나 서브넷 마스크가 잘못되어, 게이트웨이와 같은 네트워크 대역에 속하지 않는 경우입니다. `ip addr show`로 IP 설정을 확인합니다.
    - **원인 3: 링크 다운**: `ip link show`로 해당 인터페이스가 `UP` 상태인지 확인합니다. 케이블이 빠졌거나 스위치 포트에 문제가 있을 수 있습니다.

라우팅 테이블을 올바르게 읽고 해석하는 능력은 "왜 통신이 안 되는가?"라는 질문에 답하기 위한 가장 기본적인 단계이며, 모든 네트워크 트러블슈팅의 시작점입니다.
