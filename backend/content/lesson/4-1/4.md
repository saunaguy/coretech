# 4-1-4: IPv4/IPv6 기초, CIDR/프리픽스

IP(Internet Protocol) 주소는 인터넷에 연결된 모든 장치를 식별하는 고유한 번호입니다. 현재는 IPv4와 IPv6 두 가지 버전이 함께 사용되고 있으며, 네트워크의 크기를 표현하는 CIDR 표기법을 이해하는 것은 네트워크를 설정하고 관리하는 데 필수적입니다.

## 1. IPv4 (Internet Protocol version 4)

- **구조**: 32비트(bit) 주소 체계로, 8비트씩 4개의 부분으로 나누어 10진수로 표현합니다. (예: `192.168.1.100`)
- **주소 개수**: 약 43억 개 ($2^{32}$)의 주소를 가질 수 있습니다. 인터넷의 폭발적인 성장으로 인해 IPv4 주소는 거의 고갈된 상태입니다.
- **클래스(Class) 기반 주소 (과거)**: 예전에는 IP 주소를 A, B, C, D, E 클래스로 나누어 네트워크의 크기를 구분했지만, 비효율성으로 인해 현재는 거의 사용되지 않고 CIDR 방식으로 대체되었습니다.

### 사설(Private) IP 주소 대역
- 인터넷 공유기(NAT) 내부의 로컬 네트워크(가정, 회사 등)에서 자유롭게 사용할 수 있도록 예약된 주소 대역입니다. 이 주소들은 인터넷상에서 라우팅되지 않으므로 외부에서 직접 접근할 수 없습니다.
    - **`10.0.0.0` ~ `10.255.255.255`** (10.0.0.0/8)
    - **`172.16.0.0` ~ `172.31.255.255`** (172.16.0.0/12)
    - **`192.168.0.0` ~ `192.168.255.255`** (192.168.0.0/16)

## 2. IPv6 (Internet Protocol version 6)

- **구조**: 128비트(bit) 주소 체계로, 16비트씩 8개의 부분으로 나누어 16진수로 표현합니다. (예: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`)
- **주소 개수**: 거의 무한대($2^{128}$)에 가까운 주소를 제공하여 IPv4 주소 고갈 문제를 근본적으로 해결합니다.
- **주소 표현 규칙**:
    - 각 부분에서 앞의 0은 생략할 수 있습니다. (`0db8` -> `db8`, `0370` -> `370`)
    - 0이 연속으로 반복되는 부분은 한 번에 한해 `::`로 축약할 수 있습니다.
      `2001:0db8:85a3:0000:0000:8a2e:0370:7334` → `2001:db8:85a3::8a2e:370:7334`
- **주요 특징**: 보안 기능(IPsec)이 기본적으로 강화되었고, 주소 자동 설정 기능이 개선되었습니다.

## 3. 서브넷 마스크 (Subnet Mask) 와 프리픽스 (Prefix)

IP 주소는 단순히 장치를 식별하는 것을 넘어, **네트워크 부분(Network ID)**과 **호스트 부분(Host ID)**으로 나뉩니다. 서브넷 마스크는 IP 주소의 어디까지가 네트워크 부분이고 어디부터가 호스트 부분인지를 구분하는 역할을 합니다.

- **서브넷 마스크**: IPv4 주소와 똑같이 32비트 숫자로 표현되며, 네트워크 부분을 1로, 호스트 부분을 0으로 채웁니다.
    - `255.255.255.0` → `11111111.11111111.11111111.00000000` (앞의 24비트가 네트워크 부분)

- **프리픽스 (Prefix)**: 서브넷 마스크를 단순히 1의 개수, 즉 네트워크 부분의 비트 수로 표현하는 방식입니다. 훨씬 간결하여 널리 사용됩니다.
    - `255.255.255.0` → `/24`
    - `255.255.0.0` → `/16`

## 4. CIDR (Classless Inter-Domain Routing)

- **개념**: CIDR(사이더)는 클래스 없는 도메인 간 라우팅 기법으로, IP 주소와 프리픽스를 함께 사용하여 네트워크의 크기를 유연하게 표현하는 현대적인 주소 표기법입니다. (예: `192.168.1.0/24`)

- **CIDR 표기법 분석 (`192.168.1.0/24`)**:
    - **네트워크 주소**: `192.168.1.0` (해당 네트워크 자체를 나타내는 주소)
    - **프리픽스**: `/24` (앞의 24비트가 네트워크 부분, 뒤의 8비트가 호스트 부분)
    - **호스트 비트 수**: `32 - 24 = 8`비트
    - **사용 가능한 호스트 수**: $2^8 - 2 = 254$개
        - 2개를 빼는 이유: 호스트 부분이 모두 0인 주소(`192.168.1.0`)는 네트워크 주소로, 모두 1인 주소(`192.168.1.255`)는 브로드캐스트 주소로 예약되어 있기 때문입니다.
    - **사용 가능한 IP 주소 범위**: `192.168.1.1` ~ `192.168.1.254`

- **CIDR 예시**:
    - `/24`: 약 254개의 호스트를 가짐 (C 클래스 규모)
    - `/16`: 약 65,534개의 호스트를 가짐 (B 클래스 규모)
    - `/27`: $2^{(32-27)} - 2 = 2^5 - 2 = 30$개의 호스트를 가짐
    - `/30`: $2^{(32-30)} - 2 = 2^2 - 2 = 2$개의 호스트를 가짐 (라우터 간 연결 등 Point-to-Point 링크에 주로 사용)

CIDR 표기법을 이해하면, IP 주소와 서브넷 마스크만 보고도 해당 네트워크의 크기, 사용 가능한 IP 주소의 범위, 네트워크 주소, 브로드캐스트 주소를 빠르게 계산할 수 있으며, 이는 라우팅과 방화벽 규칙을 설정하는 데 필수적인 능력입니다.
