# 4-5-2: 게이트웨이 이중화: VRRP/GLBP/HSRP, `keepalived`

네트워크에서 **SPOF(Single Point of Failure, 단일 장애점)**가 될 수 있는 가장 대표적인 요소는 바로 **기본 게이트웨이(Default Gateway)**, 즉 라우터입니다. 모든 내부 트래픽이 외부로 나가기 위해 이 라우터를 거쳐야 하므로, 라우터에 장애가 발생하면 네트워크 전체가 마비될 수 있습니다. **게이트웨이 이중화**는 두 대 이상의 라우터를 사용하여 이러한 단일 장애점을 제거하고 고가용성을 확보하는 기술입니다.

이를 위한 프로토콜을 **FHRP(First Hop Redundancy Protocol)**라고 부르며, VRRP, HSRP, GLBP가 대표적입니다.

## 1. 게이트웨이 이중화 프로토콜

- **기본 개념**: 두 대 이상의 물리적 라우터를 하나의 논리적인 **가상 라우터(Virtual Router)**로 묶습니다. 내부 네트워크의 클라이언트들은 실제 라우터의 IP가 아닌, 이 가상 라우터의 **가상 IP(Virtual IP)**를 자신의 기본 게이트웨이로 설정합니다.
- **동작 원리**: 묶인 라우터 그룹 내에서, 한 대의 라우터가 **Active(활성)** 역할을 맡아 가상 IP에 대한 실질적인 게이트웨이 역할을 수행합니다. 나머지 라우터들은 **Standby(대기)** 상태로 대기하다가, Active 라우터에 장애가 발생했음을 감지하면(주기적인 헬스 체크 실패), 그중 한 대가 즉시 새로운 Active 라우터가 되어 가상 IP를 인계받아 중단 없이 게이트웨이 역할을 계속 수행합니다.

### VRRP (Virtual Router Redundancy Protocol)
- **특징**: IETF 표준 프로토콜로, 여러 벤더의 장비에서 지원되어 호환성이 높습니다. Active 라우터 한 대와 여러 대의 Standby 라우터로 구성됩니다.
- **용어**: Master(Active), Backup(Standby), Virtual IP.

### HSRP (Hot Standby Router Protocol)
- **특징**: 시스코(Cisco)에서 개발한 프로토콜로, VRRP와 거의 동일한 방식으로 동작합니다. 시스코 장비에서 널리 사용됩니다.
- **용어**: Active, Standby, Virtual IP.

### GLBP (Gateway Load Balancing Protocol)
- **특징**: HSRP, VRRP와 달리, 게이트웨이 이중화뿐만 아니라 **로드 밸런싱** 기능까지 제공하는 시스코 프로토콜입니다. 그룹 내의 여러 라우터가 동시에 Active 상태로 동작하며, 클라이언트들에게 서로 다른 가상 MAC 주소를 할당하여 나가는 트래픽을 여러 게이트웨이로 분산시킬 수 있습니다.

## 2. `keepalived`: 리눅스에서의 VRRP 구현

- **개념**: `keepalived`는 리눅스 서버에서 VRRP 프로토콜을 구현하여, 라우터뿐만 아니라 일반 리눅스 서버 자체를 이중화하는 데 널리 사용되는 오픈소스 소프트웨어입니다. 주로 두 대의 로드밸런서(예: HAProxy, Nginx)를 Active-Standby 구성으로 묶어 로드밸런서 자체의 고가용성을 확보하는 데 사용됩니다.

- **시나리오**: 두 대의 `Nginx` 로드밸런서(`nginx-1`, `nginx-2`)를 이중화하여, 외부 사용자가 접속하는 가상 IP(`1.2.3.4`)에 대한 서비스를 중단 없이 제공하고 싶다.

- **`keepalived` 설정 (`/etc/keepalived/keepalived.conf`)**:

  - **`nginx-1` (Master 서버) 설정**:
    ```
    vrrp_instance VI_1 {
        state MASTER
        interface eth0
        virtual_router_id 51
        priority 150
        advert_int 1
        authentication {
            auth_type PASS
            auth_pass 1111
        }
        virtual_ipaddress {
            1.2.3.4/24
        }
    }
    ```

  - **`nginx-2` (Backup 서버) 설정**:
    ```
    vrrp_instance VI_1 {
        state BACKUP
        interface eth0
        virtual_router_id 51
        priority 100
        advert_int 1
        authentication {
            auth_type PASS
            auth_pass 1111
        }
        virtual_ipaddress {
            1.2.3.4/24
        }
    }
    ```

- **설정 분석**:
    - `state MASTER/BACKUP`: 해당 서버의 초기 역할을 지정합니다. `MASTER`가 되면 즉시 가상 IP를 활성화합니다.
    - `interface eth0`: VRRP 프로토콜 메시지를 주고받을 네트워크 인터페이스.
    - `virtual_router_id 51`: VRRP 그룹을 식별하는 고유한 ID. 같은 그룹에 속한 서버들은 이 ID가 동일해야 합니다.
    - **`priority 150/100`**: 우선순위. **숫자가 높을수록** Master가 될 확률이 높습니다. Master 서버에 장애가 발생하면, 남은 Backup 서버들 중 `priority`가 가장 높은 서버가 새로운 Master가 됩니다.
    - `advert_int 1`: VRRP 헬스 체크 메시지를 몇 초 간격으로 보낼지 지정합니다.
    - `authentication`: 그룹 내 서버들 간의 인증에 사용할 비밀번호.
    - `virtual_ipaddress`: 이 VRRP 그룹이 관리할 가상 IP 주소.

- **동작**: 평상시에는 `priority`가 높은 `nginx-1`이 Master가 되어 가상 IP `1.2.3.4`를 소유하고 모든 서비스를 처리합니다. `nginx-1`에 장애가 발생하여 VRRP 메시지 전송이 끊기면, `nginx-2`가 이를 감지하고 자신이 새로운 Master가 되어 `1.2.3.4` 가상 IP를 가져와 서비스 중단을 최소화하며 인계받습니다.

게이트웨이 이중화와 `keepalived`는 네트워크 인프라의 핵심적인 단일 장애점을 제거하여, 하드웨어 장애나 소프트웨어 오류 상황에서도 서비스 연속성을 보장하는 고가용성 아키텍처의 필수적인 구성 요소입니다.
