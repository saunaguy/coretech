# 4-5-3: 정책 기반 라우팅 (PBR), 다중 회선/게이트웨이

일반적인 라우팅은 오직 **목적지 IP 주소(Destination IP)**만을 기준으로 경로를 결정합니다. 하지만 실제 네트워크 환경에서는 "이 트래픽은 A 회선으로, 저 트래픽은 B 회선으로 보내고 싶다"와 같이, 목적지 주소 외의 다른 조건(예: **출발지 IP 주소**, 포트 번호, 패킷 크기 등)에 따라 경로를 다르게 지정해야 하는 경우가 있습니다. 이를 **정책 기반 라우팅(Policy-Based Routing, PBR)**이라고 합니다.

PBR은 주로 두 개 이상의 인터넷 회선(다중 회선)을 사용하는 환경에서 트래픽을 효율적으로 관리하기 위해 사용됩니다.

## 1. PBR의 필요성: 다중 회선 환경

- **시나리오**: 한 회사에서 빠른 속도의 주 인터넷 회선(ISP A)과, 저렴하지만 속도가 느린 백업 회선(ISP B)을 동시에 사용하고 있습니다.
    - **요구사항 1**: 모든 일반적인 웹 서핑(HTTP/HTTPS) 트래픽은 빠른 주 회선(ISP A)으로 내보내고 싶다.
    - **요구사항 2**: 대용량 파일 전송(FTP)이나 중요하지 않은 트래픽은 저렴한 백업 회선(ISP B)으로 내보내고 싶다.
    - **요구사항 3**: 특정 서버(예: `192.168.1.100`)에서 나가는 모든 트래픽은 무조건 ISP B 회선을 사용하게 하고 싶다.

- **문제점**: 일반적인 라우팅 테이블은 오직 하나의 기본 게이트웨이(default gateway)만 가질 수 있으므로(메트릭 값이 가장 낮은 경로), 위와 같은 복잡한 요구사항을 충족시킬 수 없습니다.

## 2. 리눅스에서의 PBR 구현: `ip rule`과 라우팅 테이블

리눅스는 `iproute2` 패키지의 `ip rule` 명령을 사용하여 매우 강력하고 유연한 PBR을 구현할 수 있습니다. 그 핵심 원리는 **여러 개의 라우팅 테이블**을 만들고, **규칙(rule)**을 통해 특정 조건을 만족하는 트래픽이 어떤 라우팅 테이블을 참조할지를 지정하는 것입니다.

- **동작 순서**:
    1.  패킷이 들어오면, 커널은 `ip rule`에 정의된 규칙 목록을 순서대로(우선순위가 낮은 숫자부터) 확인합니다.
    2.  패킷의 속성(출발지 IP, 목적지 IP, 인터페이스 등)이 규칙의 조건과 일치하면,
    3.  커널은 해당 규칙이 지정한 **라우팅 테이블**을 사용하여 경로를 찾습니다.
    4.  만약 어떤 규칙과도 일치하지 않으면, 기본 라우팅 테이블(`main` 테이블)을 사용합니다.

### PBR 구현 단계

- **시나리오**: `eth0`는 ISP A(게이트웨이 `1.1.1.1`)에, `eth1`은 ISP B(게이트웨이 `2.2.2.2`)에 연결되어 있다. `192.168.1.100` 서버에서 나가는 모든 트래픽은 ISP B를 통하게 하고 싶다.

**1단계: 추가 라우팅 테이블 생성**
- `/etc/iproute2/rt_tables` 파일에 새로운 라우팅 테이블의 이름과 ID를 추가합니다. ID는 1부터 252까지의 숫자를 사용할 수 있습니다.
  ```
  # /etc/iproute2/rt_tables
  ...
  1    isp_b_table
  ```

**2단계: 새 라우팅 테이블에 경로 추가**
- `isp_b_table` 라우팅 테이블에 ISP B로 나가는 기본 게이트웨이를 설정합니다.
  ```bash
  # isp_b_table을 사용하는 트래픽은 2.2.2.2 게이트웨이를 통하도록 설정
  sudo ip route add default via 2.2.2.2 dev eth1 table isp_b_table

  # 해당 테이블에 로컬 경로도 추가
  sudo ip route add 192.168.1.0/24 dev eth0 table isp_b_table
  ```

**3단계: 규칙(Rule) 추가**
- `ip rule` 명령으로, 어떤 트래픽이 `isp_b_table`을 사용할지 규칙을 만듭니다.
  ```bash
  # 출발지 IP(from)가 192.168.1.100인 모든 트래픽은 'isp_b_table'을 참조하도록 규칙 추가
  # 30000은 규칙의 우선순위(priority)
  sudo ip rule add from 192.168.1.100 table isp_b_table priority 30000
  ```

**4단계: 확인**
- `ip rule list`: 현재 적용된 규칙 목록을 확인합니다.
- `ip route show table isp_b_table`: 새로 만든 라우팅 테이블의 내용을 확인합니다.

이제 `192.168.1.100` 서버에서 나가는 모든 트래픽은 `main` 테이블 대신 `isp_b_table`을 참조하게 되므로, 게이트웨이 `2.2.2.2`를 통해 ISP B 회선으로 나가게 됩니다. 반면, 다른 출발지 IP를 가진 트래픽은 이 규칙과 일치하지 않으므로 기존의 `main` 테이블에 설정된 기본 게이트웨이(`1.1.1.1`)를 통해 ISP A 회선으로 나갑니다.

정책 기반 라우팅은 이처럼 단순한 목적지 기반 라우팅의 한계를 넘어, 복잡한 네트워크 요구사항을 만족시키고 다중 회선을 효율적으로 활용할 수 있게 해주는 고급 네트워크 기술입니다. 출발지 주소뿐만 아니라, 방화벽 마크(`fwmark`), 인터페이스(`iif`), TOS 값 등 다양한 조건을 규칙으로 사용할 수 있어 매우 유연한 제어가 가능합니다.
