# 4-5-4: VPN (OpenVPN/IPsec), 터널/라우팅 상호작용

VPN(Virtual Private Network, 가상 사설망)은 인터넷과 같은 공용 네트워크를 통해, 마치 전용선으로 직접 연결된 사설 네트워크처럼 안전하게 통신할 수 있게 해주는 기술입니다. VPN은 데이터 암호화를 통해 통신의 **기밀성(Confidentiality)**과 **무결성(Integrity)**을 보장합니다.

VPN은 크게 두 가지 주요 시나리오에서 사용됩니다.
- **Site-to-Site VPN**: 서울 본사와 부산 지사처럼, 두 개의 서로 다른 네트워크를 안전하게 연결합니다.
- **Remote Access VPN**: 재택 근무자나 외부 사용자가 자신의 PC에서 회사 내부 네트워크에 안전하게 접속할 때 사용합니다.

## 1. VPN 프로토콜: IPsec과 SSL/TLS VPN

### IPsec (Internet Protocol Security)
- **개념**: 네트워크 계층(L3)에서 IP 패킷 자체를 암호화하고 인증하는 프로토콜 모음입니다. 운영체제의 커널 레벨에서 동작하므로, 상위 애플리케이션에 관계없이 모든 IP 트래픽을 투명하게 보호할 수 있습니다.
- **주요 프로토콜**:
    - **AH (Authentication Header)**: 데이터의 무결성과 인증을 보장하지만, 암호화는 제공하지 않습니다.
    - **ESP (Encapsulating Security Payload)**: 데이터의 무결성, 인증, 그리고 **암호화**까지 모두 제공합니다. 대부분의 경우 ESP가 사용됩니다.
- **동작 모드**:
    - **터널(Tunnel) 모드**: 원래의 IP 패킷 전체(헤더+데이터)를 암호화하고, 새로운 IP 헤더를 붙여 캡슐화합니다. 주로 Site-to-Site VPN에서 사용됩니다.
    - **전송(Transport) 모드**: 원래의 IP 헤더는 그대로 두고, 데이터 부분(페이로드)만 암호화합니다. 주로 내부 네트워크의 두 호스트 간 통신을 보호하는 데 사용됩니다.
- **장점**: 표준 프로토콜이며, 커널 레벨에서 동작하여 성능이 우수하고 모든 트래픽을 보호할 수 있습니다.
- **단점**: 설정이 복잡하고, 방화벽이나 NAT 환경에서 통과하기 어려운 경우가 있습니다.

### SSL/TLS VPN (OpenVPN, WireGuard)
- **개념**: 웹 브라우저의 HTTPS 통신에 사용되는 SSL/TLS 프로토콜을 사용하여 VPN 터널을 만드는 방식입니다. 응용 계층(L7)에서 동작하며, 별도의 클라이언트 소프트웨어를 통해 가상의 네트워크 인터페이스를 생성합니다.
- **대표적인 구현체**:
    - **OpenVPN**: SSL/TLS 기반 VPN의 사실상 표준으로, 매우 유연하고 다양한 인증 방식을 지원하며 대부분의 운영체제에서 사용 가능합니다.
    - **WireGuard**: 최신 VPN 프로토콜로, 더 적은 코드 라인과 최신 암호화 기술을 사용하여 OpenVPN보다 훨씬 빠르고 간결하며 설정이 쉽다는 장점이 있어 빠르게 채택되고 있습니다.
- **장점**: 표준 HTTPS 포트(443)를 사용할 수 있어 대부분의 방화벽을 쉽게 통과할 수 있으며, 설정이 비교적 간편합니다. Remote Access VPN에 매우 적합합니다.
- **단점**: 사용자 공간에서 동작하므로 커널 레벨의 IPsec보다 약간의 성능 오버헤드가 있을 수 있습니다.

## 2. VPN 터널과 라우팅의 상호작용

VPN이 연결되면, 시스템에는 `tun0` (OpenVPN) 또는 `wg0` (WireGuard)와 같은 **가상 네트워크 인터페이스**가 생성됩니다. 이 가상 인터페이스는 VPN 터널의 입구 역할을 하며, 시스템의 라우팅 테이블에 변화를 줍니다.

- **시나리오**: 내 PC(`192.168.1.100`)에서 OpenVPN 클라이언트를 실행하여 회사 VPN 서버에 접속했습니다. VPN 서버는 내 PC에 가상 IP `10.8.0.10`을 할당해주었고, 회사 내부 네트워크는 `10.0.0.0/8` 대역을 사용합니다.

- **VPN 연결 후 라우팅 테이블 변화 (`ip route show`)**:
  ```
  # VPN 연결 전
  default via 192.168.1.1 dev eth0
  192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.100

  # VPN 연결 후 (추가된 경로)
  0.0.0.0/1 via 10.8.0.1 dev tun0
  10.0.0.0/8 via 10.8.0.1 dev tun0
  128.0.0.0/1 via 10.8.0.1 dev tun0
  [VPN서버_공인IP] via 192.168.1.1 dev eth0
  ...
  ```

- **라우팅 분석**:
    - **`10.0.0.0/8 via 10.8.0.1 dev tun0`**: 회사 내부 네트워크(`10.0.0.0/8`)로 향하는 모든 트래픽은, 이제 물리적인 `eth0`가 아닌, 가상 인터페이스 `tun0`를 통해 VPN 터널의 게이트웨이(`10.8.0.1`)로 보내라는 규칙이 추가됩니다. 이 패킷들은 암호화되어 VPN 터널을 통과하게 됩니다.
    - **`[VPN서버_공인IP] via 192.168.1.1 dev eth0`**: VPN 터널 자체를 만들기 위한 통신(내 PC와 VPN 서버 간의 암호화된 패킷)은 기존의 인터넷 회선(기본 게이트웨이 `192.168.1.1`)을 통해야 하므로, VPN 서버의 공인 IP로 가는 더 구체적인 경로가 추가됩니다.
    - **`0.0.0.0/1`, `128.0.0.0/1`**: `default` 경로를 덮어쓰는 대신, 더 구체적인 두 개의 경로를 추가하여 모든 인터넷 트래픽이 VPN 터널을 통하도록 설정하는 기술입니다(Split Tunneling 비활성화). 이를 통해 VPN에 연결된 동안에는 내 모든 인터넷 트래픽이 회사 네트워크를 거쳐 나가게 되어, 보안 정책을 강제하거나 해외 서비스를 우회 접속하는 등의 용도로 사용될 수 있습니다.

VPN 트러블슈팅 시에는, `ip route show`와 `ip addr show`를 통해 VPN 연결 후 라우팅 테이블과 가상 인터페이스의 상태가 예상대로 변경되었는지 확인하는 것이 가장 중요합니다. 만약 경로가 제대로 추가되지 않았다면, VPN 클라이언트 설정이나 서버로부터 푸시(push)되는 라우팅 설정에 문제가 있을 가능성이 높습니다.
