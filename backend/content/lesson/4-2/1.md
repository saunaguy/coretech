# 4-2-1: DNS 동작(재귀/권한/캐시), DNSSEC/split-horizon

DNS(Domain Name System)는 `www.google.com`과 같이 사람이 기억하기 쉬운 도메인 이름을 컴퓨터가 이해하는 IP 주소(`172.217.25.196`)로 변환해주는, 인터넷의 전화번호부와 같은 핵심 시스템입니다. DNS의 동작 원리를 이해하는 것은 네트워크 문제 해결의 중요한 부분입니다.

## 1. DNS 쿼리 과정: 재귀적 질의 (Recursive Query)

사용자가 웹 브라우저에 `www.google.com`을 입력했을 때, IP 주소를 알아내기까지의 과정은 다음과 같습니다. 이 과정은 주로 **재귀적 질의(Recursive Query)**와 **반복적 질의(Iterative Query)**로 이루어집니다.

1.  **Local DNS Cache 확인**: PC가 가장 먼저 자신의 로컬 DNS 캐시(이전에 조회했던 기록)를 확인합니다. 여기에 정보가 있으면 즉시 반환하고 과정이 종료됩니다.

2.  **Recursive DNS Server (리졸버)에 질의**: 로컬 캐시에 정보가 없으면, PC는 미리 설정된 DNS 서버(보통 통신사에서 제공하는 서버나 `8.8.8.8`과 같은 공용 DNS 서버)에 질의를 보냅니다. 이 서버를 **Recursive DNS Server** 또는 **리졸버(Resolver)**라고 부릅니다. 사용자를 대신해서 IP 주소를 알아내어 알려줄 책임이 있습니다.

3.  **반복적 질의 (Iterative Query) 시작**: 이제부터 리졸버가 IP 주소를 찾기 위한 반복적 질의를 시작합니다.
    a.  **리졸버 → Root DNS Server**: 리졸버는 전 세계에 13개가 있는 **루트(Root) DNS 서버**에게 "`www.google.com`의 IP 주소가 뭐야?"라고 묻습니다. 루트 서버는 "나는 모르지만, `.com`을 관리하는 **TLD(Top-Level Domain) 서버** 주소는 이거야"라고 알려줍니다.
    b.  **리졸버 → TLD DNS Server**: 리졸버는 전달받은 `.com` TLD 서버에게 "`www.google.com`의 IP 주소가 뭐야?"라고 다시 묻습니다. TLD 서버는 "나는 모르지만, `google.com`을 관리하는 **권한 있는(Authoritative) DNS 서버** 주소는 이거야"라고 알려줍니다.
    c.  **리졸버 → Authoritative DNS Server**: 리졸버는 마침내 `google.com` 도메인의 실제 정보를 가지고 있는 **권한 있는 DNS 서버**(예: `ns1.google.com`)에게 "`www.google.com`의 IP 주소가 뭐야?"라고 묻습니다. 권한 있는 서버는 "그 IP 주소는 `172.217.25.196`이야"라고 최종 답변을 줍니다.

4.  **결과 캐싱 및 응답**: 리졸버는 알아낸 IP 주소를 자신의 **캐시(Cache)**에 일정 시간(TTL, Time-To-Live) 동안 저장하고, 최종적으로 사용자 PC에게 `172.217.25.196`이라는 IP 주소를 알려줍니다.

5.  **통신 시작**: 사용자 PC는 이제 IP 주소를 알게 되었으므로, 해당 IP로 HTTP 요청을 보내 웹사이트에 접속합니다.

## 2. DNS 서버의 종류

- **Recursive DNS Server (리졸버)**: 클라이언트의 요청을 받아 대신 IP 주소를 찾아주는 서버. 캐시 기능이 있어 반복적인 요청을 빠르게 처리합니다. (예: KT/SKT/LG DNS, Google DNS(`8.8.8.8`), Cloudflare DNS(`1.1.1.1`))
- **Authoritative DNS Server (권한 있는 DNS 서버)**: 특정 도메인(예: `google.com`)에 대한 실제 정보를 가지고 있는 원본 서버. 도메인 관리자가 직접 레코드(A, MX, CNAME 등)를 설정하는 곳입니다. (예: AWS Route 53, Cloudflare DNS, 가비아 DNS 등)

## 3. 고급 DNS 개념

### DNSSEC (Domain Name System Security Extensions)
- **개념**: DNS 응답이 중간에 공격자에 의해 변조되는 것(DNS Spoofing, Cache Poisoning)을 막기 위한 보안 확장 기술입니다.
- **동작 원리**: 권한 있는 DNS 서버가 자신의 DNS 레코드에 대해 **전자서명**을 하여 공개합니다. 리졸버는 이 서명을 검증함으로써, 자신이 받은 응답이 변조되지 않은 신뢰할 수 있는 응답임을 확인할 수 있습니다.
- **효과**: DNS 데이터의 **무결성(Integrity)**과 **인증(Authentication)**을 보장하여 인터넷의 신뢰도를 높입니다.

### Split-Horizon DNS (View-based DNS)
- **개념**: 동일한 도메인 이름에 대해, **질의를 요청한 클라이언트의 위치(IP 주소)에 따라 서로 다른 IP 주소를 응답**해주는 기술입니다.
- **주요 사용 사례**:
    - **내부용/외부용 서비스 분리**: 회사 내부 네트워크에서 `service.mycompany.com`에 접속하면 내부 사설 IP(`10.1.1.10`)를 알려주고, 외부 인터넷에서 접속하면 외부 공인 IP(`203.0.113.50`)를 알려주어 불필요한 외부 트래픽을 줄이고 보안을 강화합니다.
    - **CDN (Content Delivery Network)**: 사용자와 가장 가까운 위치에 있는 CDN 엣지 서버의 IP 주소를 알려주어, 콘텐츠 다운로드 속도를 향상시킵니다.

이러한 DNS의 동작 원리와 개념을 이해하면, "웹사이트 접속이 안 돼요"라는 문제가 발생했을 때, 그것이 서버 자체의 문제인지, 네트워크 경로의 문제인지, 아니면 DNS 이름 해석 단계의 문제인지를 체계적으로 진단할 수 있게 됩니다.
