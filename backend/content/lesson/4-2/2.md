# 4-2-2: DNS 도구 (`dig`/`nslookup`) 및 레코드 유형

DNS 관련 문제를 진단하고 도메인 설정을 확인하기 위해서는 `dig`나 `nslookup`과 같은 커맨드라인 도구를 사용하여 DNS 서버에 직접 질의하는 방법을 알아야 합니다. 또한, DNS를 구성하는 다양한 레코드 유형의 의미를 이해하는 것이 중요합니다.

## 1. DNS 조회 도구

### `dig` (Domain Information Groper)
- **기능**: 현재 DNS 문제를 진단하는 데 가장 널리 사용되는 표준 도구입니다. `nslookup`보다 훨씬 더 상세하고, 스크립트에서 사용하기 좋은 형식으로 결과를 출력합니다.

- **`dig` 결과 분석**:
  ```
  $ dig www.google.com

  ; <<>> DiG 9.16.1-Ubuntu <<>> www.google.com
  ;; global options: +cmd
  ;; Got answer:
  ;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 12345
  ;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

  ;; OPT PSEUDOSECTION:
  ; EDNS: version: 0, flags:; udp: 65494
  ;; QUESTION SECTION:
  ;www.google.com.                  IN      A

  ;; ANSWER SECTION:
  www.google.com.         200     IN      A       172.217.25.196

  ;; Query time: 10 msec
  ;; SERVER: 8.8.8.8#53(8.8.8.8)
  ;; WHEN: Thu Sep 25 10:00:00 KST 2025
  ;; MSG SIZE  rcvd: 61
  ```
  - **`QUESTION SECTION`**: 내가 무엇을 질문했는지 보여줍니다. (`www.google.com`의 `A` 레코드)
  - **`ANSWER SECTION`**: 질문에 대한 답변입니다. (`172.217.25.196`)
  - `status: NOERROR`: 쿼리가 성공적으로 처리되었음을 의미합니다. (`NXDOMAIN`은 도메인이 없다는 의미)
  - `SERVER`: 이 응답을 해준 DNS 서버의 IP 주소입니다. (이 경우 `8.8.8.8`)

- **주요 `dig` 사용법**:
  ```bash
  # 특정 타입의 레코드 조회 (MX: 메일 서버)
  dig google.com MX

  # 특정 네임서버에 직접 질의
  dig @ns1.google.com www.google.com

  # +trace 옵션: 루트 서버부터의 전체 질의 과정을 추적하여 보여줌 (매우 유용)
  dig +trace google.com

  # +short 옵션: IP 주소 등 최종 결과만 간략하게 보여줌
  dig +short google.com
  ```

### `nslookup`
- **기능**: `dig`보다 오래된 도구로, 간단한 DNS 조회에 사용할 수 있습니다. 대화형 모드를 제공하는 특징이 있습니다.
  ```bash
  $ nslookup google.com
  Server:         8.8.8.8
  Address:        8.8.8.8#53

  Non-authoritative answer:
  Name:   google.com
  Address: 172.217.161.14
  ```

## 2. 주요 DNS 레코드 유형

DNS는 단순히 도메인 이름을 IP 주소로 변환하는 것 외에도, 다양한 종류의 정보를 저장하기 위해 여러 레코드 유형을 사용합니다.

- **`A` (Address) 레코드**: 도메인 이름에 해당하는 **IPv4 주소**를 지정합니다. 가장 기본적인 레코드입니다.
  `example.com.  IN  A  93.184.216.34`

- **`AAAA` (Quad A) 레코드**: 도메인 이름에 해당하는 **IPv6 주소**를 지정합니다.
  `example.com.  IN  AAAA  2606:2800:220:1:248:1893:25c8:1946`

- **`CNAME` (Canonical Name) 레코드**: 특정 도메인 이름을 다른 도메인 이름의 **별칭(alias)**으로 지정합니다. `www.example.com`을 `example.com`으로 연결하는 등에 사용됩니다.
  `www.example.com.  IN  CNAME  example.com.`
  - **주의**: `CNAME` 레코드가 설정된 이름에는 다른 레코드(MX, NS 등)를 추가할 수 없습니다.

- **`MX` (Mail eXchanger) 레코드**: 해당 도메인의 이메일을 처리하는 **메일 서버**의 주소를 지정합니다. 우선순위(priority) 값을 가지며, 낮은 숫자가 더 높은 우선순위를 가집니다.
  `example.com.  IN  MX  10  mail.example.com.`

- **`NS` (Name Server) 레코드**: 해당 도메인에 대한 **권한 있는 네임서버**가 무엇인지 지정합니다. 이 레코드는 상위 TLD 서버에 등록되어 DNS 쿼리 과정에서 사용됩니다.
  `example.com.  IN  NS  ns1.example.com.`

- **`TXT` (Text) 레코드**: 도메인에 대한 임의의 텍스트 정보를 저장하는 데 사용됩니다. 주로 도메인 소유권을 확인하거나, 이메일 보안을 위한 **SPF(Sender Policy Framework)**, **DKIM(DomainKeys Identified Mail)**, **DMARC** 정책을 설정하는 데 널리 사용됩니다.
  `example.com.  IN  TXT  "v=spf1 include:_spf.google.com ~all"`

- **`SRV` (Service) 레코드**: 특정 서비스(예: LDAP, SIP, Minecraft 서버)가 어떤 호스트와 포트에서 실행되고 있는지 알려주는 레코드입니다.

이러한 DNS 도구와 레코드 유형에 대한 이해는 웹사이트가 열리지 않거나, 이메일이 전송되지 않는 등 다양한 네트워크 관련 문제의 원인을 진단하고 해결하는 데 필수적인 지식입니다.
