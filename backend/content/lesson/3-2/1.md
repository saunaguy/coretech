# 3-2-1: 부팅 실패: GRUB 수동 부팅, `initramfs` 검증, 커널 파라미터

리눅스 서버 부팅 실패는 가장 까다로운 문제 중 하나입니다. 시스템이 완전히 시작되지 않은 상태에서 문제를 해결해야 하기 때문입니다. 부팅 프로세스의 초기 단계인 GRUB, `initramfs`를 이해하고, 커널 파라미터를 조정하는 것은 부팅 문제 해결의 핵심입니다.

## 리눅스 부팅 프로세스 (간략)

1.  **BIOS/UEFI**: 하드웨어를 초기화하고 부트 로더를 찾아서 실행합니다.
2.  **GRUB2 (부트 로더)**: 사용자가 선택한 커널을 메모리에 로드하고, `initramfs`와 함께 커널에 제어권을 넘깁니다.
3.  **커널 & `initramfs`**: 커널이 초기화되면서 `initramfs`(초기 RAM 파일 시스템)를 메모리에 로드합니다. `initramfs`는 실제 루트 파일 시스템에 접근하는 데 필요한 드라이버(예: 디스크 컨트롤러, LVM, RAID)를 포함하고 있는 작은 임시 파일 시스템입니다. 여기서 실제 루트 파일 시스템을 마운트합니다.
4.  **`systemd`**: 실제 루트 파일 시스템의 `systemd` 프로세스(PID 1)가 실행되어 나머지 시스템 서비스를 시작합니다.

부팅 실패는 주로 2번과 3번 단계에서 발생합니다.

## 1. GRUB (GRand Unified Bootloader) 문제 해결

- **시나리오**: 커널 업데이트 후 또는 `grub.cfg` 파일이 손상되어 부팅 메뉴가 나타나지 않거나, 잘못된 커널로 부팅을 시도하여 "kernel panic"이 발생하는 경우.

- **해결 방법: GRUB 메뉴에서 수동 부팅**
    1.  시스템 부팅 시, GRUB 메뉴가 나타나면 `e` 키를 눌러 부팅 파라미터 편집 모드로 들어갑니다.
    2.  편집 화면에는 `linux ...` 또는 `linux16 ...`으로 시작하는 라인이 있습니다. 이 라인이 커널과 부팅 옵션을 정의하는 부분입니다.
        - `linux /boot/vmlinuz-5.14.0-427.el9.x86_64 root=UUID=... ro`: 커널 이미지 파일 경로와 루트 파일 시스템의 위치, 읽기 전용 마운트 옵션 등을 지정합니다.
        - `initrd /boot/initramfs-5.14.0-427.el9.x86_64.img`: `initramfs` 이미지 파일 경로를 지정합니다.
    3.  **잘못된 커널 버전 수정**: 만약 새 커널에 문제가 있다면, 이 라인들의 커널 버전(예: `5.14.0-427`)을 이전에 정상적으로 부팅되었던 이전 커널 버전으로 직접 수정합니다.
    4.  **커널 파라미터 추가/수정**: 특정 하드웨어 문제나 디버깅을 위해 커널 파라미터를 추가할 수 있습니다. (아래 '커널 파라미터' 섹션 참고)
    5.  `Ctrl + x`를 눌러 수정된 파라미터로 부팅을 시도합니다.
    6.  부팅에 성공했다면, `grub2-mkconfig` 명령을 사용하여 GRUB 설정을 영구적으로 재생성해야 합니다.
        ```bash
        # RHEL/CentOS 계열
        sudo grub2-mkconfig -o /boot/grub2/grub.cfg

        # Debian/Ubuntu 계열
        sudo update-grub
        ```

## 2. `initramfs` 문제 해결

- **시나리오**: LVM, RAID 등 특수 드라이버가 필요한데 `initramfs`에 해당 모듈이 포함되지 않아 실제 루트 파일 시스템을 찾지 못하고 부팅이 멈추는 경우. (예: "Dracut Emergency Shell")

- **`initramfs` 검증 (`lsinitrd`)**:
  `lsinitrd` 명령어는 `initramfs` 이미지 파일 안에 어떤 파일과 커널 모듈이 포함되어 있는지 보여줍니다.
  ```bash
  # 현재 커널의 initramfs 내용 확인
  lsinitrd | less

  # 특정 initramfs 파일 내용 확인
  lsinitrd /boot/initramfs-5.14.0-427.el9.x86_64.img

  # 특정 커널 모듈(예: LVM)이 포함되어 있는지 확인
  lsinitrd | grep lvm
  ```

- **`initramfs` 재생성 (`dracut`, `update-initramfs`)**:
  커널 모듈 설정(`modprobe.d`)을 변경했거나 `initramfs`가 손상되었다고 의심될 때, 이를 재생성하여 문제를 해결할 수 있습니다.
  ```bash
  # RHEL/CentOS 계열 (dracut)
  # 현재 커널에 대해 initramfs를 강제로 다시 생성
  sudo dracut --force

  # Debian/Ubuntu 계열 (update-initramfs)
  # 모든 커널 버전에 대해 initramfs 업데이트
  sudo update-initramfs -u -k all
  ```

## 3. 커널 파라미터 (부팅 옵션) 활용

커널 파라미터는 GRUB에서 커널로 전달하는 옵션으로, 커널의 동작 방식을 변경하여 부팅 문제를 해결하거나 시스템을 특정 모드로 시작하게 할 수 있습니다.

- **주요 커널 파라미터**:
    - **`systemd.unit=rescue.target`**: 복구 모드(rescue mode)로 부팅합니다. 최소한의 서비스만 실행되며, 파일 시스템 점검이나 암호 변경 등에 사용됩니다.
    - **`systemd.unit=emergency.target`**: 긴급 모드(emergency mode)로 부팅합니다. 루트 파일 시스템을 읽기 전용으로 마운트하고 거의 아무 서비스도 시작하지 않는 최후의 복구 환경입니다.
    - **`rd.break`**: `initramfs` 단계에서 부팅을 멈추고 셸을 띄워줍니다. 루트 파일 시스템의 암호를 잊어버렸을 때, `chroot`를 통해 암호를 재설정하는 데 주로 사용됩니다.
    - **`nomodeset`**: 그래픽 드라이버(GPU) 문제로 화면이 깨지거나 부팅이 멈출 때, 커널 모드 세팅(KMS)을 비활성화하여 기본적인 그래픽 모드로 부팅을 시도합니다.

- **적용 방법**:
  GRUB 메뉴에서 `e` 키를 눌러 편집 모드로 들어간 뒤, `linux ...` 라인의 끝에 원하는 파라미터를 추가하고 `Ctrl + x`로 부팅합니다.

부팅 트러블슈팅은 시스템의 가장 근본적인 부분을 다루기 때문에 어렵게 느껴질 수 있지만, 부팅 프로세스의 각 단계를 이해하고 GRUB, `initramfs`, 커널 파라미터라는 세 가지 핵심 요소를 활용하면 대부분의 부팅 관련 문제를 체계적으로 해결할 수 있습니다.
