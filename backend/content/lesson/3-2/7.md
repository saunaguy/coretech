# 3-2-7: 감사/포렌식: `auditd` 규칙, 무결성/이벤트 검색 (`ausearch`)

(이 내용은 `2-4-15`에서 다룬 `auditd` 기초를 바탕으로, 트러블슈팅과 포렌식 관점에서 더 심화된 내용을 다룹니다.)

시스템에 보안 사고가 발생했거나, 규정 준수(Compliance)를 위해 특정 행위를 반드시 기록해야 할 때, `auditd`는 "누가, 언제, 무엇을 했는가"를 추적하는 가장 강력한 도구입니다. 감사(Auditing)는 사후 분석과 포렌식(Forensic)의 기반이 됩니다.

## 1. `auditd` 규칙 심화

`auditd`의 규칙은 `/etc/audit/rules.d/` 디렉터리에 `.rules` 파일로 정의하며, 시스템 부팅 시 이 규칙들이 메모리에 로드됩니다. 규칙은 매우 상세하게 설정할 수 있어, 원하는 이벤트를 정밀하게 포착할 수 있습니다.

### 주요 규칙 설정 (`auditctl`)

- **파일/디렉터리 감시 (`-w`)**: 특정 경로에 대한 접근을 감시합니다.
  ```bash
  # /etc/shadow 파일에 대한 모든 쓰기(w)와 속성 변경(a)을 감시하고, 'shadow_changes'라는 키로 식별
  -w /etc/shadow -p wa -k shadow_changes
  ```

- **시스템 콜 감시 (`-a`)**: 특정 시스템 콜이 호출되는 것을 감시합니다. `-S` 옵션으로 시스템 콜 이름을 지정합니다.
  ```bash
  # 'open' 시스템 콜 중, 쓰기(O_WRONLY)나 읽기/쓰기(O_RDWR) 모드로 파일을 여는 모든 시도를 감시
  -a always,exit -F arch=b64 -S open -F a2&03=03 -k file_writes
  ```

- **명령어 실행 감시**: 특정 명령어가 실행되는 것을 직접 감시할 수는 없지만, 해당 명령어가 사용하는 시스템 콜을 감시함으로써 간접적으로 추적할 수 있습니다. `auditctl`은 이를 위한 편리한 문법을 제공합니다.
  ```bash
  # /usr/bin/passwd 명령어가 실행되는 것을 감시
  -w /usr/bin/passwd -p x -k passwd_execution
  ```

### 규칙 파일 관리

- 규칙들은 논리적인 그룹(예: `logins.rules`, `file_monitoring.rules`)으로 나누어 여러 `.rules` 파일로 관리하는 것이 좋습니다.
- 규칙 파일의 이름 앞에는 번호를 붙여(예: `10-logins.rules`, `20-files.rules`) 로드되는 순서를 제어할 수 있습니다.
- 규칙을 수정한 후에는 `augenrules --load` 명령으로 즉시 적용하거나, `auditd` 서비스를 재시작합니다.

## 2. 이벤트 검색과 분석 (`ausearch`, `aureport`)

`auditd`가 생성하는 로그(`/var/log/audit/audit.log`)는 매우 상세하지만, 그대로 읽기에는 어렵습니다. `ausearch`와 `aureport`는 이 로그를 의미 있는 정보로 가공해주는 필수 도구입니다.

### `ausearch`: 특정 이벤트 검색

- **시나리오**: 어젯밤 사이에 `/etc/shadow` 파일이 변경된 것 같다. 누가 변경했는지 추적하고 싶다.

- **검색 절차**:
  1.  규칙에 설정한 키(`-k`)로 검색하는 것이 가장 효율적입니다.
      ```bash
      sudo ausearch -k shadow_changes
      ```
  2.  특정 시간대(`-ts`, `-te`)를 지정하여 검색 범위를 좁힙니다.
      ```bash
      sudo ausearch -k shadow_changes -ts yesterday -te today
      ```
  3.  특정 사용자(`-ui`)나 프로세스 이름(`-c`)으로 필터링합니다.
      ```bash
      sudo ausearch -k shadow_changes -ui admin
      ```
  4.  `-i` 옵션을 추가하면 UID, GID 등을 실제 이름으로 변환해주어 가독성을 높여줍니다.
      ```bash
      sudo ausearch -k shadow_changes -i
      ```

- **로그 분석**: `ausearch`의 출력은 여러 `type=` 레코드로 구성된 이벤트 묶음입니다. `SYSCALL` 레코드에서는 어떤 시스템 콜이 호출되었는지, `CWD`(Current Working Directory) 레코드에서는 명령이 실행된 위치, `PATH` 레코드에서는 접근한 파일의 경로를 알 수 있습니다. `auid`(Audit UID)는 최초 로그인한 사용자를, `uid`는 명령을 실행한 유효 사용자를 나타내어 `sudo` 사용 등을 추적할 수 있습니다.

### `aureport`: 통계 리포트 생성

- **기능**: `aureport`는 전체 감사 로그를 분석하여 요약된 통계 리포트를 생성합니다. 시스템에서 어떤 일들이 주로 발생했는지 전체적인 그림을 파악하는 데 유용합니다.

- **주요 리포트**:
  ```bash
  # 로그인/로그아웃 리포트
  sudo aureport -l

  # 인증 실패 리포트
  sudo aureport -au

  # 이벤트 발생 요약 리포트
  sudo aureport --summary

  # 특정 키('shadow_changes')에 대한 리포트
  sudo aureport -k
  ```

## 3. 파일 무결성 검증과의 연계

`auditd`는 파일 변경 **행위**를 기록하는 반면, `AIDE`(Advanced Intrusion Detection Environment)나 `Tripwire`와 같은 호스트 기반 침입 탐지 시스템(HIDS)은 파일 내용의 **결과**를 검증합니다.

- **AIDE**: 시스템의 중요 파일들에 대한 해시, 권한, 타임스탬프 등의 정보를 데이터베이스로 만들어 둡니다. 그리고 주기적으로 현재 파일 상태와 데이터베이스를 비교하여 변경 사항을 리포트합니다.
- **연계 전략**: `AIDE`가 `/etc/hosts` 파일의 변경을 탐지했다면, `auditd` 로그를 `ausearch`로 분석하여 "언제, 누가, 어떤 프로세스가 `/etc/hosts` 파일을 변경했는지"를 역추적하여 완벽한 감사 체인을 완성할 수 있습니다.

감사와 포렌식은 문제가 발생하기 전에 미리 계획하고 준비해야 하는 선제적인 활동입니다. 어떤 이벤트를 기록할지 정책을 수립하고, `auditd` 규칙을 설정하며, 정기적으로 로그를 검토하는 프로세스를 갖추는 것이 중요합니다.
