# 3-2-3: 네트워크 이슈: 라우팅/방화벽/네임해결 점검 (`ip`, `ss`, `nft`, `dig`)

"서버는 정상인데 접속이 안 돼요"라는 상황은 네트워크 관련 문제일 가능성이 높습니다. 네트워크 문제는 크게 **1) 로컬 설정 오류, 2) 방화벽 차단, 3) 경로 문제, 4) 이름 해석(DNS) 실패** 네 가지로 분류할 수 있습니다. 이들을 체계적으로 점검하는 방법을 알아봅니다.

## 1. 로컬 네트워크 설정 점검

가장 먼저 서버 자체의 네트워크 설정이 올바른지 확인해야 합니다.

- **`ip` 명령어**: `ifconfig`, `route`, `netstat` 등 기존의 여러 네트워크 명령어를 통합한 최신 도구입니다.

  - **IP 주소 및 인터페이스 상태 확인**:
    ```bash
    ip addr show
    # 또는 ip a
    ```
    - 확인 사항: 대상 네트워크 인터페이스(예: `eth0`)가 `UP` 상태인지, 올바른 IP 주소와 서브넷 마스크(CIDR)가 할당되었는지 확인합니다.

  - **라우팅 테이블 확인**:
    ```bash
    ip route show
    # 또는 ip r
    ```
    - 확인 사항: `default via [게이트웨이_IP]` 항목이 올바르게 설정되어 있는지 확인합니다. 게이트웨이가 잘못 설정되면 외부 네트워크(인터넷)와 통신할 수 없습니다.

- **`ss` 명령어**: 소켓(Socket) 상태를 확인하여 서비스가 특정 포트에서 정상적으로 LISTEN 하고 있는지 확인합니다. (`netstat`의 현대적인 대체재)
  ```bash
  # LISTEN 중인 TCP 포트와 관련 프로세스 확인
  sudo ss -tlpn
  ```
  - 확인 사항: 접속하려는 서비스(예: `nginx`)가 예상하는 포트(예: `80`, `443`)에서 `LISTEN` 상태인지 확인합니다. 만약 `127.0.0.1:80`과 같이 로컬 주소에만 바인딩되어 있다면 외부에서 접속할 수 없습니다.

## 2. 방화벽 점검

로컬 설정이 정상이라면, 다음은 방화벽이 트래픽을 차단하고 있는지 확인해야 합니다.

- **`firewalld` 사용 시**:
  ```bash
  # 현재 활성화된 규칙 목록 보기
  sudo firewall-cmd --list-all
  ```
  - 확인 사항: `services:` 또는 `ports:` 목록에 허용하려는 서비스 이름이나 포트 번호가 포함되어 있는지 확인합니다.

- **`nftables` 사용 시**: `iptables`를 대체하는 최신 패킷 필터링 프레임워크입니다.
  ```bash
  # 현재 규칙 세트 보기
  sudo nft list ruleset
  ```
  - 확인 사항: `input` 체인에 해당 포트로 들어오는 패킷을 `accept`하는 규칙이 있는지, 혹은 그보다 먼저 `drop`하는 규칙이 없는지 확인합니다.

- **방화벽 임시 중단으로 테스트**: 방화벽 규칙이 복잡하여 분석이 어려울 경우, **잠깐 동안만** 방화벽을 비활성화하여 문제가 해결되는지 확인해 볼 수 있습니다. (주의: 운영 환경에서는 보안에 매우 취약해지므로 테스트 직후 반드시 다시 활성화해야 합니다.)
  ```bash
  sudo systemctl stop firewalld
  # ... 접속 테스트 ...
  sudo systemctl start firewalld
  ```

## 3. 경로 추적 (`traceroute`, `mtr`)

서버와 클라이언트 사이의 중간 경로에 문제가 있을 수도 있습니다. `traceroute`나 `mtr`을 사용하여 패킷이 어떤 라우터를 거쳐 가는지, 어느 구간에서 지연이나 손실이 발생하는지 확인할 수 있습니다.

- **`mtr` (My Traceroute)**: `traceroute`와 `ping`을 결합한 도구로, 각 홉(hop)까지의 패킷 손실률과 지연 시간을 지속적으로 보여주어 훨씬 더 유용합니다.
  ```bash
  # 클라이언트에서 서버 IP로 mtr 실행
  mtr [서버_IP_주소]
  ```
  - 확인 사항: 특정 홉에서 갑자기 패킷 손실(`Loss%`)이 발생하거나 지연 시간(`Last`, `Avg`)이 급증하는지 확인합니다. 이는 해당 라우터나 그 다음 구간에 문제가 있음을 시사합니다.

## 4. 이름 해석 (DNS) 점검 (`dig`)

IP 주소로는 접속되는데 도메인 이름으로 접속이 안 된다면, DNS 문제일 가능성이 높습니다.

- **`dig` 명령어**: 도메인에 대한 DNS 정보를 상세하게 조회합니다.
  ```bash
  # 도메인의 IP 주소(A 레코드) 조회
  dig my-server.example.com
  ```
  - **`ANSWER SECTION` 확인**: 여기에 올바른 IP 주소가 반환되는지 확인합니다.
  - **`status: NOERROR` 확인**: `NXDOMAIN`(도메인이 없음)이나 `SERVFAIL`(서버 오류) 등이 표시된다면 DNS 서버 자체나 도메인 설정에 문제가 있는 것입니다.

- **클라이언트의 DNS 설정 확인**: 클라이언트 PC나 다른 서버에서 `/etc/resolv.conf` 파일에 올바른 네임서버가 설정되어 있는지도 확인해야 합니다.

### 종합적인 네트워크 트러블슈팅 절차

1.  **(From Server)** `ip a`, `ip r`로 서버의 IP, 라우팅 확인.
2.  **(From Server)** `ss -tlpn`으로 서비스가 올바른 포트에서 LISTEN 중인지 확인.
3.  **(From Server)** `firewall-cmd --list-all` 또는 `nft list ruleset`으로 방화벽 규칙 확인.
4.  **(From Client)** `ping [서버_IP]`로 기본적인 연결성 확인.
5.  **(From Client)** `nc -vz [서버_IP] [포트]`로 특정 포트까지의 연결성 확인.
6.  **(From Client)** `mtr [서버_IP]`로 중간 경로의 문제점 확인.
7.  **(From Client)** `dig [서버_도메인]`으로 DNS 이름 해석 확인.

이처럼 계층적이고 체계적인 접근 방식을 통해, 복잡해 보이는 네트워크 문제의 원인을 효율적으로 찾아내고 해결할 수 있습니다.
