# 3-2-5: 성능 병목: `vmstat`/`iostat`/`sar`로 분류

"서버가 느려요"라는 문제는 가장 흔하면서도 원인을 찾기 어려운 문제입니다. 성능 병목 현상은 크게 **CPU, 메모리, 디스크 I/O, 네트워크** 네 가지 영역에서 발생합니다. `vmstat`, `iostat`, `sar`와 같은 도구들은 시스템의 전반적인 성능 지표를 보여주어 문제의 원인이 어느 영역에 있는지 분류하는 데 도움을 줍니다.

이 도구들은 대부분 `sysstat` 패키지에 포함되어 있으므로, `sudo dnf install sysstat` 또는 `sudo apt install sysstat`로 설치해야 할 수 있습니다.

## 1. `vmstat`: 시스템 전반의 활동 요약

- **기능**: `vmstat` (Virtual Memory Statistics)는 특정 시간 간격으로 프로세스, 메모리, 페이징, 블록 I/O, CPU 활동에 대한 정보를 한 줄로 요약해서 보여줍니다.

- **사용법**: `vmstat [간격] [횟수]`
  ```bash
  # 2초 간격으로 5번 상태를 출력
  vmstat 2 5
  ```
  ```
  procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
   r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
   1  0      0 123456  10000 543210    0    0    10    20  100  200 10  5 80  5  0
   ...
  ```

- **주요 컬럼 분석**:
    - **`procs`**
        - `r` (run queue): CPU를 사용하기 위해 대기 중인 프로세스의 수. 이 값이 지속적으로 CPU 코어 수를 초과하면 **CPU 병목**을 의심할 수 있습니다.
        - `b` (blocked): I/O(주로 디스크) 작업이 끝나기를 기다리며 블록된 프로세스의 수.
    - **`memory`**
        - `swpd`: 사용 중인 스왑 메모리의 양.
        - `free`: 사용 가능한 물리적 메모리의 양.
    - **`swap`**
        - `si` (swap-in), `so` (swap-out): 스왑 공간에서 메모리로, 또는 메모리에서 스왑 공간으로 이동하는 데이터의 양. 이 값들이 지속적으로 0이 아니라면 **메모리 부족**을 의미합니다.
    - **`io`**
        - `bi` (block-in), `bo` (block-out): 블록 장치(디스크)로부터 읽거나 쓰는 블록의 수. 이 값이 높게 유지된다면 **디스크 I/O 병목**을 의심할 수 있습니다.
    - **`cpu`**
        - `us` (user): 사용자 공간에서 사용된 CPU 비율.
        - `sy` (system): 커널 공간에서 사용된 CPU 비율.
        - `id` (idle): 유휴 CPU 비율. 이 값이 낮다면 CPU가 바쁘다는 의미입니다.
        - `wa` (wait): I/O 대기에 사용된 CPU 비율. 이 값이 높다면 **디스크 I/O 병목**으로 인해 CPU가 놀고 있음을 의미합니다.

## 2. `iostat`: 디스크 I/O 심층 분석

- **기능**: `iostat` (Input/Output Statistics)는 시스템의 CPU 사용량과 함께, 각 디스크 장치별 I/O 성능에 대한 상세한 통계를 보여줍니다.

- **사용법**: `iostat -x [간격] [횟수]`
  ```bash
  # 2초 간격으로 각 디스크의 상세 I/O 통계(-x)를 보여줌
  iostat -x 2
  ```

- **주요 컬럼 분석**:
    - `r/s`, `w/s`: 초당 읽기/쓰기 요청 수 (IOPS).
    - `rkB/s`, `wkB/s`: 초당 읽기/쓰기 데이터 양 (Throughput).
    - `await`: I/O 요청이 처리되기까지 걸리는 평균 시간 (밀리초). 이 값이 높다면 디스크 응답이 느리다는 의미입니다.
    - `%util`: 해당 장치가 I/O 작업을 처리하는 데 사용된 시간의 비율. 이 값이 100%에 가깝다면 **디스크가 포화 상태**임을 의미하며, 명백한 **디스크 I/O 병목**입니다.

## 3. `sar`: 과거 데이터 분석의 강자

- **기능**: `sar` (System Activity Reporter)는 `sysstat` 패키지의 핵심 도구로, 시스템의 다양한 성능 지표(CPU, 메모리, I/O, 네트워크 등)를 주기적으로 수집하여 과거 데이터로 저장하고, 이를 리포트 형태로 보여줍니다. "어젯밤 10시에 서버가 느렸는데, 그때 무슨 일이 있었지?"와 같은 질문에 답할 수 있게 해줍니다.

- **사용법**:
  `sar`는 `cron`을 통해 10분마다 `/var/log/sa/` 디렉터리에 바이너리 형태로 데이터를 기록합니다.

  - **CPU 사용량 분석**:
    ```bash
    # 오늘의 CPU 사용량 통계 보기
    sar -u

    # 특정 날짜(예: 25일)의 데이터 보기 (-f 옵션)
    sar -u -f /var/log/sa/sa25
    ```

  - **메모리 사용량 분석**:
    `sar -r`

  - **디스크 I/O 분석**:
    `sar -b`

  - **네트워크 트래픽 분석**:
    `sar -n DEV`

### 성능 병목 분류 절차

1.  **`vmstat 1`** 또는 **`top`/`htop`**을 실행하여 시스템의 전반적인 상태를 실시간으로 관찰합니다.
2.  **CPU 병목 의심**:
    - `vmstat`의 `r` 값이 CPU 코어 수보다 지속적으로 높다.
    - `vmstat`의 `id` 값이 0에 가깝고, `us` 또는 `sy` 값이 높다.
    - → `top`이나 `perf` 같은 도구로 어떤 프로세스가 CPU를 많이 사용하는지 상세 분석합니다.
3.  **메모리 병목 의심**:
    - `vmstat`의 `si`, `so` 값이 지속적으로 0이 아니다.
    - `free -h` 명령으로 확인 시 사용 가능한 메모리가 거의 없다.
    - → `top`이나 `ps`로 메모리를 많이 사용하는 프로세스를 찾아내고, 메모리 증설이나 애플리케이션 튜닝을 고려합니다.
4.  **디스크 I/O 병목 의심**:
    - `vmstat`의 `wa` 값이 지속적으로 높다.
    - `iostat -x`의 `%util` 값이 100%에 가깝거나 `await` 값이 매우 높다.
    - → `iotop` 같은 도구로 어떤 프로세스가 디스크 I/O를 유발하는지 확인하고, 디스크 성능 개선(SSD 교체, RAID 구성)이나 쿼리 튜닝 등을 고려합니다.

이처럼 여러 도구를 종합적으로 사용하여 시스템의 상태를 입체적으로 분석함으로써, 성능 문제의 원인이 어디에 있는지 체계적으로 좁혀 나갈 수 있습니다.
