# 2-1-2: 파일 시스템 탐색과 검색

리눅스의 계층적인 파일 시스템을 자유롭게 돌아다니고, 원하는 파일을 빠르게 찾아내는 것은 CLI 작업의 효율을 결정하는 중요한 능력입니다. 이번 장에서는 위치를 확인하고, 이동하고, 검색하는 명령어들을 배웁니다.

## 1. 위치 확인 및 이동 (`pwd`, `cd`)

이 두 명령어는 이전 장에서 배운 가장 기본적인 탐색 명령어입니다. 다시 한번 핵심을 짚어봅시다.

- **`pwd` (Print Working Directory)**: "내가 지금 어디에 있지?"를 확인하는 명령입니다. 현재 작업 중인 디렉터리의 전체 경로(절대 경로)를 보여줍니다.

- **`cd` (Change Directory)**: 다른 디렉터리로 작업 위치를 옮기는 명령입니다. `cd` 명령어의 핵심은 **경로(Path)**의 개념을 이해하는 것입니다.

### 절대 경로와 상대 경로

- **절대 경로 (Absolute Path)**
    - **정의**: 최상위 디렉터리인 **루트(`/`)**부터 시작하는 전체 경로입니다.
    - **특징**: 내가 현재 어느 위치에 있든 상관없이 항상 동일한 위치를 가리킵니다.
    - **예시**: `cd /home/user/Documents`, `ls /var/log`

- **상대 경로 (Relative Path)**
    - **정의**: **현재 나의 위치**를 기준으로 상대적인 경로를 나타냅니다.
    - **특징**: 현재 위치에 따라 대상이 달라집니다.
    - **예시**: 내가 `/home/user`에 있을 때, `cd Documents`는 `/home/user/Documents`로 이동하라는 의미입니다.

### 특수 디렉터리 기호

상대 경로와 함께 사용하면 매우 편리한 기호들입니다.

- `.` (점 하나): **현재 디렉터리**를 의미합니다.
- `..` (점 두 개): 바로 위 **부모 디렉터리**를 의미합니다. (`cd ../..`는 두 단계 위로 올라갑니다.)
- `~` (틸드): 현재 로그인한 **사용자의 홈 디렉터리**를 의미합니다. (`/home/username`의 단축 표현)
- `-` (하이픈): 바로 **이전에 있었던 디렉터리**를 의미합니다. `cd -` 명령은 두 디렉터리를 번갈아 이동할 때 매우 유용합니다.

## 2. 실시간 검색: `find`

- **기능**: 지정된 위치부터 시작하여 하위 디렉터리까지 모두 탐색하며, 다양한 조건에 맞는 파일이나 디렉터리를 **실시간으로** 찾아주는 강력한 검색 도구입니다.
- **기본 문법**: `find [검색 시작 위치] [조건 표현식]`

- **주요 조건 표현식**:
    - `-name "패턴"`: 지정된 이름 패턴에 맞는 파일을 찾습니다. 와일드카드(`*`)를 사용할 수 있으며, 셸이 먼저 해석하는 것을 막기 위해 따옴표로 감싸는 것이 좋습니다.
    - `-type [f|d]`: 파일의 종류를 지정합니다. `f`는 일반 파일(file), `d`는 디렉터리(directory)를 의미합니다.
    - `-user <사용자명>`: 특정 사용자가 소유한 파일을 찾습니다.
    - `-mtime [-일수|+일수]`: 지정된 일수 이내/이전에 수정된 파일을 찾습니다. (예: `-mtime -7`은 최근 7일 내에 수정된 파일)

- **사용 예시**:
    ```bash
    # 현재 디렉터리(.) 및 하위에서 'report.txt'라는 이름의 파일을 검색
    $ find . -name "report.txt"

    # /etc 디렉터리 아래에서 '.conf'로 끝나는 모든 파일을 검색
    $ find /etc -name "*.conf"

    # 현재 디렉터리 아래에서 이름이 'logs'인 디렉터리를 검색
    $ find . -type d -name "logs"

    # /home 디렉터리 아래에서 최근 24시간 내에 수정된 파일을 검색
    $ find /home -mtime -1
    ```

## 3. 초고속 검색: `locate`

- **기능**: 파일 시스템을 미리 스캔하여 만들어 둔 **데이터베이스**를 검색하여, 파일이나 디렉터리의 위치를 매우 빠르게 찾아줍니다.
- **동작 원리**: `updatedb`라는 프로그램이 주기적으로(보통 하루에 한 번) 시스템의 모든 파일 목록을 데이터베이스에 갱신합니다. `locate`는 이 데이터베이스를 참조하므로 디스크를 직접 읽는 `find`보다 월등히 빠릅니다.

- **장점**: 검색 속도가 매우 빠릅니다.
- **단점**: 방금 생성하거나 위치를 옮긴 파일은 데이터베이스가 갱신되기 전까지 검색되지 않습니다.

- **사용 예시**:
    ```bash
    # 시스템 전체에서 'httpd.conf'라는 이름이 포함된 모든 경로를 검색
    $ locate httpd.conf

    # 데이터베이스를 수동으로 지금 바로 갱신 (root 권한 필요)
    $ sudo updatedb
    ```

## 4. `find` 와 `locate` 비교

| 특징 | `find` | `locate` |
| :--- | :--- | :--- |
| **검색 방식** | 실시간으로 파일 시스템을 직접 스캔 | 미리 생성된 데이터베이스 조회 |
| **속도** | 느림 (특히 검색 범위가 넓을 때) | 매우 빠름 |
| **정확도** | 항상 현재 상태를 정확히 반영 | DB 갱신 시점 기준 (실시간 X) |
| **검색 옵션** | 이름, 종류, 크기, 날짜, 권한 등 매우 다양 | 오직 이름으로만 검색 가능 |
| **자원 사용** | 검색 시 디스크 I/O 부하 발생 | CPU 및 메모리 부하 적음 |

> **언제 무엇을 쓸까?**
> - **`locate`**: 파일 이름만 알고 있고, 시스템 전체에서 빠르게 위치를 찾고 싶을 때.
> - **`find`**: 특정 디렉터리 안에서, 이름 외에 다양한 조건(수정한 날짜, 크기 등)으로 파일을 정밀하게 찾고 싶을 때, 또는 실시간 정보가 반드시 필요할 때.
