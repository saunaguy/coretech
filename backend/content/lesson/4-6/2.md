# 4-6-2: 패킷 캡처/분석: `tcpdump`/Wireshark, pcap

네트워크 문제를 해결하는 가장 확실하고 근본적인 방법은 네트워크를 오가는 실제 데이터, 즉 **패킷(Packet)**을 직접 들여다보는 것입니다. 패킷 캡처 및 분석은 애플리케이션이 예상과 다르게 동작하거나, 원인을 알 수 없는 통신 오류가 발생할 때, "실제로는 무슨 일이 일어나고 있는가"를 보여주는 최후의 수단이자 가장 강력한 도구입니다.

## 1. `tcpdump`: 커맨드라인 패킷 캡처

- **기능**: `tcpdump`는 리눅스 서버의 네트워크 인터페이스를 통과하는 패킷을 실시간으로 캡처하여, 그 요약 정보를 터미널에 출력하거나 파일로 저장하는 커맨드라인 도구입니다. (자세한 사용법은 `2-4-8` 참고)
- **주요 역할**: GUI 환경이 없는 원격 서버에서 즉시 패킷을 캡처하여 파일(`.pcap`)로 저장하는 역할을 담당합니다.

- **캡처 시나리오**: 웹 서버(`10.0.0.10`)에서 간헐적으로 연결 오류가 발생한다. 클라이언트(`1.2.3.4`)와의 통신 내용을 캡처하여 분석하고 싶다.

- **사용법**:
  ```bash
  # eth0 인터페이스에서, 출발지 또는 목적지가 1.2.3.4이고 80번 포트를 사용하는 모든 패킷을 캡처하여
  # web_traffic.pcap 파일로 저장 (-w)
  # -s 0 옵션은 패킷 전체를 잘리지 않고 저장하라는 의미
  sudo tcpdump -i eth0 -s 0 -w web_traffic.pcap host 1.2.3.4 and port 80
  ```
  - 위 명령을 실행해 둔 상태에서 클라이언트가 접속을 시도하면, 관련된 모든 패킷이 `web_traffic.pcap` 파일에 기록됩니다. `Ctrl+C`를 눌러 캡처를 중지합니다.

## 2. `pcap` 파일

- **개념**: `pcap`(Packet Capture)은 `tcpdump`, `Wireshark` 등 대부분의 네트워크 분석 도구에서 사용하는 표준 패킷 캡처 파일 형식입니다. 캡처된 패킷들의 원본 데이터를 시간 정보와 함께 그대로 담고 있습니다.
- **활용**: `tcpdump`로 원격 서버에서 `pcap` 파일을 생성한 뒤, 이 파일을 분석가의 PC로 가져와 `Wireshark`와 같은 그래픽 분석 도구로 열어 상세하게 분석하는 것이 일반적인 워크플로우입니다.

## 3. Wireshark: 그래픽 패킷 분석의 최강자

- **기능**: Wireshark는 `pcap` 파일을 열어, 각 패킷의 모든 계층(이더넷, IP, TCP/UDP, HTTP 등)별 헤더와 데이터를 상세하게 보여주고, 강력한 필터링과 통계 기능을 제공하는 GUI 기반의 네트워크 프로토콜 분석기입니다.

- **Wireshark 기본 분석 화면**:
    1.  **패킷 목록 (Packet List Pane)**: 캡처된 패킷들이 시간순으로 한 줄씩 요약되어 표시됩니다. (No., Time, Source, Destination, Protocol, Length, Info)
    2.  **패킷 상세 (Packet Details Pane)**: 목록에서 특정 패킷을 선택하면, 해당 패킷의 모든 프로토콜 계층(Frame, Ethernet, IP, TCP, HTTP 등)을 트리 구조로 상세하게 보여줍니다. 각 헤더의 필드 값을 하나하나 확인할 수 있습니다.
    3.  **패킷 바이트 (Packet Bytes Pane)**: 패킷의 실제 데이터(16진수 및 아스키 코드)를 보여줍니다.

### Wireshark를 이용한 트러블슈팅 예시

- **느린 웹사이트 접속 원인 분석**:
    - **필터링**: `http.request or http.response` 필터를 사용하여 HTTP 요청과 응답만 봅니다.
    - **분석**: 특정 요청에 대한 응답이 오기까지 시간이 오래 걸리는 것을 확인합니다. `Time` 컬럼을 통해 지연 시간을 측정합니다. TCP 계층을 분석하여, `TCP Retransmission`(재전송)이나 `TCP Zero Window`(수신 버퍼가 가득 참)와 같은 메시지가 많이 보인다면, 이는 네트워크 중간의 패킷 손실이나 서버의 부하가 원인일 수 있음을 시사합니다.

- **TCP 3-way Handshake 실패 분석**:
    - **필터링**: `tcp.flags.syn == 1 and tcp.flags.ack == 0` (Client의 첫 SYN 요청)
    - **분석**: 클라이언트가 SYN 패킷을 보냈는데, 서버로부터 SYN/ACK 응답이 전혀 오지 않는다면, 서버에 도달하기 전의 방화벽이 패킷을 차단했거나 서버의 해당 포트가 닫혀있을 가능성이 높습니다. 만약 서버가 SYN/ACK를 보냈는데 클라이언트가 마지막 ACK를 보내지 않는다면, 클라이언트 측의 문제일 수 있습니다.

- **HTTP Follow TCP Stream**: 특정 TCP 연결에 속한 모든 데이터를 시간순으로 재조립하여, 실제 애플리케이션(예: HTTP)이 주고받은 대화 내용을 그대로 보여주는 매우 유용한 기능입니다. 암호화되지 않은 통신의 경우, 주고받은 요청과 응답의 본문을 모두 확인할 수 있습니다.

패킷 분석은 네트워크의 가장 낮은 수준에서 일어나는 일을 직접 눈으로 확인하는 과정입니다. `tcpdump`로 증거를 수집하고, Wireshark로 그 증거를 과학적으로 분석함으로써, 다른 어떤 방법으로도 해결하기 어려운 복잡한 네트워크 문제의 근본 원인을 규명할 수 있습니다.
