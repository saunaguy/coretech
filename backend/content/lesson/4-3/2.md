# 4-3-2: `firewalld` 존/서비스, 리치 규칙

`iptables`나 `nftables`는 매우 강력하지만, 규칙을 하나하나 직접 관리하기에는 복잡하고 실수의 여지가 많습니다. `firewalld`는 이러한 복잡성을 추상화하고, **Zone(영역)**과 **Service(서비스)**라는 개념을 통해 더 쉽고 직관적으로 방화벽을 관리할 수 있게 해주는 고수준 방화벽 관리 도구입니다. RHEL/CentOS 계열의 기본 방화벽입니다.

## 1. Zone (영역)의 개념

- **개념**: Zone은 서버가 처한 네트워크 환경에 대한 신뢰 수준을 나타내는 미리 정의된 규칙의 집합입니다. 서버의 네트워크 인터페이스를 특정 Zone에 할당하면, 해당 Zone에 설정된 방화벽 규칙이 그 인터페이스에 적용됩니다.

- **주요 기본 Zone**:
    - **`public`**: 기본값으로 사용되는 Zone. 외부 네트워크(인터넷)에 연결된 인터페이스에 적합합니다. 기본적으로 신뢰하지 않는 연결로 간주하며, 꼭 필요한 서비스(예: `ssh`) 외에는 대부분 차단합니다.
    - **`internal`**: 내부 네트워크 환경에 사용됩니다. `public` Zone보다 더 많은 서비스를 허용하는 등 상대적으로 신뢰도가 높게 설정되어 있습니다.
    - **`trusted`**: Zone 안의 모든 트래픽을 허용합니다. 매우 안전하다고 확신하는 네트워크 환경에서만 사용해야 합니다.
    - **`dmz` (Demilitarized Zone)**: 외부로 서비스를 제공해야 하지만, 내부 네트워크와는 격리되어야 하는 서버(예: 웹 서버)를 위한 Zone입니다.
    - **`drop`**, **`block`**: 들어오는 모든 패킷을 거부합니다. `drop`은 조용히 패킷을 버리고, `block`은 거부 응답(ICMP)을 보냅니다.

- **Zone 관리 명령어 (`firewall-cmd`)**:
  ```bash
  # 기본으로 설정된 Zone 확인
  firewall-cmd --get-default-zone

  # 활성화된 모든 Zone과 할당된 인터페이스 확인
  firewall-cmd --get-active-zones

  # eth1 인터페이스를 internal Zone으로 변경 (영구적으로)
  sudo firewall-cmd --zone=internal --change-interface=eth1 --permanent
  ```

## 2. Service (서비스)와 Port (포트)

`firewalld`에서는 특정 포트 번호를 직접 다루는 대신, `http`(80/tcp), `ssh`(22/tcp)와 같이 미리 정의된 **서비스(Service)** 이름을 사용하여 규칙을 추가하는 것을 권장합니다. 이는 규칙을 더 이해하기 쉽게 만들어 줍니다.

- **서비스/포트 관리 명령어 (`firewall-cmd`)**:
  ```bash
  # 사용 가능한 모든 서비스 목록 보기
  firewall-cmd --get-services

  # public Zone에 http 서비스를 추가 (일시적)
  sudo firewall-cmd --zone=public --add-service=http

  # public Zone에 https 서비스를 영구적으로 추가
  sudo firewall-cmd --zone=public --add-service=https --permanent

  # public Zone에서 ssh 서비스를 영구적으로 제거
  sudo firewall-cmd --zone=public --remove-service=ssh --permanent

  # 8080/tcp 포트를 직접 추가 (미리 정의된 서비스가 없을 경우)
  sudo firewall-cmd --zone=public --add-port=8080/tcp --permanent

  # 변경된 영구 규칙을 적용하기 위해 리로드
  sudo firewall-cmd --reload
  ```
  - `--permanent` 옵션으로 추가/삭제한 규칙은 `--reload`를 실행해야만 현재 시스템에 적용됩니다.

## 3. 리치 규칙 (Rich Rules): 세밀한 제어

Zone과 Service 기반의 규칙만으로 표현하기 어려운 복잡하고 세밀한 규칙이 필요할 때 **리치 규칙(Rich Rule)**을 사용합니다. 리치 규칙은 `iptables`처럼 출발지/목적지 주소, 프로토콜, 포트 등을 조합하여 정교한 규칙을 만들 수 있게 해줍니다.

- **리치 규칙 문법**:
  `rule family="..." source address="..." service name="..." [log] [audit] [accept|reject|drop]`

- **시나리오**: `192.168.1.0/24` 네트워크 대역에서 들어오는 `http` 서비스 요청만 허용하고, 다른 모든 IP에서의 `http` 요청은 차단하고 싶다.

- **해결 방법**:
  1.  먼저 `public` Zone에서 `http` 서비스를 제거하여 기본적으로 차단되도록 합니다.
      `sudo firewall-cmd --zone=public --remove-service=http --permanent`
  2.  리치 규칙을 사용하여 특정 대역만 허용합니다.
      ```bash
      sudo firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" service name="http" accept' --permanent
      ```
  3.  규칙을 적용합니다.
      `sudo firewall-cmd --reload`

- **리치 규칙 확인**:
  `firewall-cmd --zone=public --list-rich-rules`

`firewalld`는 Zone이라는 개념을 통해 서버의 보안 정책을 네트워크 환경에 따라 동적으로 변경할 수 있게 하고, 서비스와 리치 규칙을 통해 직관적이면서도 유연한 규칙 관리를 가능하게 합니다. `iptables`의 복잡한 체인과 규칙 순서를 직접 다루지 않아도 되므로, 대부분의 방화벽 관리 작업에서 생산성과 안정성을 크게 높여줍니다.
