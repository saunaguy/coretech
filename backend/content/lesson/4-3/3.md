# 4-3-3: SSH 하드닝, 포트포워딩/프록시점프, `fail2ban`

SSH는 서버 원격 관리의 핵심 통로이므로, 이곳의 보안을 강화하는 것은 전체 시스템 보안의 첫걸음입니다. SSH 자체의 설정을 강화하는 **하드닝(Hardening)**, SSH의 터널링 기능을 활용한 고급 접속 방법, 그리고 자동화된 공격을 차단하는 `fail2ban`에 대해 알아봅니다.

## 1. SSH 하드닝 (Hardening)

(이 내용은 `3-1-6`에서 다루었지만, 네트워크 보안 관점에서 다시 한번 정리합니다.)

`/etc/ssh/sshd_config` 파일을 수정하여 SSH 서버의 보안 수준을 높이는 작업입니다.

- **핵심 하드닝 지침**:
    1.  **루트 로그인 금지**: `PermitRootLogin no`
        - 공격자가 `root` 계정을 직접 목표로 삼는 것을 방지합니다. 항상 일반 계정으로 로그인 후 `sudo`를 사용합니다.
    2.  **공개키 인증만 허용**: `PasswordAuthentication no`
        - 무차별 대입 공격(brute-force attack)에 취약한 비밀번호 인증을 비활성화하고, 훨씬 더 안전한 공개키 기반 인증만 사용합니다.
    3.  **특정 사용자/그룹만 허용**: `AllowUsers` 또는 `AllowGroups`
        - SSH 접속이 허가된 사용자를 명시적으로 지정하여, 허가되지 않은 계정의 접속 시도를 원천 차단합니다.
    4.  **기본 포트 변경**: `Port 2222`
        - 자동화된 봇들이 주로 스캔하는 22번 포트 대신 다른 포트를 사용하여 불필요한 공격 시도를 줄입니다.
    5.  **프로토콜 버전 2만 사용**: `Protocol 2`
        - 보안 취약점이 있는 구버전 SSH 프로토콜 1의 사용을 금지합니다.

## 2. SSH 터널링: 포트 포워딩과 프록시 점프

SSH는 단순히 원격 셸을 제공하는 것을 넘어, 두 지점 간에 암호화된 터널을 만들어 다른 네트워크 트래픽을 안전하게 전달하는 강력한 터널링 기능을 가지고 있습니다.

### 로컬 포트 포워딩 (`-L`)
- **기능**: 원격 서버가 접근할 수 있는 특정 포트를, 내 로컬 PC의 포트와 연결합니다.
- **시나리오**: 회사 내부망에 있는 데이터베이스 서버(`db.internal:3306`)에 내 로컬 PC에서 직접 접속하고 싶다. 외부에서는 DB 서버에 직접 접근할 수 없고, 오직 SSH 접속이 가능한 `bastion.mycompany.com` 서버를 통해서만 접근할 수 있다.

- **사용법**:
  ```bash
  # 내 로컬 PC의 3307번 포트로 들어오는 모든 요청을,
  # bastion.mycompany.com 서버를 통해 db.internal:3306으로 전달
  ssh -L 3307:db.internal:3306 user@bastion.mycompany.com
  ```
  - 위 명령을 실행한 상태에서, 내 로컬 PC의 DB 클라이언트로 `localhost:3307`에 접속하면, 실제로는 `db.internal:3306`에 안전하게 접속됩니다.

### 프록시 점프 (`-J`, ProxyJump)
- **기능**: 중간에 있는 서버(점프 호스트, 베스천 호스트)를 거쳐 최종 목적지 서버에 한 번에 접속하게 해주는 기능입니다. 로컬 포트 포워딩보다 더 직관적이고 편리합니다.
- **시나리오**: 내부망에 있는 `private-server`에 접속하고 싶다. 외부에서는 `bastion-host`에만 접속이 가능하다.

- **사용법**:
  ```bash
  # bastion-host를 거쳐 private-server에 접속
  ssh -J user@bastion-host user@private-server
  ```
- **`~/.ssh/config` 파일을 이용한 설정**: 자주 사용하는 점프 호스트는 `config` 파일에 미리 설정해두면 매우 편리합니다.
  ```
  Host bastion
      HostName bastion.mycompany.com
      User admin

  Host private-app
      HostName 10.0.1.100
      User app_user
      ProxyJump bastion
  ```
  - 위와 같이 설정하면, `ssh private-app`이라는 간단한 명령만으로 자동으로 `bastion` 호스트를 거쳐 접속됩니다.

## 3. `fail2ban`: 자동화된 침입 방지

- **기능**: `fail2ban`은 시스템의 로그 파일(예: `/var/log/secure`, `/var/log/auth.log`)을 실시간으로 감시하여, 짧은 시간 안에 반복적으로 로그인에 실패하는 등 비정상적인 접근을 시도하는 IP 주소를 찾아내어 방화벽(`iptables` 또는 `firewalld`)을 통해 자동으로 차단하는 침입 방지 소프트웨어입니다.

- **동작 원리**:
    1.  **Jail 설정**: `/etc/fail2ban/jail.local` 파일에 어떤 로그 파일을 감시하고(logpath), 어떤 패턴(filter)을 찾으며, 몇 번 이상(maxretry) 발생 시 얼마 동안(bantime) 차단할지를 정의합니다. (이를 "Jail"이라고 부릅니다.)
    2.  **로그 감시**: `fail2ban` 서비스가 실행되면, 정의된 로그 파일을 계속 감시합니다.
    3.  **패턴 매칭**: 로그인 실패와 같은 특정 로그 패턴이 감지되면 내부 카운터를 증가시킵니다.
    4.  **차단 실행**: `maxretry` 횟수를 초과하면, `fail2ban`은 방화벽(`iptables` 등)에 해당 IP 주소를 차단하는 규칙을 자동으로 추가합니다.
    5.  **차단 해제**: `bantime`이 지나면 방화벽에서 차단 규칙을 자동으로 삭제합니다.

- **SSH를 위한 `fail2ban` 설정 예시 (`/etc/fail2ban/jail.local`)**:
  ```ini
  [sshd]
  enabled = true
  port    = ssh
  logpath = %(sshd_log)s
  maxretry = 5
  bantime  = 3600
  ```
  - 위 설정은 1시간(`3600`초) 동안 SSH 로그인에 5번 실패한 IP를 차단합니다.

SSH 하드닝으로 기본적인 방어력을 갖추고, `fail2ban`으로 자동화된 공격을 막으며, SSH 터널링을 통해 내부 자원에 안전하게 접근하는 이 세 가지 전략은 현대적인 서버 관리 환경에서 필수적인 보안 실천 방법입니다.
