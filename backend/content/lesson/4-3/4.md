# 4-3-4: TLS/인증서 기초, OCSP/ALPN/HSTS

HTTPS, 즉 HTTP over TLS(Transport Layer Security)는 현대 웹 통신의 표준입니다. TLS는 클라이언트와 서버 간의 통신을 암호화하여 중간에서 데이터를 가로채거나 변조하는 것을 방지합니다. 이 TLS 통신의 핵심에는 **TLS/SSL 인증서**가 있습니다.

## 1. TLS/SSL 인증서의 역할과 원리

- **인증서(Certificate)**: 웹사이트(서버)가 신뢰할 수 있음을 증명하는 일종의 디지털 신분증입니다. 인증서에는 다음과 같은 정보가 포함됩니다.
    - **서버의 도메인 이름** (예: `www.google.com`)
    - **서버의 공개키(Public Key)**
    - **인증서를 발급한 기관(CA, Certificate Authority)**의 정보 및 전자서명

- **TLS 핸드셰이크(Handshake) 과정 (간략)**:
    1.  **Client Hello**: 클라이언트(웹 브라우저)가 서버에 접속하며, 자신이 사용 가능한 TLS 버전과 암호화 방식(Cipher Suite) 목록을 서버에 알립니다.
    2.  **Server Hello**: 서버는 클라이언트의 제안 중 하나를 선택하여 응답하고, 자신의 **TLS 인증서**를 클라이언트에게 전달합니다.
    3.  **인증서 검증**: 클라이언트는 서버로부터 받은 인증서를 신뢰할 수 있는지 검증합니다.
        a.  인증서의 도메인 이름이 현재 접속하려는 사이트와 일치하는지 확인합니다.
        b.  인증서가 만료되지 않았는지 확인합니다.
        c.  인증서를 발급한 **CA가 신뢰할 수 있는 기관인지** 확인합니다. (브라우저나 운영체제는 신뢰할 수 있는 CA 목록을 미리 내장하고 있습니다.)
        d.  CA의 공개키를 사용하여 인증서의 전자서명을 검증함으로써, 인증서가 변조되지 않았음을 확인합니다.
    4.  **키 교환**: 인증서 검증이 완료되면, 클라이언트는 앞으로 통신을 암호화하는 데 사용할 **대칭키(Symmetric Key)**를 생성합니다. 그리고 이 대칭키를 서버 인증서에 포함된 **서버의 공개키**로 암호화하여 서버에 전달합니다.
    5.  **암호화 통신 시작**: 서버는 자신의 **개인키(Private Key)**로 암호화된 대칭키를 복호화하여 얻습니다. 이제 클라이언트와 서버는 동일한 대칭키를 공유하게 되었으므로, 이 키를 사용하여 모든 통신 내용을 암호화하고 복호화합니다.

## 2. 고급 TLS 개념

### OCSP (Online Certificate Status Protocol)
- **개념**: 인증서가 **폐지(Revoked)**되었는지 실시간으로 확인하는 프로토콜입니다. 인증서는 만료일 이전이라도 개인키 유출 등의 이유로 폐지될 수 있습니다. 기존의 CRL(Certificate Revocation List) 방식보다 더 빠르고 효율적입니다.
- **OCSP Stapling**: 서버가 직접 자신의 인증서에 대한 OCSP 응답을 CA로부터 주기적으로 받아두었다가, TLS 핸드셰이크 과정에서 인증서와 함께 클라이언트에게 전달하는 기술입니다. 이를 통해 클라이언트가 직접 CA에 OCSP 요청을 보내는 부담을 줄여 성능을 향상시킵니다.

### ALPN (Application-Layer Protocol Negotiation)
- **개념**: TLS 핸드셰이크 과정에서, 클라이언트와 서버가 어떤 **응용 계층 프로토콜(예: HTTP/2, HTTP/1.1)**을 사용할지 협상할 수 있게 해주는 TLS 확장 기능입니다.
- **동작**: 클라이언트가 Client Hello 메시지에 자신이 지원하는 프로토콜 목록(예: `h2`, `http/1.1`)을 담아 보내면, 서버가 그중 하나를 선택하여 Server Hello 메시지로 응답합니다. 이를 통해 클라이언트는 추가적인 RTT(Round Trip Time) 없이 처음부터 HTTP/2와 같은 최신 프로토콜로 통신을 시작할 수 있습니다.

### HSTS (HTTP Strict Transport Security)
- **개념**: 웹 브라우저가 특정 웹사이트에 접속할 때, 무조건 **HTTPS로만 접속하도록 강제**하는 보안 정책입니다.
- **동작**: 서버는 HTTP 응답 헤더에 `Strict-Transport-Security` 헤더를 포함하여 보냅니다.
  `Strict-Transport-Security: max-age=31536000; includeSubDomains`
  - 이 헤더를 한 번이라도 받은 브라우저는, `max-age`에 지정된 시간(초 단위) 동안 해당 도메인(및 `includeSubDomains`가 있으면 하위 도메인 포함)에 대해 `http://`로 접속을 시도하더라도 자동으로 `https://`로 전환하여 접속합니다.
- **효과**: 사용자가 실수로 HTTP로 접속하거나, SSL 스트리핑(Stripping)과 같은 중간자 공격을 통해 암호화되지 않은 HTTP로 다운그레이드되는 것을 방지하여 통신의 보안을 강화합니다.

이러한 TLS의 기본 원리와 확장 기능들은 안전하고 효율적인 최신 웹 서비스를 구축하고 운영하는 데 있어 반드시 이해해야 할 핵심적인 네트워크 보안 기술입니다.
