# 2-3-5: 로깅 (`journalctl`, `rsyslog` 기본)

리눅스 시스템은 발생하는 모든 이벤트(부팅, 사용자 로그인, 서비스 시작/종료, 오류 등)를 기록으로 남깁니다. 이 기록을 **로그(Log)**라고 하며, 시스템의 상태를 파악하고 문제를 해결하는 데 가장 중요한 정보 소스입니다.

## 1. `systemd-journald`와 `journalctl`

최신 리눅스 배포판은 대부분 `systemd`를 사용하며, `systemd-journald` 데몬이 시스템의 모든 로그를 중앙에서 수집하고 관리합니다. 이 로그는 텍스트가 아닌 바이너리 형식으로 저장되어 더 빠르고 구조적인 검색이 가능합니다.

`journalctl`은 `systemd-journald`가 수집한 로그를 조회하고 분석하는 강력한 명령어입니다.

### 주요 `journalctl` 사용법

- **전체 로그 보기**:
  ```bash
  journalctl
  ```
  (가장 오래된 로그부터 보여줍니다. `less`와 동일한 방식으로 탐색 가능: `Space`로 페이지 다운, `b`로 페이지 업, `g`로 처음, `G`로 끝, `/`로 검색, `q`로 종료)

- **최신 로그 실시간 확인**:
  ```bash
  journalctl -f
  ```
  (`tail -f`와 유사하게 새로운 로그가 추가될 때마다 화면에 출력됩니다.)

- **최근 로그 N줄만 보기**:
  ```bash
  journalctl -n 20
  ```
  (최근 20개의 로그 라인을 보여줍니다.)

- **특정 시간대 로그 필터링**:
  ```bash
  # 어제부터 발생한 로그
  journalctl --since "yesterday"

  # 특정 시간 사이의 로그
  journalctl --since "2025-09-25 10:00:00" --until "2025-09-25 11:00:00"
  ```

- **특정 유닛(서비스)의 로그만 보기**:
  ```bash
  # sshd 서비스의 로그만 확인
  journalctl -u sshd.service

  # nginx 서비스의 최근 50개 로그를 실시간으로 확인
  journalctl -u nginx -n 50 -f
  ```

- **특정 프로세스 ID(PID)의 로그 보기**:
  ```bash
  journalctl _PID=1234
  ```

- **커널 메시지(dmesg와 유사)만 보기**:
  ```bash
  journalctl -k
  ```

- **로그 수준(Priority)으로 필터링**:
  로그 수준은 0(emerg)부터 7(debug)까지 있으며, 특정 수준 이상의 로그만 볼 수 있습니다.
  ```bash
  # "err" (error, 수준 3) 이상의 심각한 로그만 보기
  journalctl -p err

  # "warning" (수준 4) 이상의 로그 보기
  journalctl -p warning
  ```

## 2. `rsyslog`: 전통적인 로그 관리자

`rsyslog`는 오랫동안 사용되어 온 표준 로그 관리 시스템입니다. 파일 기반으로 로그를 관리하며, 네트워크를 통해 다른 서버로 로그를 전송하는 등 강력한 기능을 갖추고 있습니다.

`systemd` 환경에서도 `rsyslog`는 `journald`로부터 로그를 전달받아 `/var/log` 디렉터리 아래의 여러 파일에 저장하는 역할을 계속 수행하는 경우가 많습니다.

### `rsyslog`의 주요 로그 파일 (`/var/log`)

- `/var/log/messages`: 시스템 전반의 주요 메시지. 가장 먼저 확인하게 되는 로그 파일 중 하나입니다. (Debian/Ubuntu 계열에서는 `/var/log/syslog`)
- `/var/log/secure`: 보안 및 인증 관련 로그 (로그인 시도, `sudo` 사용 등). (Debian/Ubuntu 계열에서는 `/var/log/auth.log`)
- `/var/log/cron`: `cron` 데몬이 실행한 작업에 대한 로그.
- `/var/log/dmesg`: 부팅 시 출력되는 커널 메시지.
- `/var/log/boot.log`: 시스템 부팅 과정에 대한 로그.

이 파일들은 일반 텍스트 파일이므로 `cat`, `less`, `grep`, `tail` 등의 명령어로 내용을 확인할 수 있습니다.

```bash
# /var/log/messages 파일의 마지막 20줄 확인
tail -n 20 /var/log/messages

# /var/log/secure 파일에서 "Failed password" 문자열이 포함된 줄 검색
grep "Failed password" /var/log/secure
```

## `journalctl` vs `rsyslog` 파일

| 특징 | `journalctl` | `/var/log` 파일 (`rsyslog`) |
| --- | --- | --- |
| **데이터 형식** | 바이너리 (구조화) | 플레인 텍스트 |
| **관리 주체** | `systemd-journald` | `rsyslogd` |
| **조회 도구** | `journalctl` | `cat`, `less`, `grep`, `tail` 등 |
| **중앙 관리** | 모든 로그를 한 곳에서 관리 | 서비스/기능별로 파일 분리 |
| **필터링** | 강력하고 다양한 조건 (시간, 유닛, 심각도 등) | `grep` 등 텍스트 검색 도구에 의존 |
| **로그 보존** | 기본적으로 재부팅 시 사라질 수 있음 (설정으로 영구 저장 가능) | 파일로 저장되어 영구 보존 |

**결론**: 시스템의 현재 상태나 특정 서비스의 동작을 빠르게 확인할 때는 `journalctl`이 매우 효율적입니다. 반면, 로그를 장기간 보관하거나 다른 시스템으로 전송하고, 텍스트 기반으로 분석해야 할 때는 `rsyslog`와 `/var/log`의 파일들이 여전히 중요한 역할을 합니다. 현대 시스템에서는 이 두 가지가 상호 보완적으로 함께 사용되는 경우가 많습니다.
