# 2-3-6: 시간 동기화 (`chrony`, `ntpd`)

분산 환경과 네트워크로 연결된 현대 컴퓨터 시스템에서 **정확한 시간**은 매우 중요합니다. 로그 파일의 타임스탬프, 데이터베이스 트랜잭션, 인증 시스템(Kerberos 등) 등 많은 요소들이 시스템 간의 시간이 일치한다고 가정하고 동작하기 때문입니다. 시간이 틀어지면 원인 불명의 오류가 발생하거나 보안에 허점이 생길 수 있습니다.

리눅스에서는 **NTP(Network Time Protocol)**를 사용하여 네트워크를 통해 신뢰할 수 있는 시간 서버와 시간을 동기화합니다. 이를 위한 서비스 데몬으로 전통적으로 `ntpd`가 사용되었고, 최근에는 `chrony`가 많이 사용됩니다.

## 1. `chrony`: 현대적인 NTP 구현체

`chrony`는 `ntpd`에 비해 더 빠르고 정확하게 시간을 동기화하도록 설계되었습니다. 특히, 인터넷 연결이 불안정하거나 간헐적으로 연결되는 시스템(노트북, 가상 머신 등)에서도 더 나은 성능을 보입니다.

- **패키지**: `chrony`
- **서비스 데몬**: `chronyd`
- **명령어**: `chronyc`

### 주요 `chronyc` 명령어

- **동기화 상태 확인**:
  ```bash
  chronyc tracking
  ```
  - `Reference ID`: 현재 동기화의 기준이 되는 시간 서버의 ID.
  - `Stratum`: 시간 서버의 계층. 숫자가 낮을수록 더 정확한 상위 서버입니다. (Stratum 1은 GPS나 원자 시계와 직접 연결된 서버)
  - `Last offset`: 마지막으로 측정된 로컬 시간과 원격 서버 시간의 차이.
  - `Update interval`: 동기화 주기.

- **시간 소스(서버) 목록 확인**:
  ```bash
  chronyc sources
  ```
  - `^`: 서버 모드
  - `*`: 현재 동기화 대상으로 선택된 서버(Sys.peer).
  - `+`: 동기화 대상으로 고려되는 좋은 품질의 서버.
  - `-`: 동기화 대상으로 고려되지만 품질이 낮은 서버.
  - `?`: 연결할 수 없거나 상태를 알 수 없는 서버.

- **수동으로 시간 즉시 동기화**:
  ```bash
  sudo chronyc -a makestep
  ```
  (chrony 서비스가 시작될 때 시간 오차가 크면 시스템에 무리를 주지 않기 위해 서서히 시간을 조정합니다. 이 명령은 그 과정을 무시하고 즉시 시간을 맞춥니다.)

### 설정 파일 (`/etc/chrony.conf`)

기본적으로 배포판에서 제공하는 시간 서버 풀(pool)을 사용하도록 설정되어 있습니다.

```conf
# Use public servers from the pool.ntp.org project.
# Please consider joining the pool (http://www.pool.ntp.org/join.html).
pool 2.rhel.pool.ntp.org iburst

# ... (기타 설정)
```

- `pool` 또는 `server` 지시어를 사용하여 동기화할 NTP 서버를 지정합니다.
- `iburst` 옵션은 서비스 시작 시 여러 개의 패킷을 연속으로 보내 더 빠르게 초기 동기화를 수행하도록 합니다.

## 2. `ntpd`: 전통적인 NTP 데몬

`ntpd`는 오랫동안 유닉스 계열 시스템에서 표준으로 사용되어 온 NTP 데몬입니다. 매우 안정적이지만, `chrony`에 비해 동기화 속도가 느리고 변화하는 네트워크 환경에 대한 적응성이 다소 떨어질 수 있습니다.

- **패키지**: `ntp`
- **서비스 데몬**: `ntpd`
- **명령어**: `ntpq`

### 주요 `ntpq` 명령어

- **동기화 상태 및 서버 목록 확인**:
  ```bash
  ntpq -p
  ```
  (`chronyc sources`와 유사한 정보를 보여줍니다. 출력 컬럼의 의미는 `chrony`와 거의 동일하며, `*`는 현재 동기화 대상을 의미합니다.)

### 설정 파일 (`/etc/ntp.conf`)

`chrony.conf`와 유사하게 `pool`이나 `server` 지시어로 동기화할 서버를 지정합니다.

## `chrony` vs `ntpd`

| 특징 | `chrony` | `ntpd` |
| --- | --- | --- |
| **동기화 속도** | 빠름 | 상대적으로 느림 |
| **네트워크 환경** | 불안정하거나 간헐적인 연결에 강함 | 안정적인 네트워크 연결에 적합 |
| **정확도** | 일반적으로 더 높음 | 안정적이지만 `chrony`보다 낮을 수 있음 |
| **자원 사용량** | 적음 | 상대적으로 많음 |
| **최신 배포판** | 기본 NTP 클라이언트로 채택되는 추세 (RHEL/CentOS 7+, Ubuntu 18.04+) | 여전히 사용 가능하지만 기본은 아님 |

**결론**: 특별한 이유가 없다면, 현대적인 리눅스 시스템에서는 `chrony`를 사용하는 것이 좋습니다. 더 빠르고, 가벼우며, 다양한 환경에서 더 잘 동작합니다. 시스템에 `chrony`와 `ntpd`가 모두 설치되어 있다면, 하나만 활성화하여 충돌이 발생하지 않도록 해야 합니다.

```bash
# chrony가 활성화되어 있는지 확인
sudo systemctl status chronyd

# ntpd가 활성화되어 있는지 확인
sudo systemctl status ntpd
```
