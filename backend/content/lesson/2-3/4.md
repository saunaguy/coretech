# 2-3-4: 작업 스케줄링 (`cron`, `at`, `systemd timer`)

시스템 관리자는 매일, 매주, 매월 반복되는 작업(예: 데이터 백업, 시스템 점검, 리포트 생성)을 자동화해야 합니다. 또한 특정 시간에 한 번만 실행해야 하는 작업도 있습니다. 리눅스는 이러한 작업 스케줄링을 위한 여러 도구를 제공합니다.

## 1. `cron`: 반복 작업의 대명사

- **기능**: 지정된 시간에 주기적으로 특정 명령어나 스크립트를 실행하도록 예약하는 가장 전통적이고 널리 사용되는 도구입니다. `crond`라는 데몬이 백그라운드에서 실행되며 스케줄을 관리합니다.
- **`crontab`**: "cron table"의 약자로, 스케줄링할 작업 목록이 담긴 설정 파일입니다.

- **주요 명령어**:
    - `crontab -e`: 현재 사용자의 crontab 파일을 편집합니다. (기본적으로 `vi` 에디터로 열립니다.)
    - `crontab -l`: 현재 사용자의 crontab 파일에 등록된 작업 목록을 보여줍니다.
    - `crontab -r`: 현재 사용자의 crontab 작업을 모두 삭제합니다. (주의해서 사용)

### `crontab` 문법

```
# ┌───────────── 분 (0 - 59)
# │ ┌───────────── 시 (0 - 23)
# │ │ ┌───────────── 일 (1 - 31)
# │ │ │ ┌───────────── 월 (1 - 12)
# │ │ │ │ ┌───────────── 요일 (0 - 7) (0과 7이 일요일, 1-6은 월-토)
# │ │ │ │ │
# * * * * * <실행할 명령어>
```

- **특수 문자**:
    - `*`: 모든 값을 의미 (예: 분 자리에 `*`는 "매 분마다")
    - `,`: 여러 값을 나열 (예: `0,15,30,45`)
    - `-`: 값의 범위를 지정 (예: `1-5`는 1부터 5까지)
    - `/`: 간격을 지정 (예: `*/10`은 "매 10분마다")

- **예시**:
    ```bash
    # 매일 새벽 2시 30분에 백업 스크립트 실행
    30 2 * * * /home/user/bin/backup.sh

    # 매 10분마다 시스템 상태 점검 스크립트 실행
    */10 * * * * /home/user/bin/check_status.sh > /dev/null 2>&1

    # 매주 월요일 오전 9시에 리포트 생성
    0 9 * * 1 /home/user/bin/weekly_report.sh
    ```

- **시스템 `cron`**: `/etc/crontab` 파일이나 `/etc/cron.hourly`, `/etc/cron.daily` 등의 디렉터리에 스크립트를 넣어 시스템 전체에 적용되는 작업을 등록할 수도 있습니다.

## 2. `at`: 일회성 작업 예약

- **기능**: 특정 시간에 **단 한 번만** 명령어나 스크립트를 실행하도록 예약합니다.
- **사용법**: `at <시간>`을 입력하면 `at>` 프롬프트가 나타납니다. 실행할 명령어들을 입력하고, `Ctrl + D`를 눌러 입력을 마칩니다.

- **시간 형식**: 매우 유연한 시간 형식을 지원합니다.
    - `at 10:30pm`
    - `at now + 30 minutes` (지금부터 30분 후)
    - `at 5pm tomorrow` (내일 오후 5시)
    - `at 16:00 09.25.2025` (특정 날짜 및 시간)

- **관련 명령어**:
    - `atq`: 예약된 작업 목록(Queue)을 확인합니다.
    - `atrm <작업번호>`: 예약된 작업을 삭제(Remove)합니다.

- **예시**:
    ```bash
    $ at now + 10 minutes
    at> /home/user/bin/heavy_job.sh
    at> <Ctrl+D>
    job 2 at 2025-09-24 15:00
    ```

## 3. `systemd Timers`: 현대적인 스케줄러

- **기능**: `systemd`에서 제공하는 타이머 기능으로, `cron`을 대체하는 현대적인 작업 스케줄링 방식입니다. `journalctl`을 통한 로그 통합, 더 유연한 스케줄링 등 여러 장점을 가집니다.
- **동작 원리**: 2개의 유닛 파일이 한 쌍으로 동작합니다.
    1.  `.service` 파일: **무엇을** 실행할지 정의합니다.
    2.  `.timer` 파일: **언제** 실행할지 정의합니다.

- **예시**: 매시간 정각에 `my_task.sh` 스크립트를 실행하는 타이머 만들기
    1.  `/etc/systemd/system/mytask.service` 파일 작성:
        ```ini
        [Unit]
        Description=My Hourly Task

        [Service]
        Type=oneshot
        ExecStart=/usr/local/bin/my_task.sh
        ```
    2.  `/etc/systemd/system/mytask.timer` 파일 작성:
        ```ini
        [Unit]
        Description=Run mytask.service hourly

        [Timer]
        OnCalendar=hourly  # 매시간 실행
        Persistent=true    # 재부팅 후에도 스케줄 유지

        [Install]
        WantedBy=timers.target
        ```
    3.  타이머 활성화 및 시작:
        ```bash
        $ sudo systemctl enable mytask.timer
        $ sudo systemctl start mytask.timer
        ```
- **타이머 상태 확인**: `systemctl list-timers` 명령어로 현재 활성화된 타이머와 다음 실행 시간을 확인할 수 있습니다.

### `cron` vs `systemd Timers`
- **`cron`**: 문법이 간단하고 직관적이며, 거의 모든 시스템에 있어 호환성이 좋습니다. 간단한 작업에 적합합니다.
- **`systemd Timers`**: `systemd`와 완벽하게 통합되어 로그 관리, 자원 제어, 의존성 설정 등 훨씬 더 강력하고 유연한 기능을 제공합니다. 복잡한 스케줄링이나 정교한 제어가 필요할 때 권장됩니다.
