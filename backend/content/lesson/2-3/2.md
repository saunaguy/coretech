# 2-3-2: `systemd`와 서비스 관리 (`systemctl`)

리눅스 시스템은 부팅 시점부터 웹 서버, 데이터베이스, SSH 서버 등 수많은 백그라운드 프로그램들을 실행하고 관리합니다. 이러한 백그라운드 프로그램을 **서비스(Service)** 또는 **데몬(Daemon)**이라고 부릅니다. 현대적인 리눅스 배포판은 이 모든 서비스와 시스템 전반의 동작을 **`systemd`** 라는 초기화 시스템(Init System)을 통해 관리합니다.

### `SysVinit`에서 `systemd`로
과거 Red Hat 계열 6 이하 버전에서는 `SysVinit`이라는 방식을 사용했으며, `/etc/init.d` 스크립트와 `service`, `chkconfig` 명령어로 서비스를 관리했습니다. 하지만 RHEL 7, CentOS 7, Fedora 15 이후의 모든 현대적인 Red Hat 계열 시스템은 `systemd`를 표준으로 채택했습니다. `systemd`는 병렬 처리로 부팅 속도가 빠르고, 더 강력하고 체계적인 관리 기능을 제공합니다.

## `systemctl`: `systemd`의 만능 제어 도구

`systemctl`은 `systemd`를 제어하는 중앙 관리 명령어로, 시스템의 서비스, 장치, 마운트 지점 등 모든 유닛(Unit)을 관리할 수 있습니다. 서비스 관리에 있어서는 거의 모든 작업을 `systemctl` 하나로 수행합니다.

- **기본 문법**: `sudo systemctl [명령] [서비스 이름]`
  (서비스 이름 뒤의 `.service` 확장자는 보통 생략 가능합니다.)

---

## 1. 서비스의 즉각적인 제어

이 명령어들은 현재 세션에서만 서비스의 상태를 변경합니다. 재부팅하면 원래 상태로 돌아갑니다.

- **`start`**: 서비스 시작
    ```bash
    $ sudo systemctl start httpd
    ```
- **`stop`**: 서비스 중지
    ```bash
    $ sudo systemctl stop httpd
    ```
- **`restart`**: 서비스 재시작 (중지 후 다시 시작)
    - 설정 파일을 변경한 후 적용할 때 가장 일반적으로 사용됩니다.
    ```bash
    $ sudo systemctl restart sshd
    ```
- **`reload`**: 서비스 중단 없이 설정만 다시 불러오기
    - `restart`와 달리, 서비스가 잠시라도 멈추는 것을 원치 않을 때 사용합니다. 단, 해당 서비스가 `reload` 기능을 지원해야만 합니다.
    ```bash
    $ sudo systemctl reload httpd
    ```
- **`status`**: 서비스의 현재 상태 확인 (★★가장 중요★★)
    - 서비스가 잘 실행되고 있는지, 오류는 없는지 확인할 때 가장 많이 사용하는 필수 명령어입니다.
    ```bash
    $ systemctl status firewalld
    ```
    - **출력 확인**: `Active: active (running)` 인지, `inactive (dead)` 인지, `failed` 인지를 확인하고, 하단의 로그를 통해 문제의 원인을 파악할 수 있습니다.

## 2. 부팅 시 서비스 동작 설정

서버는 재부팅되더라도 웹 서버나 DB 같은 주요 서비스들이 자동으로 실행되어야 합니다. 이와 관련된 명령어들입니다.

- **`enable`**: 시스템 부팅 시 서비스가 자동으로 시작되도록 설정
    ```bash
    $ sudo systemctl enable httpd
    ```
- **`disable`**: 부팅 시 자동 시작되지 않도록 설정을 해제
    ```bash
    $ sudo systemctl disable httpd
    ```
- **`is-enabled`**: 서비스가 현재 자동 시작되도록 설정되어 있는지 확인
    ```bash
    $ systemctl is-enabled httpd
    enabled
    ```

> **💡 `start`와 `enable`의 차이**
> - `start`는 **지금 당장** 서비스를 켜는 일회성 명령입니다.
> - `enable`은 **다음 부팅 때부터** 자동으로 켜지도록 "예약"하는 설정입니다.
> - 따라서, 서비스를 설치한 직후에는 `sudo systemctl enable --now httpd` 처럼 `--now` 옵션을 주거나, `enable`과 `start`를 모두 실행해주는 것이 일반적입니다.

## 3. 기타 유용한 명령어

- **`systemctl list-units --type=service`**: 현재 메모리에 로드된 모든 서비스 유닛의 목록과 상태를 보여줍니다.
- **`systemctl list-unit-files --type=service`**: 설치된 모든 서비스 유닛 파일의 목록과 자동 시작 설정 상태(enabled, disabled, static 등)를 보여줍니다.
- **`systemctl mask <서비스명>`**: `disable`보다 강력한 비활성화. `mask`된 서비스는 수동으로도 시작할 수 없게 됩니다. 특정 서비스가 실수로라도 실행되는 것을 원천적으로 막고 싶을 때 사용합니다.
- **`systemctl unmask <서비스명>`**: `mask`를 해제합니다.

### 📝 명령어 요약

| 목적 | 명령어 | 설명 |
| :--- | :--- | :--- |
| **즉시 실행** | `start` | 서비스를 지금 당장 시작합니다. |
| **즉시 중지** | `stop` | 서비스를 지금 당장 중지합니다. |
| **재시작** | `restart` | 서비스를 중지 후 다시 시작합니다. (설정 적용) |
| **설정만 재로딩** | `reload` | 서비스를 중단하지 않고 설정만 다시 읽어들입니다. |
| **상태 확인** | `status` | 서비스의 현재 동작 상태와 최근 로그를 확인합니다. |
| **부팅 시 자동실행** | `enable` | 다음 부팅부터 서비스를 자동으로 시작하도록 설정합니다. |
| **자동실행 해제** | `disable` | 다음 부팅부터 서비스가 자동으로 시작되지 않도록 해제합니다. |
