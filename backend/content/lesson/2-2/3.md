# 2-2-3: `sudo`를 통한 권한 상승과 `visudo`

시스템을 관리하다 보면 패키지 설치, 서비스 재시작 등 `root` 사용자만이 할 수 있는 작업이 반드시 필요합니다. 하지만 보안상의 이유로 평소에 `root` 계정으로 직접 로그인하여 작업하는 것은 매우 위험합니다. `sudo`는 이 문제를 해결하기 위한 현명한 방법입니다.

## 1. 왜 `root`를 직접 사용하면 안 되는가?

- **실수 한 번의 파급력**: `root`는 모든 것을 할 수 있는 만큼, `rm -rf`와 같은 위험한 명령어를 실수로 잘못 입력했을 때 시스템 전체를 파괴할 수 있습니다.
- **책임 추적의 어려움**: 여러 관리자가 `root` 계정 하나를 공유해서 사용한다면, 누가 어떤 작업을 했는지 추적하기가 매우 어렵습니다.

이러한 문제를 해결하기 위해, 일반 사용자에게 꼭 필요한 관리 명령어만 **일시적으로 `root` 권한을 빌려 실행**할 수 있게 해주는 도구가 바로 `sudo`입니다.

## 2. `sudo` (superuser do)

- **기능**: 일반 사용자가 허용된 범위 내에서 특정 명령어를 `root` 또는 다른 사용자의 권한으로 실행할 수 있게 해줍니다.
- **장점**:
    - **보안**: 사용자는 `root`의 암호가 아닌 **자기 자신의 암호**를 입력하여 인증합니다. 이를 통해 `root` 암호의 노출을 최소화할 수 있습니다.
    - **감사 및 로깅 (Auditing)**: 누가, 언제, 어떤 명령어를 `sudo`로 실행했는지 `/var/log/secure` 파일에 기록이 남아 책임 추적이 용이합니다.
    - **세분화된 권한 제어**: 모든 권한을 주는 대신, 특정 사용자에게는 오직 웹 서버를 재시작하는 권한만 부여하는 등 매우 세밀한 정책 설정이 가능합니다.

- **사용법**: `sudo [실행할 명령어]`
    ```bash
    # dnf 패키지 업데이트 (root 권한 필요)
    $ sudo dnf update

    # httpd 서비스 재시작 (root 권한 필요)
    $ sudo systemctl restart httpd
    ```
    `sudo`를 처음 실행하면 암호를 묻고, 한 번 인증되면 일정 시간(기본 5분) 동안은 암호 없이 `sudo`를 계속 사용할 수 있습니다.

## 3. `sudo`의 정책 파일: `/etc/sudoers`

누가, 어떤 컴퓨터에서, 어떤 사용자로, 어떤 명령어를 실행할 수 있는지는 모두 `/etc/sudoers`라는 설정 파일에 정의되어 있습니다. 하지만 이 파일은 매우 민감하며, 문법이 조금이라도 틀리면 `sudo` 자체가 동작하지 않아 시스템에 대한 관리 권한을 잃을 수도 있습니다.

> **⚠️ 경고**: 절대로 `nano`나 `vim` 같은 일반 편집기로 `/etc/sudoers` 파일을 직접 편집해서는 안 됩니다.

## 4. `visudo`: 안전한 `sudoers` 편집기

- **기능**: `/etc/sudoers` 파일을 안전하게 편집하기 위한 전용 명령어입니다. `visudo`를 사용하면, 파일을 저장할 때 **문법 검사를 자동으로 수행**하여, 오류가 있을 경우 저장을 막아 실수를 방지해 줍니다.
- **사용법**: `root` 권한으로 `visudo`를 실행합니다.
    ```bash
    $ sudo visudo
    ```
    기본적으로 `vi` 에디터로 파일이 열리며, 편집 후 `:wq`로 저장하고 종료하면 됩니다.

## 5. `sudo` 권한 부여하기 (Red Hat 계열 표준 방식)

Red Hat 계열(RHEL, CentOS, Fedora 등)에서는 **`wheel` 그룹**에 사용자를 추가하는 것만으로 `sudo` 권한을 부여하는 것이 표준 방식입니다.

1.  **`visudo`로 `sudoers` 파일 확인**
    `sudo visudo`를 실행하여 파일 내용 중에 아래와 같은 줄이 있는지 확인합니다. 보통 기본적으로 포함되어 있으며, 주석(` # `)이 있다면 제거해 줍니다.

    ```
    ## Allows people in group wheel to run all commands
    %wheel  ALL=(ALL)       ALL
    ```

    - **해석**:
        - `%wheel`: `wheel` 그룹에 속한 사용자들은 (`%`는 그룹을 의미)
        - `ALL=`: 모든 호스트(컴퓨터)에서
        - `(ALL)`: 모든 사용자의 권한으로
        - `ALL`: 모든 명령어를 실행할 수 있다.

2.  **사용자를 `wheel` 그룹에 추가**
    `usermod` 명령어를 사용하여 권한을 부여하고 싶은 사용자를 `wheel` 그룹에 추가합니다. `-aG` 옵션을 사용하는 것이 중요합니다.

    ```bash
    # testuser 사용자를 wheel 그룹에 추가
    $ sudo usermod -aG wheel testuser
    ```

3.  **재로그인**
    그룹 변경 사항이 시스템에 완전히 적용되려면, 해당 사용자는 **로그아웃 후 다시 로그인**해야 합니다. 재로그인 후 `id` 명령어로 `wheel` 그룹에 포함되었는지 확인하고, `sudo` 명령어가 잘 동작하는지 테스트합니다.

### (참고) 암호 없이 `sudo` 사용하기

보안상 권장되지는 않지만, 특정 사용자나 그룹이 암호 입력 없이 `sudo`를 사용하게 하려면 `visudo`를 통해 아래와 같이 `NOPASSWD:`를 추가할 수 있습니다.

```
# testuser는 암호 없이 모든 sudo 명령 사용 가능
testuser ALL=(ALL) NOPASSWD: ALL

# wheel 그룹 전체가 암호 없이 모든 sudo 명령 사용 가능
%wheel  ALL=(ALL)       NOPASSWD: ALL
```
