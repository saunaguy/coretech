# 2-2-4: 특수 권한 (SUID, SGID, Sticky Bit)

리눅스는 기본적인 읽기(r), 쓰기(w), 실행(x) 권한 외에, 특정 상황에서 특별한 역할을 하는 세 가지 특수 권한을 가지고 있습니다. 이 권한들은 시스템 운영에 있어 매우 중요하게 사용됩니다.

## 1. SUID (Set User ID)

- **개념**: 실행 파일에 설정되는 특수 권한으로, 어떤 사용자가 이 파일을 실행하든, 실행되는 순간만큼은 **파일의 소유자 권한**으로 프로세스가 실행되게 합니다.

- **`ls -l` 에서의 표시**: 소유자(user)의 실행 권한(`x`) 자리에 `s`로 표시됩니다.
    - `rwx` → `rws`
    - 만약 원래 실행 권한이 없었다면 대문자 `S`로 표시되며, 이는 보통 잘못된 설정입니다.

- **대표적인 예: `passwd` 명령어**
    일반 사용자는 자신의 암호를 바꿀 때 `passwd` 명령어를 사용합니다. 이 과정은 `root`만이 쓰기 가능한 `/etc/shadow` 파일을 수정해야 합니다. 어떻게 이것이 가능할까요?
    ```bash
    $ ls -l /usr/bin/passwd
    -rwsr-xr-x. 1 root root 30768 Dec 15  2021 /usr/bin/passwd
    ```
    `passwd` 명령어 파일은 소유자가 `root`이고 SUID가 설정되어 있습니다. 따라서 일반 사용자가 `passwd`를 실행하면, 그 프로세스는 `root`의 권한으로 실행되어 `/etc/shadow` 파일을 안전하게 수정할 수 있는 것입니다. 물론 `passwd` 프로그램 자체는 자신의 암호만 변경하도록 제한하는 로직을 가지고 있습니다.

- **보안**: 매우 강력한 기능이지만, SUID가 설정된 프로그램에 보안 취약점이 있다면 시스템 전체에 대한 `root` 권한을 탈취당할 수 있는 심각한 위험을 내포합니다.

- **설정 방법**:
    - `chmod u+s <파일명>` (기호 방식)
    - `chmod 4755 <파일명>` (숫자 방식, 맨 앞의 `4`가 SUID를 의미)

## 2. SGID (Set Group ID)

SGID는 파일에 설정될 때와 디렉터리에 설정될 때의 역할이 다릅니다.

### 파일에 설정될 경우
- **개념**: SUID와 유사하게, 파일을 실행하는 동안 **파일의 소유 그룹 권한**으로 프로세스가 실행됩니다. SUID보다는 사용 빈도가 낮습니다.

### 디렉터리에 설정될 경우 (★★중요★★)
- **개념**: **디렉터리 내에서 생성되는 모든 새로운 파일이나 하위 디렉터리는, 생성한 사용자의 기본 그룹이 아닌, 해당 디렉터리의 소유 그룹을 자동으로 상속받게 됩니다.**

- **`ls -l` 에서의 표시**: 그룹(group)의 실행 권한(`x`) 자리에 `s`로 표시됩니다.
    - `rwx` → `rws` (파일) / `r-x` → `r-s` (디렉터리)

- **주요 사용 사례: 협업용 공유 디렉터리**
    여러 사용자가 `developers`라는 그룹에 속해 프로젝트를 진행한다고 가정해봅시다.
    ```bash
    # 1. 공유 디렉터리 생성 및 그룹 소유권 변경
    $ sudo mkdir /data/project
    $ sudo chown :developers /data/project

    # 2. SGID 설정
    $ sudo chmod g+s /data/project
    $ ls -ld /data/project
    drwxr-sr-x 2 root developers 4096 Sep 24 12:00 /data/project
    ```
    이제 `developers` 그룹에 속한 `user1`이 이 디렉터리에 파일을 생성해도, 파일의 그룹은 `user1`이 아닌 `developers`가 됩니다. 덕분에 다른 팀원(`user2`, `user3`)들도 그룹 권한에 따라 해당 파일을 수정하거나 읽을 수 있게 되어 협업이 매우 편리해집니다.

- **설정 방법**:
    - `chmod g+s <디렉터리명>` (기호 방식)
    - `chmod 2775 <디렉터리명>` (숫자 방식, 맨 앞의 `2`가 SGID를 의미)

## 3. Sticky Bit

- **개념**: **오직 디렉터리에만 적용**되는 특수 권한입니다. 디렉터리에 Sticky Bit가 설정되면, 그 디렉터리 안의 파일은 **오직 파일의 소유자**와 **디렉터리의 소유자(및 root)**만이 삭제하거나 이름을 변경할 수 있습니다.

- **`ls -l` 에서의 표시**: 그 외 사용자(other)의 실행 권한(`x`) 자리에 `t`로 표시됩니다.
    - `rwx` → `rwt`

- **대표적인 예: `/tmp` 디렉터리**
    `/tmp`는 모든 사용자가 파일을 생성하고 임시 데이터를 저장할 수 있는 공용 공간입니다. 권한을 확인해봅시다.
    ```bash
    $ ls -ld /tmp
    drwxrwxrwt. 1 root root 4096 Sep 24 12:10 /tmp
    ```
    모든 사용자가 쓰기(`w`) 권한을 가지고 있지만, 맨 끝에 `t`(Sticky Bit)가 설정되어 있습니다. 이 때문에, A 사용자가 B 사용자가 만든 임시 파일을 함부로 삭제할 수 없습니다. 오직 파일의 주인인 B만이 자신의 파일을 삭제할 수 있습니다.

- **설정 방법**:
    - `chmod +t <디렉터리명>` (기호 방식)
    - `chmod 1777 <디렉터리명>` (숫자 방식, 맨 앞의 `1`이 Sticky Bit를 의미)

### 📝 특수 권한 요약

| 권한 | 숫자 값 | `ls -l` 표시 | 주된 역할 |
| :--- | :---: | :---: | :--- |
| **SUID** | 4000 | `rws`r-xr-x | 실행 시, 파일 소유자의 권한으로 실행 |
| **SGID** | 2000 | rwxr`s`r-x | (디렉터리) 하위 파일/디렉터리가 부모의 그룹을 상속 |
| **Sticky Bit** | 1000 | rwxrwxrw`t` | (디렉터리) 파일 소유자만 파일 삭제/수정 가능 |
