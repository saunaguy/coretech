# 2-2-6: ACL(Access Control List) 관리

기본적인 파일 권한(소유자, 그룹, 그 외)만으로는 복잡한 권한 설정을 하기에 한계가 있습니다. 예를 들어, 특정 파일에 대해 소유자 외에 `userA`에게는 읽기/쓰기 권한을, `userB`에게는 읽기 권한만 부여하고 싶다면 어떻게 해야 할까요? 이럴 때 사용하는 것이 바로 **ACL(Access Control List, 접근 제어 목록)**입니다.

## 1. ACL이란 무엇인가?

- **기능**: 전통적인 UGO(User, Group, Other) 권한 모델을 확장하여, **특정 사용자나 특정 그룹**에 대해 개별적인 권한을 추가로 설정할 수 있게 하는 기능입니다.
- **필요성**: 보다 유연하고 세분화된 접근 제어가 가능해져, 복잡한 협업 환경에서 권한 관리를 용이하게 합니다.

### 사전 확인
- 최신 Red Hat 계열 시스템(RHEL, CentOS, Fedora 등)의 기본 파일 시스템(XFS, ext4)은 대부분 ACL 기능이 기본적으로 활성화되어 있습니다.
- `ls -l` 명령 실행 시, 권한 비트 끝에 `+` 기호가 붙어있다면(`-rw-r--r--+`), 해당 파일에 ACL이 설정되어 있음을 의미합니다.

## 2. ACL 관리 명령어: `getfacl` & `setfacl`

- **`getfacl <파일명>`**: 파일이나 디렉터리에 설정된 ACL 정보를 확인합니다.
- **`setfacl <옵션> <규칙> <파일명>`**: 파일이나 디렉터리에 ACL을 설정하거나 변경합니다.

## 3. ACL 사용법

### 1) ACL 확인하기 (`getfacl`)

먼저, ACL이 설정되지 않은 일반 파일의 상태를 확인해봅시다.
```bash
$ touch data.txt
$ ls -l data.txt
-rw-rw-r--. 1 user user 0 Sep 24 13:00 data.txt

$ getfacl data.txt
# file: data.txt
# owner: user
# group: user
user::rw-
group::r--
other::--
```
기본적인 소유자, 그룹, 그 외 사용자의 권한만 표시됩니다.

### 2) ACL 설정하기 (`setfacl`)

`setfacl`의 `-m` (modify) 옵션을 사용하여 특정 사용자나 그룹에 대한 규칙을 추가할 수 있습니다.

- **문법**: `setfacl -m [u|g]:[이름]:[권한] <파일명>`
    - `u`: 특정 사용자(user)
    - `g`: 특정 그룹(group)

- **예시**: `data.txt` 파일에 대해 `dev1` 사용자에게는 읽기/쓰기(`rw`) 권한을, `managers` 그룹에게는 읽기(`r`) 권한만 부여해봅시다.
    ```bash
    # dev1 사용자에게 rw 권한 부여
    $ sudo setfacl -m u:dev1:rw data.txt

    # managers 그룹에게 r 권한 부여
    $ sudo setfacl -m g:managers:r data.txt
    ```

- **결과 확인**:
    ```bash
    $ ls -l data.txt
    -rw-rw-r--+ 1 user user 0 Sep 24 13:00 data.txt  # <-- 권한 비트 끝에 +가 생김

    $ getfacl data.txt
    # file: data.txt
    # owner: user
    # group: user
    user::rw-
    user:dev1:rw-      # <-- 추가된 ACL 규칙
    group::r--
    group:managers:r-- # <-- 추가된 ACL 규칙
    mask::rw-
    other::--
    ```
    - `mask`: 추가된 ACL 항목(특정 사용자/그룹)에 부여될 수 있는 **최대 유효 권한**을 나타냅니다. `mask`가 `r--`라면, `user:dev1:rw-` 규칙이 있더라도 `dev1`은 실제로는 읽기(`r`)만 가능합니다. 보통 `setfacl`이 자동으로 적절하게 계산해줍니다.

### 3) ACL 제거하기

- `-x` (remove): 특정 ACL 규칙을 제거합니다.
- `-b` (remove-all): 모든 확장 ACL 규칙을 전부 제거하고, 기본 UGO 권한으로 되돌립니다.

- **예시**:
    ```bash
    # dev1 사용자에 대한 규칙만 제거
    $ sudo setfacl -x u:dev1 data.txt

    # data.txt의 모든 ACL 규칙을 제거
    $ sudo setfacl -b data.txt
    ```

## 4. 기본 ACL (Default ACL) for Directories

- **기능**: 디렉터리에 **기본(Default) ACL**을 설정하면, 그 디렉터리 내에 새로 생성되는 모든 파일과 하위 디렉터리가 해당 ACL 규칙을 **자동으로 상속**받게 됩니다.
- **설정법**: 일반 규칙 앞에 `d:`를 붙여줍니다.

- **예시**: `/shared/project` 디렉터리 안에 생성되는 모든 파일에 대해, `dev_team` 그룹이 항상 `rwx` 권한을 갖도록 설정해봅시다.
    ```bash
    # /shared/project 디렉터리에 기본 ACL 설정
    $ sudo setfacl -m d:g:dev_team:rwx /shared/project

    # 확인 (default 항목이 추가됨)
    $ getfacl /shared/project
    # file: /shared/project
    # owner: root
    # group: root
    user::rwx
    group::r-x
    other::r-x
    default:user::rwx
    default:group::r-x
    default:group:dev_team:rwx  # <-- 기본 ACL 규칙
    default:mask::rwx
    default:other::r-x

    # 이제 이 디렉터리 안에 새 파일을 만들면 자동으로 dev_team:rwx 권한이 상속된다.
    $ sudo touch /shared/project/new_file.txt
    $ getfacl /shared/project/new_file.txt
    # file: /shared/project/new_file.txt
    # owner: root
    # group: root
    user::rw-
    group::r-x          # <-- mask에 의해 r-x로 조정됨
    group:dev_team:rwx  # <-- 상속받은 ACL 규칙
    mask::rwx
    other::r--
    ```

ACL은 복잡한 권한 요구사항을 해결해주는 강력한 도구이지만, 과도하게 사용하면 관리가 복잡해질 수 있습니다. 따라서 기본적인 UGO 권한으로 해결할 수 없는 특정 상황에서 보조적으로 사용하는 것이 좋습니다.
