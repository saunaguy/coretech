# 2-2-7: 로그인 셸과 환경 변수

사용자가 시스템에 로그인하여 셸을 실행할 때, 셸은 단순히 시작되는 것이 아니라 정해진 순서에 따라 여러 설정 파일들을 읽어들여 사용자의 작업 환경을 구성합니다. 이 과정과 환경 변수의 개념을 이해하면, 나만의 CLI 환경을 꾸미고 스크립트의 동작을 더 깊이 이해할 수 있습니다.

## 1. 로그인 셸 vs 비-로그인 셸

`bash` 셸은 시작되는 방식에 따라 **로그인 셸**과 **비-로그인 셸**로 나뉩니다. 이 둘은 서로 다른 설정 파일을 읽어들입니다.

- **로그인 셸 (Login Shell)**: 사용자가 시스템에 처음 접속할 때 얻게 되는 셸입니다. (예: SSH 원격 접속, 텍스트 모드 콘솔 로그인)
- **비-로그인 셸 (Non-Login Shell)**: 이미 로그인된 상태에서 새로 시작되는 셸입니다. (예: GUI 환경에서 터미널 창을 새로 열 때, 셸 스크립트를 실행할 때)

## 2. 셸 시작 파일의 로딩 순서 (`bash` 기준)

셸이 시작될 때, 아래와 같은 순서로 설정 파일을 찾아 읽고 실행합니다.

### 로그인 셸의 경우
1.  **/etc/profile**: 시스템의 모든 사용자에게 공통적으로 적용되는 **전역 설정 파일**입니다. 시스템 관리자가 관리합니다.
2.  **~/.bash_profile**: 각 사용자 개인의 로그인 셸 설정 파일입니다. 이 파일이 없다면 `~/.bash_login`, `~/.profile` 순서로 찾아서 하나만 실행합니다. 로그인 시 **단 한 번만** 실행되므로, 환경 변수 설정과 같이 처음에 한 번만 필요한 내용을 여기에 넣습니다.

### 비-로그인 대화형 셸의 경우
1.  **/etc/bashrc**: 시스템의 모든 사용자에게 공통적으로 적용되는 함수나 별칭(alias)을 설정합니다.
2.  **~/.bashrc**: 각 사용자 개인의 비-로그인 셸 설정 파일입니다. 터미널을 새로 열 때마다 실행되므로, `alias`나 프롬프트 모양(`PS1`) 설정처럼 **매번 적용되어야 하는 내용**을 여기에 넣습니다.

> **💡 일반적인 설정 관행**
> 복잡함을 피하기 위해, 많은 시스템에서는 `~/.bash_profile` 파일 안에 `~/.bashrc` 파일을 불러오는 코드를 넣어, 로그인 시 두 파일이 모두 실행되도록 설정합니다. 이렇게 하면 모든 설정을 `~/.bashrc` 파일 하나로 통일해서 관리할 수 있어 편리합니다.
> ```bash
> # in ~/.bash_profile
> if [ -f ~/.bashrc ]; then
>    source ~/.bashrc
> fi
> ```

## 3. 환경 변수 (Environment Variables)

- **개념**: 셸이나 다른 프로세스들이 실행될 때 참조하는, **이름과 값으로 구성된 변수**입니다. 프로세스가 실행되는 환경을 정의하며, 부모 프로세스에서 자식 프로세스로 상속됩니다.

- **확인 명령어**:
    - `env` 또는 `printenv`: 현재 설정된 모든 환경 변수를 출력합니다.
    - `echo $<변수명>`: 특정 변수의 값을 확인합니다. (예: `echo $HOME`)

- **설정 명령어**:
    - `export <변수명>="<값>"`: 환경 변수를 설정합니다. `export`를 사용해야 자식 프로세스에도 이 변수가 전달됩니다. 터미널에서 직접 설정한 변수는 해당 세션에서만 유효합니다.
    - **영구 설정**: `~/.bash_profile` 이나 `~/.bashrc` 파일에 `export` 명령어를 추가하면, 다음 로그인/셸 실행 시부터 계속 적용됩니다.

### 주요 환경 변수
- `PATH`: 명령어를 입력했을 때, 셸이 해당 실행 파일을 찾는 **경로들의 목록**입니다. 각 경로는 콜론(`:`)으로 구분됩니다. `/bin`, `/usr/bin` 등이 기본적으로 포함되어 있어 우리가 `ls`만 입력해도 `/bin/ls`가 실행될 수 있습니다.
- `HOME`: 현재 사용자의 홈 디렉터리 경로.
- `USER`: 현재 사용자의 이름.
- `SHELL`: 현재 사용자의 기본 셸 프로그램 경로.
- `PS1`: 셸 프롬프트의 모양을 정의하는 변수. 이 값을 변경하여 프롬프트에 원하는 정보를 표시할 수 있습니다.

## 4. `sudo`와 `secure_path`

일반 사용자가 `sudo`를 통해 `root` 권한으로 명령어를 실행할 때, 보안을 위해 사용자의 `PATH` 환경 변수를 그대로 사용하지 않습니다.

- **개념**: `sudo`는 `/etc/sudoers` 파일에 정의된 **`secure_path`** 라는 안전한 경로 목록을 사용하여 실행할 명령어를 찾습니다.
- **이유**: 만약 악의적인 사용자가 자신의 홈 디렉터리에 `ls`라는 이름의 악성 스크립트를 만들어 놓고, `sudo ls`를 실행하면 어떻게 될까요? 사용자의 `PATH`에 홈 디렉터리가 먼저 포함되어 있다면, 시스템의 `/bin/ls`가 아닌 악성 스크립트가 `root` 권한으로 실행될 수 있습니다. `secure_path`는 이러한 위험을 원천적으로 차단합니다.

- **확인 방법**: `sudo visudo` 명령으로 `sudoers` 파일을 열어보면 아래와 같은 줄을 찾을 수 있습니다.
    ```
    Defaults    secure_path = /sbin:/bin:/usr/sbin:/usr/bin
    ```
    이는 `sudo` 명령이 오직 `/sbin`, `/bin`, `/usr/sbin`, `/usr/bin` 이 4개의 신뢰할 수 있는 경로에서만 명령어를 찾아 실행하겠다는 의미입니다.
